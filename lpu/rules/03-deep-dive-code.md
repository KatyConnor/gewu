# LPU 规则 · 03 代码维深潜（S2 · DIV-C）

> 代码维回答：这个系统由什么组成、怎么组织、质量如何。
> 逐模块执行，产出写入 `findings/C-code.md`。

---

### LPU-DIV-C-001【M】模块内架构还原
每个模块必须还原：内部组成（controller/service/dao 或等效层次）、职责、对外暴露面
（被谁调用、调用谁）。对照 SKL-001 的"职责猜测"逐条验证：证实→升级置信度；推翻→按 GEN-008 留痕。

### LPU-DIV-C-002【M】核心调用链追踪
每模块至少追踪 3 条代表性调用链（入口 → 业务逻辑 → 数据访问，文本形式记录）：

```
POST /api/orders → OrderController.create:45 → OrderService.create:88
  → InventoryService.deduct:210 → OrderMapper.insert (orders 表)
```

调用链是架构文档与 API 文档的素材来源。追踪深度以到达数据访问层或外部调用为限。

### LPU-DIV-C-003【R】复制粘贴族识别
识别"复制粘贴族"（相似度极高的重复代码块）：登记簇名 + 分布位置 + 估算行数。
复制粘贴族是绞杀者重构的天然切入点，也是 debt-risks 的重要素材。

### LPU-DIV-C-004【M】技术债热点标记
标记以下热点（位置 + 简述，正式定级留给 S5）：
- 超大文件（>1000 行）/ 超长方法（>200 行）
- 圈复杂度明显失控的方法（嵌套 ≥4 层）
- 吞异常（catch 后空处理或仅打印）
- 硬编码配置（IP/路径/密钥散落代码中）
- 过时技术用法（已废弃 API、明显不安全写法如字符串拼接 SQL）

### LPU-DIV-C-005【R】框架惯用法偏离
识别"反框架"用法：绕过框架标准机制的怪异实现（反射调用私有方法、自定义线程池管理事务等）。
偏离处往往藏着历史包袱或关键业务约束，是 K 维挖掘的富矿。

### LPU-DIV-C-006【M】对外集成点登记
所有外部交互点（HTTP 出站、MQ 收发、文件交换、第三方 SDK）逐一登记：
`目标系统 / 交互方式 / 代码位置 / 同步异步`。集成点直接进入 architecture.md 的部署视图与
rebuild-plan 的迁移边界分析。

### LPU-DIV-C-007【O】测试覆盖画像
统计测试文件与被测代码比例、断言质量。遗留项目常见"测试为零"——这也是有效结论（写入 debt-risks）。
