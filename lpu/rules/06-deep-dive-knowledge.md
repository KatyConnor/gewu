# LPU 规则 · 06 知识维深潜（S2 · DIV-K）

> 知识维回答：这个业务领域有哪些概念和规则。知识维是五维中最依赖"挖掘"的维度——
> 业务规则不会写在明面上，它们藏在条件分支、校验逻辑、注释、命名和魔法值里。

---

### LPU-DIV-K-001【M】领域术语表建设
从以下来源提取术语并统一登记（term → 中文释义 → 首次出现位置）：
- 实体类名与字段名（Order/Refund/Adjustment…）
- 表名列名（业务黑话常驻于此：如 `sku`、`spu`、`settle`）
- 注释与提交信息中的行话
- 枚举类名与枚举项

术语表的作用：让成文文档的用词与代码实体**一一对应**，新工程师读文档时能反查代码。
同义术语（"退款/退货退款/仅退款"）必须显式合并说明。

### LPU-DIV-K-002【M】显式业务规则提取
业务规则 = 系统强制执行的约束。提取并编号（BR-###）：
`规则描述 / 类型（校验|计算|流转|权限） / 证据（代码位置） / 置信度 / 备注（是否可疑）`
典型藏身处：参数校验逻辑、Service 层 if 抛出的 BusinessException、SQL 中的 WHERE 条件、
数据库约束（唯一键、CHECK）。

### LPU-DIV-K-003【M】隐式规则挖掘（遗留项目最有价值的产出）
隐式规则 = 代码没有直接说、但行为上强制遵守的约束。重点排查：
- **金额计算规则**：精度处理方式（BigDecimal scale? 分为单位?四舍五入模式?）——重构中最容易悄悄改变结果的地方；
- **时间边界规则**：跨天/跨月/时区处理（"日切"逻辑在哪）；
- **顺序依赖规则**：必须先 A 后 B 的隐含约束（依据状态检查或时序推断）；
- **默认值兜底规则**：查不到数据时的 fallback 行为（返回空 vs 抛异常 vs 造一条默认记录）。

每条隐式规则必须给出行为证据（代码位置+逻辑摘录），标注置信度。**挖到一条能救重构一命的隐式规则，价值超过十页架构描述。**

### LPU-DIV-K-005【R】历史包袱注释挖掘
系统性地摘录有信息量的历史注释：`// 2019年双11临时加的，忘了删`、`// 老板要求的，别动`、
`// HACK: XX系统bug，先绕过`。这些注释是业务变迁史的活化石，直接进 debt-risks 与 rebuild-plan 的约束条件。
