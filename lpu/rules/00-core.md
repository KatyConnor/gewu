# LPU 规则 · 00 核心规则（GEN + MEM + 红线）

> 本文为 LPU 工作流必读规则。规则编号格式：`LPU-GEN-###` / `LPU-MEM-###`。
> 级别：M=强制（违反即返工）/ R=推荐 / O=可选。

---

## 一、红线五条（违反任意一条，本次分析结果不可信）

| # | 红线 | 说明 |
|---|---|---|
| R1 | 无证据不结论 | 任何写进成文文档的判断必须带证据锚点（`路径:行号` / 表名.列名 / 配置项）。"我感觉这是订单模块"不是结论。 |
| R2 | C 级置信不入重构决策 | 置信度 C（单源推断）的结论只能进"待人工确认清单"，禁止进入 rebuild-plan 的决策依据。 |
| R3 | 业务代码与数据只读 | 分析期间禁止修改/重构/格式化任何业务代码；数据库只读 schema 与聚合统计，行级业务数据不得导出落盘。 |
| R4 | 大项目增量推进 | 预估分析量超过单次会话承载力时，必须按模块拆分，先落盘进度再继续；禁止一次会话贪全导致分析烂尾。 |
| R5 | 进度先落盘 | 每完成一个模块/阶段，先更新 `.lpu/progress/PROGRESS.md` 与 findings，再做其他事。会话可能随时中断。 |

## 二、GEN 通用规则

### LPU-GEN-001【M】证据锚点格式
所有结论的证据锚点采用统一格式，便于人工复核与 `lpu_check.py` 校验：

```
【证据】src/main/java/com/acme/order/OrderService.java:142
【证据】orders 表 order_status 列 + OrderStatusEnum.java:8（枚举定义）
```

- 代码证据：相对路径 + 行号；
- 数据库证据：`表名.列名` 或 DDL 文件路径；
- 配置证据：配置文件路径 + 键名；
- 多源证据逐行列出，不合并。

### LPU-GEN-002【M】置信度分级与标注
每个结论条目必须以 `[A]` / `[B]` / `[C]` 开头标注置信度：

| 级别 | 定义 | 判定标准 |
|---|---|---|
| A | 代码直接证据 | 结论可由单一可信源直接读出（如枚举定义、显式校验逻辑、外键约束） |
| B | 多源推断 | ≥2 个独立来源相互印证（如代码 + 表结构，或路由 + 模板） |
| C | 单源推断 | 仅一个来源支撑，或存在无法消解的矛盾 |

### LPU-GEN-003【M】发现条目格式（findings 库统一格式）
`.lpu/findings/*.md` 中每条发现为一个条目：

```markdown
### F-C-0007 [A] 订单取消会触发库存回补
- 结论：取消已支付订单时，按下单数量回补库存
- 证据：src/.../OrderCancelService.java:58-72（回补逻辑）
- 影响维度：C/P
- 状态：已验证
```

编号规则：`F-{维度}-{序号}`，序号全局递增不复用。状态取值：已验证 / 待交叉验证 / 已推翻。

### LPU-GEN-004【M】禁止臆测补全
遇到无法理解的代码/数据结构时：
1. 记录为 C 级发现，注明"未能解读，疑似 XX"；
2. 列入 `X-conflicts.md` 的待人工确认清单；
3. **禁止**根据"常见做法"脑补业务规则并当作事实写入文档。

### LPU-GEN-005【R】区分"是什么"与"应该是什么"
成文文档只描述现状（as-is）。改进建议（to-be）只允许出现在 `debt-risks.md` 与 `rebuild-plan.md`
两份文档中，且必须标注 `[建议]` 前缀，避免现状描述与改进主张混杂。

### LPU-GEN-006【M】魔法值必须显式登记
代码中无命名的魔法值（状态码 `1/2/3`、类型标志 `A/B/C`、金额倍率等）发现即登记到
`K-knowledge.md`，格式：`值 → 含义 → 证据 → 置信度`。魔法值是遗留项目业务规则的主要藏身处。

### LPU-GEN-007【R】每维度发现量下限
每个被分析模块在五维上至少各产出 1 条发现（哪怕结论是"未发现 X"）。
"未发现入口点""未发现状态机"本身也是有效结论，证明该维度已被覆盖。

### LPU-GEN-008【M】结论推翻必须留痕
当新证据推翻旧结论时：旧条目状态改为"已推翻"并注明推翻原因与新证据，禁止直接删除。
被推翻 ≥3 次的模块在 PROGRESS 中标记为"高噪声模块"，成文时整体置信度降一级。

## 三、MEM 记忆与断点规则

### LPU-MEM-001【M】PROGRESS.md 状态机字段
每次落盘必须包含：`当前阶段`（S0-S5）、`已覆盖模块`（清单）、`进行中`（模块+维度）、
`未决问题`（编号列表）、`下一步`（具体到模块+维度+动作）、`累计会话数`。

### LPU-MEM-002【M】续跑恢复协议
会话开始读取 PROGRESS 后：
1. 跳过所有"已覆盖模块"（除非标记被推翻）；
2. 从"下一步"字段描述的位置继续；
3. 向用户简报：上次进度 + 本次计划，获得确认后继续。

### LPU-MEM-003【R】上下文预算管理
单次会话建议只深潜 1-3 个模块。当发现自己在"重复读同一批文件"或"忘记之前的结论"时，
说明上下文已接近极限：立即执行落盘（R5），宁可分多次会话完成。

### LPU-MEM-004【R】跨会话知识复用
成文阶段（S4）优先从 findings 库汇总，而非重新阅读源码。findings 库就是为"不需要重新读代码"
而存在的——如果发现成文时还必须大量重读源码，说明 S2 的发现记录不达标，应回补。
