# 性能测试计划

> 格物平台生产环境性能测试方案

## 1. 测试目标

- 验证系统在 750 并发用户下的稳定性
- 确认核心 API P95 延迟 < 200ms
- 验证 HPA 自动扩缩容有效性
- 识别性能瓶颈并优化

## 2. 测试场景

### 2.1 登录认证
- 并发用户: 100
- 持续时间: 5 分钟
- 预期: P95 < 100ms, 错误率 < 0.1%

### 2.2 会话列表
- 并发用户: 200
- 持续时间: 10 分钟
- 预期: P95 < 150ms, 错误率 < 0.1%

### 2.3 AI 对话（流式）
- 并发用户: 50
- 持续时间: 15 分钟
- 预期: 首字节 < 500ms, 完整响应 < 10s

### 2.4 工作流执行
- 并发用户: 30
- 持续时间: 10 分钟
- 预期: P95 < 2s, 错误率 < 1%

### 2.5 混合负载
- 并发用户: 750
- 持续时间: 30 分钟
- 预期: 系统稳定，无 OOM，HPA 正常扩容

## 3. 测试工具

### JMeter 测试计划
- 文件: `deploy/jmeter/gewu-platform.jmx`
- 线程组: 按场景配置
- 断言: 响应码 200，响应时间阈值
- 监听器: Summary Report, Aggregate Report, View Results Tree (调试用)

### 监控指标
- JVM: 堆内存、GC 次数、线程数
- HTTP: 请求速率、P95/P99 延迟、错误率
- DB: 连接池使用率、慢查询数量
- 缓存: 命中率、内存使用

## 4. 测试环境

| 组件 | 配置 |
|------|------|
| 应用服务器 | 4 核 8GB × 2 实例 |
| MySQL | 4 核 8GB |
| Redis | 2 核 4GB |
| 网络 | 1Gbps 内网 |

## 5. 执行步骤

1. 部署测试环境
2. 执行基准测试（单用户）
3. 逐步增加并发（100 → 200 → 500 → 750）
4. 记录各阶段指标
5. 分析瓶颈并优化
6. 复测验证优化效果

## 6. 验收标准

- [ ] 750 并发下系统稳定运行 30 分钟
- [ ] 核心 API P95 < 200ms
- [ ] 错误率 < 1%
- [ ] HPA 在 CPU > 70% 时自动扩容
- [ ] 无内存泄漏（JVM 堆内存稳定）
- [ ] 数据库连接池无耗尽

## 7. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 数据库连接耗尽 | 服务不可用 | 配置连接池上限，监控活跃连接数 |
| 内存溢出 | 服务崩溃 | 配置 JVM 参数，监控堆内存 |
| 网络延迟 | 响应慢 | 使用内网测试，优化网络配置 |
| 第三方 API 限流 | 功能异常 | 配置熔断降级，使用 Mock 数据 |
