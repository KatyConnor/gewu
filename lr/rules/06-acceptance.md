# R5 验收与切换 · 06-acceptance（LR-STD-001）

> 输入：D-R4-02 变更追溯矩阵全覆盖 + 末批（退役批）就绪
> 出口门禁：D-R5-01 重构验收报告 / D-R5-02 数据迁移终验报告 / D-R5-03 旧系统退役与归档方案（均 approved）

## 1. 阶段目标

全量验收、数据终验、正式收官退役。R5 结束即"重构完成"的官方时点。

## 2. 验收（D-R5-01）

1. **功能验收**：P0 流程全回归（特征测试套件 + 新增功能测试），对照
   LPU features-api.md 功能清单逐项核销。
2. **非功能验收**：性能基线（新旧对比，允许的劣化阈值按立项决议）、
   安全基线（CR L3-SEC 项 + SDLC 角色 05 复核）、可观测性就绪（日志/监控/告警）。
3. **文档验收**：D-R4-02 无悬空映射；行为变更清单（累计）在预算内且逐条有确认。
4. **遗留项**：未完成项显式登记（含责任人与期限），禁止静默遗留。

## 3. 数据终验（D-R5-02）

- 全量数据核对：四层校验（行数/主键/汇总/抽样）在**最终数据集**上重跑。
- 序列/自增/约束/索引状态核对；历史数据归档完整性核对。
- 校验脚本与结果固化为证据（可重复执行）。

## 4. 退役与归档（D-R5-03）

- 退役前置：观察期（末批切换后 ≥1 个业务周期）无回滚事件。
- 归档内容：旧系统代码（含构建脚本）、最终数据库快照、配置与密钥清单
  （密钥按安全规范脱敏存储）、运行手册。保留期限写入方案。
- 下线序列：流量确认归零 → 只读冻结期 → 停服 → 资源回收。
  每步均为 AETC R3 级操作。
- **可逆性声明**：归档副本 + 恢复演练记录 = 唯一的"退役可逆"依据。

## 5. 协作要点

- 角色：06（测试）主验收，09（SRE）主退役操作，10（项目管理）签收，
  用户/业务方对验收报告终审。
- R5 任一门禁 FAIL 的处置：功能性缺口回 R4 对应单元；数据缺口回炉迁移并重新终验。
