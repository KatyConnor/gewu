# S7 复盘改进阶段规则（07-retro.md）

阶段目标：把每次任务/事件的经验转化为可复用的规则改进，形成管控闭环。
phase 值：retro

## Agent 职责边界
- 应做：汇总本次会话留痕、生成会话报告（audit_report.py）、
  复盘报告草案撰写、规则改进提案、指标统计。
- 禁止：在复盘中美化或选择性呈现记录（一切以 traces 为准）；
  未经人工批准直接修改 audit/rules/ 或全局规则。

## 必检点
1. 会话报告已生成并归档 audit/reports/。
2. 时间线、决策链、风险操作、审批门四个维度已复盘。
3. 失败/阻塞/回退项都有根因分类（需求/实现/环境/误操作/其他）。
4. 改进项有明确落点：新增/修订规则编号、责任角色、验证方式。
5. 指标已统计：留痕完整率、审批合规率、检查点成功率、回退成功率。

## 留痕要求
- 复盘本身以 TASK_OPEN(phase=retro) 开启，产出物 STEP_DONE 记录。
- 规则变更提案以 GATE_REQUEST 提交人工批准（修订 audit/rules/ 属 R2）。
- 批准后的规则变更记录 CORRECTION（规范体系级纠偏）。

## 审批门（复盘报告确认）
- 复盘报告由人工确认后归档；改进项进入跟踪清单。

## 常见风险
- 复盘流于形式：改进项无落点、无验证方式的报告不予通过。
- 指标造假：指标一律由 audit_check.py 从 traces 计算，不手填。

## 四项核心指标定义
- 留痕完整率 = 合格记录数 / 应记事件数（应记事件由任务流程推导）。
- 审批合规率 = 实际走完审批门的 R2/R3 操作数 / 应审批操作数。
- 检查点成功率 = 恢复验证通过的检查点数 / 创建的检查点数。
- 回退成功率 = 按五步法完成且回退后验证通过的次数 / 回退总次数。
