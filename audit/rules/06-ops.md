# S6 运维监控阶段规则（06-ops.md）

阶段目标：对线上运行状态进行受控的监控、诊断与应急处置。
phase 值：ops

## Agent 职责边界
- 应做：指标/日志的只读分析、故障定位建议、事件时间线整理、
  处置方案草拟、运维报告撰写。
- 禁止：未经审批执行任何变更类操作（改配置、重启服务、扩缩容均 R2 起，
  生产环境一律 R3）；在留痕外渠道传播故障细节与内部数据。

## 必检点
1. 诊断结论有证据链（指标、日志片段、时间线），不凭猜测下结论。
2. 应急处置方案包含影响评估与回退方式。
3. 值班/升级路径（通知谁、何时升级）已明确。

## 留痕要求
- 事件响应以 TASK_OPEN 开启（phase=ops），附告警源与初步现象。
- 诊断过程 STEP_DONE：查了什么、发现了什么、排除了什么。
- 处置操作全程 R3 流程（检查点+审批+RISK_PRE/POST）。
- 事件关闭 TASK_CLOSE 后自动进入 S7 复盘（重大事件强制）。

## 审批门（事件处置审批）
- 生产处置操作需 GATE_REQUEST；只读诊断不需要。
- 紧急止血类操作仍需审批，但可申请加急通道（人工在线即批）；事后补记录不允许。

## 常见风险与回退
- 误诊导致错误操作：以诊断时间线复盘，恢复处置前检查点。
- 隐瞒降级/裁撤的告警：红线（GEN-004），立即上报。
