# market_feasibility_check | 市场可行性研判

## 1. 技能描述

本技能面向业务需求分析师，提供产品想法从 0 到 1 阶段的市场可行性快速验证能力。覆盖目标市场规模测算（TAM / SAM / SOM）、3-5 年增速预判、政策合规性校验、商业化潜力评估、竞争格局初判五大维度，输出 go/no-go 倾向性建议与决策依据，避免无效投入。

## 2. 触发条件

满足以下任一条件即触发：
- 输入包含「市场可行性 / 立项评估 / 商业化潜力 / 市场规模 / ROI 测算」等关键词
- 业务方提出新业务想法并要求快速验证
- 涉及新赛道布局、新业务立项、商业模式验证场景
- 角色 01 被激活且场景为「市场可行性研判」

## 3. 执行步骤

1. **需求理解与拆解**：将业务方原始想法转化为结构化调研问题清单
2. **赛道判定**：基于业务描述判定 B 端 / C 端 / AI 智能体 / 金融托管的赛道归属
3. **市场规模测算**：采用 TAM / SAM / SOM 双算法（自上而下 + 自下而上）测算
4. **增速预判**：基于历史数据与行业报告，输出 3-5 年 CAGR 与驱动因素
5. **政策合规性校验**：强监管赛道调用角色 00 的政策研判结论，输出合规风险清单
6. **商业化潜力评估**：测算付费模式、客单价、付费意愿、ROI 回收期
7. **竞争格局初判**：扫描同业产品，判定红海 / 蓝海 / 细分机会
8. **可行性结论输出**：输出 go / no-go 倾向性建议 + 决策依据
9. **风险控制校验**：标注数据来源、置信度、假设条件、调整空间

## 4. 输入规范

```yaml
业务想法: "为机构客户设计 AI 驱动的合规审查 SaaS"
赛道: "B 端 SaaS + AI 智能体"
调研目的: "立项 go/no-go 决策"
时间预算: "1-2 周"
重点关注: ["目标市场规模与增速", "付费意愿", "AI 能力边界"]
强监管判定: "是 / 否"
输出格式: "结构化报告 + 倾向性建议"
```

## 6. 质量标准

- 市场规模必须采用双算法交叉验证，单算法结论必须标注不确定性
- 所有商业化预测必须附假设条件清单，假设变更需重新测算
- 强监管赛道必须输出合规确认要点清单
- 竞品样本量低于 5 家时必须标注「仅供参考」
- 禁止给出「必须立项 / 绝对可行」等绝对性建议，输出倾向性建议
- 所有结论标注置信度（高 / 中 / 低）与 ±10% 调整空间

## 7. 风险控制

| 规则编号 | 风险点 | 控制动作 |
|---------|--------|---------|
| R-01 | 市场规模单算法偏差 | 强制双算法交叉验证 |
| R-02 | 商业化预测脱离实际 | 必须附假设条件清单 + 敏感性分析 |
| R-03 | 强监管赛道合规缺位 | 必须调用角色 00 / 07 复核 |
| R-04 | 绝对性立项建议 | 禁止「必须立项」措辞，输出倾向性建议 |
| R-05 | 数据时效过期 | 引用报告超 12 个月需重新核验 |
| R-06 | 调整空间预留不足 | 所有结论附加 ±10% 调整空间 |
| R-07 | 赛道判定模糊 | 多赛道交叉时按主导赛道判定并标注次要属性 |

## 8. 跨角色协作接口

|---------|---------|---------|

| 角色 07 合规专家 | 强监管赛道 | 合规确认要点清单 |
