# 技能模块：unit_test_generator

> 自动生成单元测试代码，覆盖正常 / 边界 / 异常三类场景。

## 1. 技能描述

本技能基于源代码静态分析与依赖图，自动生成符合框架规范（JUnit / Pytest / Jest / Mockito / gomock）的单元测试，确保三类场景（正常 / 边界 / 异常）全量覆盖。核心模块覆盖率 100%，普通模块 ≥ 80%。输出包含测试代码、Mock 桩、覆盖率报告与用例清单。

## 2. 触发条件

- 输入包含「单元测试」「测试用例」「覆盖率」「JUnit/Pytest/Jest」等关键词
- 已存在待测源代码（.java/.py/.ts/.go 等文件）
- 模块类型明确（核心 / 普通 / 工具类 / DAO）
- 测试框架与 Mock 框架已指定

## 3. 执行步骤

1. **解析代码结构**：提取类、方法、参数、返回值、依赖关系（外部服务、数据库、缓存）。
2. **识别核心逻辑分支**：if/else、switch、循环、异常捕获、空值判断、边界条件。
3. **生成正常用例**：覆盖业务主流程，正向链路，期望返回成功。
4. **生成边界用例**：参数边界（0、-1、MAX）、空值、极值、并发、超时。
5. **生成异常用例**：异常输入、依赖故障（Mock 抛异常）、超时、重试、回滚。
6. **构建 Mock 桩**：Mock 外部依赖（DB、RPC、HTTP、MQ），桩行为可参数化。
7. **执行测试**：本地运行，收集通过率与覆盖率。
8. **输出报告**：覆盖率报告（行/分支/方法）、用例清单、未覆盖分支说明。

## 4. 输入规范

```yaml
任务类型: 单元测试生成
源代码路径: src/main/java/com/xxx/OrderService.java
模块类型: 核心模块
测试框架: JUnit5
Mock框架: Mockito
覆盖率工具: JaCoCo
目标覆盖率: 100%
已有测试: [清单，避免重复]
```

## 6. 质量标准

- 核心模块覆盖率 100%，普通模块 ≥ 80%，工具类 ≥ 90%，DAO ≥ 70%
- 三类场景（正常 / 边界 / 异常）必须全量覆盖，缺一不可
- 测试必须独立可重复运行，不依赖外部环境
- Mock 桩必须显式声明，禁止隐式状态
- 测试命名规范：`should_<期望>_when_<条件>` 或 `方法_场景_期望`
- 单个测试方法执行时间 < 200ms

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 核心模块未达 100% 覆盖率禁止提测，自动补充用例 |
| RISK-02 | 三类用例必须齐备，缺失时强制补全 |
| RISK-03 | 测试不得依赖真实数据库 / 网络环境，必须 Mock |
| RISK-04 | 禁止删除已有测试用例，仅可追加 |
| RISK-05 | 异常用例必须覆盖业务异常 + 系统异常双路径 |
| RISK-06 | 覆盖率工具与 CI 集成，未达标自动阻断流水线 |
