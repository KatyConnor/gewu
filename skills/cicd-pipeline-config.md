# 技能模块：cicd_pipeline_config

> CI/CD 流水线配置方案，覆盖代码提交到上线的全链路。

## 1. 技能描述

本技能设计端到端 CI/CD 流水线，覆盖代码提交 → 静态扫描 → 镜像构建 → 单元测试 → 集成测试 → 安全扫描 → 多环境发布（dev/test/staging/prod）→ 灰度上线 → 全量发布全流程。支持 Jenkins / GitLab CI / GitHub Actions / ArgoCD 主流工具，输出完整流水线配置 + 回滚预案 + 环境管理规范。

## 2. 触发条件

- 输入包含「CI/CD」「流水线」「自动化部署」「灰度发布」「回滚预案」等关键词
- 已明确技术栈与发布策略
- 已确定部署环境（dev/test/staging/prod）
- 项目从手工部署切换到自动化部署，或现有流水线优化升级

## 3. 执行步骤

1. **项目信息梳理**：技术栈、代码仓库结构、依赖管理、构建方式。
2. **环境规划**：dev / test / staging / prod 四环境隔离，配置项隔离。
3. **流水线阶段设计**：
   - **CI 阶段**：代码提交触发 → 静态扫描（SonarQube / Checkstyle / ESLint）→ 依赖安全扫描（SCA）→ 单元测试 + 覆盖率门禁 → 镜像构建（多阶段）→ 镜像安全扫描（Trivy / Clair）
   - **CD 阶段**：dev 自动部署 → test 自动部署 + 集成测试 → staging 手动触发 + 全量回归 → prod 灰度发布（金丝雀 / 蓝绿 / 滚动）
4. **发布策略选择**：金丝雀 / 蓝绿 / 滚动，按业务关键性选择。
5. **门禁设计**：单元测试通过率、覆盖率、安全扫描、性能基线。
6. **回滚预案**：自动回滚触发条件、手动回滚步骤、数据回滚方案。
7. **监控与告警 + 输出**：发布监控、SLO 指标 + YAML 配置 + 回滚预案 + 操作手册。

## 4. 输入规范

```yaml
任务类型: CI/CD流水线配置
项目名: order-service
技术栈: Java + Spring Boot + Docker + K8s
代码仓库: GitLab
构建方式: Maven + Dockerfile
环境: dev/test/staging/prod
发布策略: 金丝雀（10% → 50% → 100%）
工具链: Jenkins + Harbor + ArgoCD + Prometheus
```

## 6. 质量标准

- 流水线必须支持全自动 CI + 半自动 CD（生产手工触发）
- 关键门禁必须设置自动阻断（覆盖率、安全、性能）
- 生产发布必须支持灰度（金丝雀 / 蓝绿 / 滚动）
- 回滚必须 ≤ 5 分钟内完成
- 镜像必须经过安全扫描，严重漏洞为 0 才能上线
- 流水线执行日志必须保留 ≥ 6 个月

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 生产发布必须有审批（双人复核） |
| RISK-02 | 严重漏洞镜像禁止上线，覆盖率未达门禁禁止合并主干 |
| RISK-03 | 生产环境禁止直连数据库执行变更，数据库变更必须有回滚脚本 |
| RISK-04 | 灰度阶段 SLO 未达成自动回滚 |
| RISK-05 | 流水线凭证必须加密存储，生产环境配置与开发严格隔离 |
