# user_journey_mapping | 用户旅程地图设计

## 1. 技能描述

本技能面向产品经理 / 产品专家，提供用户旅程地图的结构化设计能力。覆盖用户角色识别、核心场景拆解、关键触点标注、情绪曲线绘制、痛点挖掘、机会点识别六大模块，输出可指导 PRD 优化与体验设计的旅程图与优化清单。

## 2. 触发条件

满足以下任一条件即触发：
- 输入包含「用户旅程 / 旅程图 / 触点 / 情绪曲线 / 痛点 / 机会点」等关键词
- 业务方要求进行用户体验诊断或优化方案设计
- 角色 02 被激活且场景为「需求洞察」或「迭代优化」

## 3. 执行步骤

1. **用户角色识别**：基于角色 01 输出的用户画像，明确旅程主角
2. **核心场景拆解**：将用户使用产品的完整场景拆解为阶段（认知 → 试用 → 使用 → 流失 / 复购）
3. **关键触点标注**：识别每个阶段的核心触点（线上 / 线下 / 系统内 / 系统外）
4. **用户行为梳理**：描述用户在每个触点的具体行为与目标
5. **情绪曲线绘制**：评估用户在每个触点的情绪高低（高 / 中 / 低）
6. **痛点挖掘**：识别阻碍用户达成目标的痛点
7. **机会点识别**：基于痛点输出优化机会点清单
8. **优化方案输出**：含优化目标 + 方案 + 预期效果 + 回滚预案
9. **风险控制校验**：标注数据来源、样本量、置信度

## 4. 输入规范

```yaml
用户角色: "机构投研人员"
核心场景: "投研报告阅读与信息检索"
用户画像: "[来自角色 01 的画像]"
需求清单: "[来自角色 01 的需求清单]"
调研数据: "[访谈记录或问卷数据]"
输出格式: "用户旅程图 + 痛点清单 + 优化机会"
```

## 5. 输出格式

```markdown
## 用户旅程地图

### 一、旅程概览
- 用户角色 + 核心场景 + 阶段划分

### 二、旅程详图
| 阶段 | 触点 | 用户行为 | 用户目标 | 情绪（高/中/低） | 痛点 | 机会点 |

### 三、情绪曲线
- 高低走势可视化描述

### 四、痛点清单（按严重度排序）
| 痛点 | 影响范围 | 严重度 | 关联阶段 |

### 五、优化机会清单（按 ROI 排序）
| 机会点 | 优化目标 | 落地方案 | 预期效果 | 回滚预案 |

### 六、PRD 优化建议
- 旅程优化对 PRD 功能清单与交互逻辑的调整建议
```

## 6. 质量标准

- 旅程图必须覆盖完整用户路径（认知 → 试用 → 使用 → 流失 / 复购）
- 每个触点必须标注：触点类型 + 用户行为 + 用户目标 + 情绪 + 痛点 + 机会点
- 情绪曲线必须可视化呈现，避免纯文字描述
- 痛点必须按严重度排序，避免罗列无优先级
- 优化机会必须含落地方案 + 预期效果 + 回滚预案
- 访谈样本量低于 5 时必须标注「样本量不足，结论仅供参考」
- 所有结论标注置信度与 ±10% 调整空间

## 7. 风险控制

| 规则编号 | 风险点 | 控制动作 |
|---------|--------|---------|
| R-01 | 旅程覆盖不全 | 必须覆盖完整路径，含流失阶段 |
| R-02 | 痛点脱离用户实际 | 必须基于访谈或问卷数据，禁止纯臆测 |
| R-03 | 样本量不足 | <5 样本必须标注「仅供参考」 |
| R-04 | 优化方案脱离业务实际 | 必须含回滚预案 + 落地难度评估 |
| R-05 | 绝对性建议 | 禁止「必须改 / 一定要优化」措辞 |
| R-06 | 调整空间预留不足 | 所有结论附加 ±10% 调整空间 |
| R-07 | 强监管赛道合规缺位 | 涉及合规触点必须调用角色 07 复核 |

|---------|---------|---------|
| 角色 01 业务需求分析师 | 用户旅程初稿细化 | 用户旅程初稿 + 痛点清单 |
| 角色 02 产品经理（自身） | PRD 优化 | 优化建议 + 交互逻辑调整 |

| 角色 07 合规专家 | 合规触点审查 | 涉及合规的触点 + 风险等级 |

**输出传递标记**：`[下一环节传递：用户旅程图 + 痛点清单 + 优化机会清单]`
