# 技能模块：incident_response_sop

> 故障应急响应标准流程：定级 → 止损 → 溯源 → 复盘 → 预防。

## 1. 技能描述

本技能定义线上故障应急响应标准操作流程（SOP），覆盖故障定级（P0/P1/P2/P3）→ 紧急止损 → 根因溯源 → 复盘总结 → 整改预防全链路。强调「先恢复后定位」原则，确保业务连续性。输出止损方案、溯源报告、整改措施、复盘报告。

## 2. 触发条件

- 输入包含「故障应急」「故障响应」「止损」「溯源」「复盘」「线上事故」等关键词
- 收到监控告警（自动触发）
- 用户大面积反馈 / 客服上报
- 故障已造成业务影响（核心功能不可用、数据异常、性能严重退化）

## 3. 执行步骤

1. **故障定级**（5 分钟内）：P0 严重（核心功能完全不可用，影响 ≥10% 用户）/ P1 高危（部分不可用，1-10%）/ P2 中危（<1%）/ P3 低危（体验问题）。
2. **应急响应启动**：拉群通知、值班人员就位、向上汇报、启动 War Room。
3. **紧急止损**（P0/P1 优先，30 分钟内）：优先回滚（最近发布版本）→ 流量切换（同城 / 异地容灾）→ 限流降级 → 重启服务 → 资源扩容。
4. **根因溯源**（止损后 24 小时内）：时间线还原 + 日志分析（应用/系统/访问日志）+ 链路追踪 + 变更分析（代码/配置/依赖）+ 资源分析（CPU/内存/网络/磁盘）。
5. **影响评估**：用户影响、业务影响、数据影响、合规影响。
6. **复盘总结**（72 小时内）：5W2H 分析，识别系统性问题。
7. **整改措施**：短期（修复 Bug）、中期（流程优化）、长期（架构改进）+ 预防机制（监控告警、预案演练、SOP 更新）。

## 4. 输入规范

```yaml
任务类型: 故障应急响应
故障描述: 订单服务大量超时，下单失败
影响范围: 全量用户，下单失败率 30%
发现时间: 2026-08-15 14:30
告警来源: Prometheus 告警 + 客服反馈
监控数据: [Grafana 链接]
最近变更: 2026-08-15 14:00 发布 v2.1.0
影响业务: 电商核心交易
```

## 6. 质量标准

- P0/P1 故障必须在 5 分钟内定级，30 分钟内止损
- 故障复盘必须在 72 小时内完成
- 整改措施必须有时限与责任人，禁止「加强关注」等无落地措施
- 根因分析必须深挖到根本原因，禁止停留在表面现象
- 复盘报告必须包含时间线、根因、影响、整改四要素

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 止损优先于定位，禁止为定位延迟止损 |
| RISK-02 | P0/P1 故障必须向上汇报，禁止隐瞒 |
| RISK-03 | 数据修复必须经过 DBA 评审，故障期间禁止任何变更 |
| RISK-04 | 整改措施未完成禁止关闭故障单，同类故障复发必须升级处理 |
| RISK-05 | 涉及用户数据泄露的故障必须同步合规与法务 |
