# user_requirement_mining | 用户需求挖掘

## 1. 技能描述

本技能面向业务需求分析师，提供目标用户的核心需求挖掘能力。覆盖用户画像构建、需求清单梳理（刚需 / 非刚需区分）、需求验证方案设计、用户旅程初稿绘制四大模块。通过桌面研究 + 用户访谈（如可行）输出可支撑 PRD 设计的需求输入，确保需求识别准确率 ≥95%。

## 2. 触发条件

满足以下任一条件即触发：
- 输入包含「用户画像 / 用户需求 / 用户调研 / 需求清单 / 刚需 / 非刚需」等关键词
- 业务方要求进行立项前用户研究或新版本需求验证
- 角色 01 被激活且场景为「用户需求初筛」

## 3. 执行步骤

1. **调研目标确认**：明确产品方向、目标用户、调研范围、时间预算
2. **桌面研究**：通过行业报告、竞品资料、社区评价收集用户行为数据
3. **用户访谈设计**：设计访谈提纲（如可行执行访谈，样本量 ≥5）
4. **用户画像初稿构建**：覆盖基础属性、行为特征、决策路径、痛点场景
5. **核心需求清单梳理**：区分刚需 / 非刚需，按优先级排序
6. **需求验证方案设计**：输出 MVP / 用户访谈 / 问卷调查 / A-B 测试组合方案
7. **用户旅程初稿绘制**：标注关键触点、情绪曲线、痛点、机会点
8. **需求优先级排序**：按用户价值 + 商业价值 + 实现成本三维评估
9. **风险控制校验**：标注数据来源、样本量、置信度、调整空间

## 4. 输入规范

```yaml
产品方向: "AI 驱动的智能投研助手"
目标用户: "机构投研人员"
调研范围: "用户画像 + 核心需求清单"
时间预算: "1 周"
可执行访谈: "是 / 否"
访谈样本量: "5-10"
强监管判定: "否"
输出格式: "用户画像 + 需求清单 + 验证方案"
```

## 5. 输出格式

```markdown

### 一、用户画像初稿
- 基础属性：[清单]
- 行为特征：[清单]
- 决策路径：[流程]
- 痛点场景：[清单]

### 二、核心需求清单
| 需求项 | 类型（刚需/非刚需） | 优先级 | 用户价值 | 商业价值 |

### 三、需求验证方案
| 验证方法 | 样本量 | 验证目标 | 时间周期 |

### 四、用户旅程初稿
- 关键触点 + 情绪曲线 + 痛点 + 机会点

### 五、需求优先级矩阵
- 按 RICE 评分排序的需求清单
```

## 6. 质量标准

- 用户画像必须覆盖基础属性 + 行为特征 + 决策路径 + 痛点场景四维度
- 需求清单必须区分刚需 / 非刚需，并标注用户价值 + 商业价值
- 访谈样本量低于 5 时必须标注「样本量不足，结论仅供参考」
- 需求验证方案必须含至少 2 种方法组合
- 用户旅程必须标注关键触点 + 情绪曲线 + 痛点 + 机会点四要素
- 所有结论标注置信度（高 / 中 / 低）与 ±10% 调整空间

## 7. 风险控制

| 规则编号 | 风险点 | 控制动作 |
|---------|--------|---------|
| R-01 | 需求真伪混淆 | 强制区分「用户需求 vs 解决方案」「表象 vs 根本需求」 |
| R-02 | 样本量不足 | <5 样本必须标注「仅供参考」 |
| R-03 | 需求脱离业务实际 | 必须结合业务背景与商业化模式评估 |
| R-04 | 强监管赛道合规缺位 | 必须调用角色 00 / 07 复核 |
| R-05 | 内部数据未脱敏 | 内部用户数据需脱敏处理 |
| R-06 | 调整空间预留不足 | 所有结论附加 ±10% 调整空间 |
| R-07 | 数据时效过期 | 引用报告超 6 个月需重新核验 |
