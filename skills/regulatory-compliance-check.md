# 技能模块：regulatory_compliance_check

> 业务合规性审查，匹配法规要求输出合规风险清单。

## 1. 技能描述

本技能对业务场景与产品方案开展合规性审查，匹配适用法规要求，输出结构化合规风险清单（含风险等级、对应条款、影响范围）与整改建议。覆盖《个人信息保护法》《数据安全法》《网络安全法》《生成式 AI 服务管理暂行办法》《GDPR》等核心法规，并关注等保 2.0、算法备案、内容审核等专项要求。

## 2. 触发条件

- 输入包含「合规审查」「合规风险」「个保法」「数安法」「生成式 AI」「GDPR」等关键词
- 已提供业务场景描述与产品方案
- 涉及个人信息收集、数据跨境、AI 内容生成、金融 / 医疗等强监管领域
- 新产品立项或重大版本上线前必须审查

## 3. 执行步骤

1. **业务场景解析**：梳理业务模式、用户群体、数据流向、技术应用（是否涉及 AI）。
2. **适用法规识别**：根据业务场景匹配适用法规（个保法 / 数安法 / 网安法 / 生成式 AI 办法 / GDPR / 行业监管）。
3. **合规要点核查**：
   - 个人信息处理合法性基础（同意 / 履行合同 / 法定义务）
   - 数据分类分级（一般 / 重要 / 核心）
   - 数据跨境传输（安全评估 / 标准合同 / 认证）
   - AI 服务合规（算法备案、内容审核、训练数据合规、用户标注）
   - 等保 2.0 等级与备案
4. **风险识别**：逐条比对法规要求与现状，识别合规风险点。
5. **风险评估**：按风险等级（高 / 中 / 低）+ 影响范围 + 法律责任分级评估。
6. **整改建议**：针对每个风险点给出可落地整改方案 + 责任部门 + 整改时限。
7. **合规审查报告**：输出审查结论（通过 / 有条件通过 / 不通过）+ 风险清单 + 整改建议。

## 4. 输入规范

```yaml
任务类型: 合规审查
业务场景: 智能客服 SaaS 平台，面向金融行业
产品方案: [产品 PRD 链接]
数据处理流程:
  收集: 用户对话内容 + 设备信息
  存储: 境内云服务
  跨境: 暂无
AI应用: 是（大模型 + RAG）
用户协议: [用户协议 + 隐私政策链接]

```

## 5. 输出格式

```markdown
## 当前角色：合规与风控专家
### 执行场景: 合规审查
### 适用法规识别
- 个保法、数安法、网安法
- 生成式 AI 服务管理暂行办法
- 等保 2.0（建议第三级）
### 合规风险清单
| 编号 | 风险点 | 适用法规 | 对应条款 | 风险等级 | 影响范围 | 整改建议 | 责任部门 |
| C-001 | 未单独同意处理敏感个人信息 | 个保法 | 第29条 | 高 | 用户投诉 + 监管处罚 | 增加单独同意流程 | 产品+法务 |
| C-002 | AI 服务未做算法备案 | 生成式AI办法 | 第17条 | 高 | 下架 + 罚款 | 启动算法备案 | 法务 |
### 整改建议（按优先级）
| 优先级 | 风险 | 整改方案 | 责任部门 | 时限 |
### 审查结论: ✅ 通过 / ⚠️ 有条件通过 / ❌ 不通过
### 法律责任提示 / 后续建议 / 置信度
```

## 6. 质量标准

- 适用法规必须穷尽识别，遗漏关键法规视为审查失败
- 风险点必须对应到具体条款（条 / 款 / 项）
- 整改建议必须可落地，包含责任部门与时限
- 涉及强监管领域（金融 / 医疗 / 教育）必须叠加行业监管要求
- AI 业务必须核查算法备案、内容审核、训练数据合规
- 审查结论必须明确，禁止「应该问题不大」等模糊措辞

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 高风险合规问题未整改禁止上线 |
| RISK-02 | 涉及个人信息出境必须做安全评估 |
| RISK-03 | AI 服务上线前必须完成算法备案 |
| RISK-04 | 等保级别不达标禁止存储核心数据 |
| RISK-05 | 涉及未成年人必须有专门合规设计 |
| RISK-06 | 金融业务必须叠加金融监管要求 |
| RISK-07 | 审查结论必须有法务签字确认 |
