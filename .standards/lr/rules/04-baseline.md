# R3 基线与防护网 · 04-baseline（LR-STD-001）

> 输入：D-R2-01~03（计划就绪）
> 出口门禁：D-R3-01 行为基线测试报告 / D-R3-02 数据快照与校验方案 / D-R3-03 回滚预案（均 approved）
> **铁律 1 的执行点：本阶段门禁未过，禁止 R4 的一切旧代码修改与切换。**

## 1. 阶段目标

重构的安全网：行为基线（证明"旧行为是什么"）、数据快照（可恢复的参照点）、
回滚预案（切换失败的逃生通道）。三者齐备才有资格动旧系统。

## 2. 行为基线（特征测试）

1. **选路径**：从 LPU features-api.md 的功能-入口映射表选取核心路径，
   覆盖标准：全部 P0 业务流程 + 全部对外接口契约 + 状态机全迁移边。
2. **写特征测试**（Characterization Test）：以"记录现状"为目的（不是"验证正确"）——
   旧行为哪怕是 bug 也先固化（bug 的修复属于行为变更，走 D-R0-01 的
   行为变更预算），测试命名 `char_<模块>_<行为>`。
3. **金样本**：核心接口录制请求-响应对（Golden Files），供 R4 对照验证复用。
4. 基线测试必须在新旧两侧**都可执行**（旧侧跑旧代码、新侧跑新代码），
   这是对照验证的机制前提。

## 3. 数据快照与校验

1. 快照范围：纳入 R4 数据单元的全部表 + 关联的外键约束链。
2. 快照方式：结构（DDL+索引+约束）+ 数据（全量或分桶）+ 序列/自增值状态。
3. 校验方案：行数核对、主键集合比对、业务汇总数比对（金额/数量级校验）、
   抽样字段逐位比对（抽样率与判定阈值写入方案）。
4. 快照的**一致性时点**必须可复现（停写窗口/事务快照/复制一致性点，三选一并记录）。

## 4. 回滚预案

逐批次编制：触发条件（量化指标：错误率阈值/数据校验失败数）、回滚动作序列
（流量切回→数据回补→通知链）、回滚时限（RTO）、责任人、演练记录。
**预案必须经过至少一次桌面演练并记录。**

## 5. 协作要点

- 角色：06（测试）主责特征测试与金样本，09（SRE）主责快照与回滚演练。
- 特征测试套件是长期资产：R4 每单元对照验证复用，R5 验收复用。
- 快照存储位置与保留期限写入 D-R3-02，并与 AETC 检查点机制关联
  （每次切换前创建检查点 = 增量快照 + 流量标记）。
