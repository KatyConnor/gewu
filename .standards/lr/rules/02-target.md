# R1 目标架构与规范制定 · 02-target（LR-STD-001）

> 输入：D-R0-01 立项决议书
> 出口门禁：D-R1-01 目标架构 / D-R1-02 技术选型 ADR / D-R1-03 工程规范采纳清单 / D-R1-04 数据模型目标（均 approved）

## 1. 阶段目标

回答"重构成什么样"：目标架构、技术栈、工程规范、数据模型。这是用户诉求
"制定出所有规范和技术文档"的主落地阶段——**规范制定本身就是 R1 的交付物**。

## 2. 动作清单

1. **现状锚定**：以 LPU architecture.md / database.md 为基线，建立"现状→目标"
   差距分析表（每个目标组件标注其替代的旧组件）。
2. **目标架构设计**：分层、模块边界、接口契约、部署形态。绞杀者模式下
   必须设计**新旧并存层**（路由/适配器/防腐层 ACL）——这是双轨期的结构前提。
3. **技术选型**：逐项 ADR（架构决策记录）格式：背景/候选/决策/后果/退出成本。
   退出成本是重构场景必填项（防止二次锁定）。
4. **工程规范采纳**：以 CR-RULES 为基座 + 项目特化条款（分层命名、错误码、
   日志规范、测试策略），形成《工程规范采纳清单》——引用而非重写 CR 规则正文。
5. **数据模型目标设计**：对标 LPU database.md 的 ERD/数据字典，给出目标模型、
   与旧模型的字段映射初稿（后续 R4 数据单元细化）、状态枚举映射终稿
   （承接 rebuild-plan 的 RBH-002 表）。

## 3. 四份必输文档

| 文档 | 必要章节要点 |
|---|---|
| D-R1-01 目标架构设计 | 分层图、模块清单与职责、接口契约、新旧并存层设计、与现状的差距分析表 |
| D-R1-02 技术选型 ADR | 每项选型一条 ADR（背景/候选/决策/后果/**退出成本**），含"沿用旧技术"的显式决策 |
| D-R1-03 工程规范采纳清单 | CR-RULES 引用条款号、项目特化条款全文、测试策略（特征测试/单元/集成比例） |
| D-R1-04 数据模型目标设计 | 目标 ERD、字段映射初稿表（旧表.字段→新表.字段）、状态枚举映射终稿、不可逆变更标注 |

## 4. 协作要点

- 角色：SDLC 角色 03（架构师）主责，角色 02（产品）确认功能对齐，
  角色 05（安全）参与安全基线条款。
- D-R1-04 的"不可逆变更标注"条目自动进入 D-R2-03 风险登记册。
- 所有 ADR 结论必须在后续阶段可追溯（R4 实施偏离 ADR 时需回改 ADR 并留变更记录）。
