# R2 重构规划与拆解 · 03-planning（LR-STD-001）

> 输入：D-R0-01（范围）、D-R1-01~04（目标）
> 出口门禁：D-R2-01 迁移单元清单 / D-R2-02 重构路线图 / D-R2-03 风险登记册（均 approved）

## 1. 阶段目标

把目标架构"翻译"为可执行的作战序列：迁移单元细化到可独立验证、可独立回滚的
粒度，排定依赖顺序与批次，登记风险与预案。

## 2. 迁移单元拆解规则

以 LPU rebuild-plan 的 M1~Mn 为起点，细化时遵循：

1. **可验证**：每个单元有明确的验收标准（基于 LPU features-api.md 的行为描述）。
2. **可回滚**：单元切换后能在回滚时限内恢复旧路径（回滚时限写入单元卡片）。
3. **可观察**：单元切换后有独立的可观测指标（错误率/延迟/业务计数）。
4. **依赖最小前置**：依赖图按 LPU architecture.md 的模块依赖与
   features-api.md 的入口归属确定；同批单元间禁止隐式共享可变状态。
5. **三类单元**：功能单元（页面/API/任务）、数据单元（表/迁移脚本）、
   接口契约单元（对外集成点）。数据单元默认排在其消费方功能单元之前一批完成。

单元卡片字段：编号/类型/范围（旧模块→新模块）/依赖前置/验证方式/回滚方式/
预估工作量/风险关联/负责人。

## 3. 路线图编排

- 批次 = 一组可同时切换的单元；批次间是绞杀者循环的"圈"。
- 首批必须含一个**试点单元**：小、独立、有代表性（验证整套流程而非只验证功能）。
- 末批必须含**退役批**：旧系统下线与归档（衔接 R5）。
- 每批预留对照验证与观察期时长（默认：切换后观察 ≥1 个业务周期或 ≥48h，
  取先到者，可在立项决议中调整）。

## 4. 风险登记册

合并三个来源并持续更新：LPU rebuild-plan §3（理解层风险）、D-R1-04 不可逆变更
（数据层风险）、R2 编排新增（计划层风险）。每条风险：编号/描述/关联证据/阶段/
防御措施/回退措施/责任人/状态。**无回退措施的风险必须升级用户决策。**

## 5. 协作要点

- 角色：10（项目管理）主责排序与批次，03（架构师）审核依赖图。
- D-R2-01/02 的任何后续变更走"计划变更记录"附页，不静默改版。
