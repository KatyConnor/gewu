# Go 编码规范

> Agent 生成 Go 代码时必须遵守本文件规则。
> 基础标准：Effective Go + Google Go Style Guide + Go Code Review Comments

---

## 1. 项目结构

```
project/
├── cmd/
│   └── server/
│       └── main.go          # 入口
├── internal/                 # 私有包（不可被外部导入）
│   ├── handler/
│   ├── service/
│   ├── repository/
│   └── model/
├── pkg/                      # 公共包（可被外部导入）
│   ├── logger/
│   └── errors/
├── api/                      # API 定义（OpenAPI/proto）
├── configs/
├── go.mod
├── go.sum
└── Makefile
```

- `cmd/` 只做入口，业务逻辑在 `internal/`
- `internal/` 强制封装，外部不可导入
- `pkg/` 放可复用工具

## 2. 命名规范

| 对象 | 风格 | 示例 | 说明 |
|------|------|------|------|
| 导出 | PascalCase | `UserService` | 首字母大写=导出 |
| 未导出 | camelCase | `userService` | 首字母小写=包内 |
| 常量 | PascalCase | `MaxRetries` | 导出时用 PascalCase |
| 接口 | PascalCase + er | `Reader` | 单方法接口名 = 方法名 + er |
| 包名 | 全小写 | `httputil` | 简短，不用下划线 |
| 文件 | snake_case | `user_service.go` | |
| 测试 | xxx_test.go | `user_service_test.go` | |

### 命名习惯

- 缩写全大写或全小写：`URL` / `HTTP` → 导出 `ParseURL`，未导出 `parseHTTP`
- 禁止 Hungarian 记号：`strName` / `iCount` 禁止
- 包名 = 目录名，避免 `import X as Y`

## 3. 错误处理

```go
// DON'T — 忽略错误
result, _ := doSomething()

// DON'T — panic 用于业务错误
func getUser(id int) *User {
    user := db.Find(id)
    if user == nil {
        panic("user not found")  // 禁止！
    }
    return user
}

// DO — 显式处理
result, err := doSomething()
if err != nil {
    return fmt.Errorf("doSomething failed: %w", err)
}

// DO — 业务错误用 sentinel
var ErrUserNotFound = errors.New("user not found")

func FindUser(id int) (*User, error) {
    user, err := repo.Find(id)
    if err != nil {
        return nil, fmt.Errorf("find user %d: %w", id, err)
    }
    if user == nil {
        return nil, ErrUserNotFound
    }
    return user, nil
}
```

### 错误规则

- 禁止 `_` 忽略 error 返回值
- 错误传播必须 `%w` wrap
- 错误信息带上下文：`fmt.Errorf("find user %d: %w", id, err)`
- 禁止 `panic` 用于业务逻辑（仅 init 和不可恢复场景）
- `errors.Is` / `errors.As` 用于错误判断，不用字符串比较
- 自定义错误类型实现 `Error() string`

## 4. 并发编程

```go
// DON'T — goroutine 泄漏
func processData(data []byte) {
    go func() {
        result := heavyWork(data)
        // 没有人接收结果 → goroutine 泄漏
    }()
}

// DO — context 控制 + WaitGroup
func processData(ctx context.Context, data []byte) error {
    results := make(chan Result, 1)
    var wg sync.WaitGroup
    wg.Add(1)

    go func() {
        defer wg.Done()
        select {
        case <-ctx.Done():
            return
        case results <- heavyWork(data):
        }
    }()

    select {
    case <-ctx.Done():
        return ctx.Err()
    case r := <-results:
        return processResult(r)
    }
}
```

### 并发规则

- goroutine 必须有退出机制（context / channel close）
- 禁止 goroutine 泄漏（启动后无人等待结果）
- channel 优先于 mutex（当传递数据时）
- 有缓冲 channel 用于解耦生产消费，无缓冲用于同步
- 禁止 `sync.Mutex` 复制值（必须指针传递）
- `defer mu.Unlock()` 紧跟 `mu.Lock()`

## 5. 接口设计

```go
// DON'T — 大接口
type UserStore interface {
    Get(id int) (*User, error)
    Create(user *User) error
    Update(user *User) error
    Delete(id int) error
    List(filter Filter) ([]*User, error)
    Count(filter Filter) (int, error)
    BatchCreate(users []*User) error
}

// DO — 小接口（接口隔离）
type UserReader interface {
    Get(id int) (*User, error)
}

type UserWriter interface {
    Create(user *User) error
    Update(user *User) error
    Delete(id int) error
}
```

### 接口规则

- 接口定义在消费方，不是实现方
- 单方法接口名 = 方法名 + `er`
- 接口最小化，组合大于继承
- 接口方法不超过 5 个

## 6. 结构体与构造

```go
// DON'T — 导出字段直接暴露
type Server struct {
    Port     int
    Host     string
    Timeout  time.Duration
}

// DO — 选项模式
type Server struct {
    port     int
    host     string
    timeout  time.Duration
}

type Option func(*Server)

func WithPort(port int) Option {
    return func(s *Server) { s.port = port }
}

func WithTimeout(d time.Duration) Option {
    return func(s *Server) { s.timeout = d }
}

func NewServer(opts ...Option) *Server {
    s := &Server{
        port:    8080,
        host:    "localhost",
        timeout: 30 * time.Second,
    }
    for _, opt := range opts {
        opt(s)
    }
    return s
}
```

## 7. Context 使用

```go
// DON'T — 不传递 context
func GetUser(id int) (*User, error) {
    return db.Query("SELECT * FROM users WHERE id = ?", id)
}

// DO — context 作为第一个参数
func GetUser(ctx context.Context, id int) (*User, error) {
    return db.QueryContext(ctx, "SELECT * FROM users WHERE id = ?", id)
}

// context 规则
// 1. ctx 作为函数第一个参数
// 2. 禁止将 ctx 存入结构体字段
// 3. 禁止传 nil context，用 context.Background()
// 4. 禁止 context.AfterFunc 用于正常取消
```

## 8. Slice 与 Map

```go
// DON'T — 不检查 nil
func process(items []Item) {
    for _, item := range items {  // items 为 nil 时不报错，但语义不明确
        ...
    }
}

// DO — 空集合用 make 初始化
func process(items []Item) {
    if len(items) == 0 {
        return
    }
    ...
}

// DON'T — 在循环中取地址
var pointers []*int
for _, v := range values {
    pointers = append(pointers, &v)  // BUG: 所有指针指向同一个地址!
}

// DO
for i := range values {
    pointers = append(pointers, &values[i])
}
```

## 9. 测试

```go
func TestUserService_Create(t *testing.T) {
    // Arrange
    repo := &mockRepo{}
    service := NewUserService(repo)
    input := User{Name: "Alice", Email: "alice@example.com"}

    // Act
    user, err := service.Create(context.Background(), input)

    // Assert
    if err != nil {
        t.Fatalf("unexpected error: %v", err)
    }
    if user.Name != "Alice" {
        t.Errorf("expected Alice, got %s", user.Name)
    }
}

// Table-driven tests
func TestEmailValidator(t *testing.T) {
    tests := []struct {
        email string
        valid bool
    }{
        {"user@example.com", true},
        {"invalid", false},
        {"", false},
    }
    for _, tt := range tests {
        t.Run(tt.email, func(t *testing.T) {
            if got := ValidateEmail(tt.email); got != tt.valid {
                t.Errorf("ValidateEmail(%q) = %v, want %v", tt.email, got, tt.valid)
            }
        })
    }
}
```

## 10. gofmt 与 lint

- 代码必须通过 `gofmt`
- `goimports` 管理导入
- `golangci-lint` 至少启用：`errcheck` / `govet` / `staticcheck` / `gocritic` / `revive`
- 禁止使用 `init()` 执行副作用（只用于注册）
