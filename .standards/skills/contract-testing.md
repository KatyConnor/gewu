# 技能模块：contract_testing

> 消费者驱动契约（CDC）：消费者定义期望 → 契约文件版本化 → 提供者验证 + CI 双向门禁。契约漂移三态不一致（文档≠契约≠实现）= 阻断。

## 1. 技能描述

本技能补齐体系契约链的**实现侧闭环**：03 的 api-contract-definition 管契约定义、12 的 api-doc-generation 管文档对账，本技能在 04 侧落地"契约的可执行验证"。方法：消费者侧定义期望（请求/响应 schema+样例）→ 生成版本化契约文件（Pact/Spring Cloud Contract，轻量路径可用 OpenAPI schema 校验）→ 提供者侧本地验证 + CI 挂门禁（提供者变更破坏契约 = 构建失败）→ 契约变更走通知流（03 重审 → 12 对账 24h）。边界：契约测试验证**接口兼容性**，业务正确性的集成/系统测试归角色 06。

## 2. 触发条件

- 输入包含「契约测试」「消费者驱动契约」「Pact」「联调」「跨服务集成」等关键词
- 前后端/微服务间接口进入开发或变更
- 契约漂移告警（文档/契约/实现不一致）

## 3. 执行步骤

1. **消费者-提供者识别**：圈定本需求的接口对（前端-后端 / 服务A-服务B），登记消费者清单。
2. **消费者期望用例**：每个消费者为所用字段写期望（schema+样例+状态：如"用户存在/不存在"）。
3. **契约文件生成**：期望合成版本化契约文件（语义版本，破坏性变更 major）。
4. **提供者验证**：本地跑 provider 验证（provider states 打桩），失败即修。
5. **CI 双向门禁**：消费者侧（期望变更）与提供者侧（实现变更）都挂契约校验，任一破坏 = 构建失败。
6. **变更通知流**：契约文件变更 → 通知 03 重审契约 → 通知 12 文档对账（24h 口径）。
7. **漂移对账**：周期比对文档/契约/实现三态，不一致项阻断合入。

## 4. 输入规范

```yaml
api_contract: 契约定义（03 产出的接口文档路径）
consumers: [{name, consumed_endpoints}]
provider: 服务名
tooling: pact | spring-cloud-contract | openapi-schema（轻量路径）
ci: 目标 CI 平台与门禁挂载点
```

## 5. 输出格式

```markdown
# 契约测试实施报告
## 接口对清单（消费者×提供者）
## 消费者期望用例（字段/状态/样例计数）
## 契约文件（版本/破坏性变更标记）
## 双向验证结果（提供者验证/CI 门禁状态）
## 变更通知记录（03 重审/12 对账）
## 漂移对账三态比对结果
```

## 6. 质量标准

- 跨边界接口 100% 有契约文件（无契约的跨端/跨服务集成禁止合并）
- 契约破坏 100% CI 阻断（零静默通过）
- 契约变更 100% 走通知流（03 重审+12 对账）
- 漂移三态比对周期化执行（文档/契约/实现）
- provider states 覆盖契约声明的全部状态

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 无契约的跨边界合并 = 违规（直接阻断） |
| RISK-02 | 契约漂移三态不一致未处置 = 阻断（先对齐再开发） |
| RISK-03 | 契约测试冒充集成测试 = 边界越权（业务正确性归 06） |
| RISK-04 | 破坏性变更未升 major 版本 = 消费者静默失败 |
| RISK-05 | 契约文件与代码不同库同版本管理 = 漂移温床 |

## 8. 跨角色协作接口

```yaml
上游角色:
  - 03-技术架构师: 提供契约定义（api-contract-definition）；接收变更重审
  - 02-产品经理: 提供接口级需求变更
下游角色:
  - 06-测试专家: 契约验证通过后交接集成/系统测试
  - 12-技术写作: 接收契约变更通知（24h 文档对账口径）
  - 09-SRE专家: CI 门禁配置协同
传递字段: [契约文件, 期望用例, 验证报告, 变更通知]
```
