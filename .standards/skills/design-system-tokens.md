# 技能模块：design_system_tokens

> 设计令牌的单一真源维护：语义命名、层级映射、变更管控、一致性走查，与 ui-design/design-tokens.json 强制同源。

## 1. 技能描述

本技能负责设计令牌体系的维护与变更管控。核心原则：**单一真源**（design-tokens.json 是唯一权威，冲突以令牌文件为准）、**语义分层**（primitive 原始层 → semantic 语义层 → component 组件层）、**变更可追溯**（任何令牌变更必须走变更单并评估影响面）。产出包括令牌变更单、语义令牌映射表、组件规格与一致性走查报告，为界面方案（ux-wireframe-prototyping 技能）提供数值基座。

## 2. 触发条件

- 输入包含「设计系统」「设计令牌」「token」「主题」「组件规格」「视觉规范」等关键词
- 存在待变更的令牌需求（新增 / 修改 / 废弃）
- 界面方案中发现令牌缺口（现有令牌无法覆盖新方案）
- 一致性走查需求（跨页面 / 跨组件规格一致性）

## 3. 执行步骤

1. **令牌盘点审计**：读取 design-tokens.json，统计三层令牌现状（primitive / semantic / component），识别孤立令牌（无引用）与冲突令牌（多义引用）。
2. **变更影响面分析**：对每个待变更令牌，列出全部引用方（页面 / 组件 / 方案），评估变更半径。
3. **语义命名与层级映射**：新令牌按语义命名规范登记（如 color-primary-fixed / text-secondary / space-lg），禁止以视觉数值命名（禁止 blue-500 类原始值直接出现在方案层）。
4. **组件规格产出**：组件层令牌绑定（组件 × 状态 × 令牌引用），状态数显式声明。
5. **变更单落盘**：产出令牌变更单（变更类型 / 影响面 / 迁移路径 / 回滚方案），同步更新 design-tokens.json（单一真源义务）。
6. **一致性走查**：抽样核对同类组件、同类状态在不同方案的令牌引用一致性，输出偏差清单。

## 4. 输入规范

```yaml
令牌基线: ui-design/design-tokens.json
变更需求: [新增/修改/废弃 + 描述]
组件清单: [受影响组件]
品牌约束: [主题色/字体族约束]
走查范围: [页面/组件抽样清单]
```

## 5. 输出格式

```markdown
## 令牌变更单（编号）

### 变更明细
| 类型 | 令牌名 | 旧值 | 新值 | 层级 |
|------|--------|------|------|------|

### 影响面分析
- 引用方清单：[页面/组件/方案]
- 变更半径：[N 处引用 / M 个组件]

### 语义令牌映射表
| 语义令牌 | 原始令牌 | 用途 | 引用组件 |

### 迁移路径
- 阶段 1：[新令牌并行引入]
- 阶段 2：[引用方迁移]
- 阶段 3：[旧令牌废弃]

### 回滚方案
- 触发条件与回退路径

### 一致性走查结论
- 抽样清单：[...]
- 偏差项：[阻断/建议/忽略 分级]
```

## 6. 质量标准

- 令牌三层结构完整（primitive / semantic / component），层间引用方向单一（禁止跨层反向引用）
- 语义命名 100%（方案层禁止出现原始数值命名）
- 变更单必含影响面分析与回滚方案
- design-tokens.json 同步率 100%（变更单与文件状态一致）
- 孤立令牌（无引用）每轮审计清理或标注保留理由
- 同类组件同类状态的令牌引用一致性 ≥ 95%（走查抽样口径）

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 绕过变更单直接改 design-tokens.json 禁止（单一真源 + 变更管控） |
| RISK-02 | 破坏性变更（废弃/改值）无迁移路径禁止合入 |
| RISK-03 | 方案引用未登记令牌（私有数值）强制走变更单或替换 |
| RISK-04 | 令牌变更后 24h 内同步受影响方案与走查记录 |
| RISK-05 | 主题切换场景（亮/暗）必须验证语义令牌完整性 |
| RISK-06 | 变更影响面 ≥ 10 处引用时升级为设计系统评审（含 03/04 会签） |

