# 技能模块：growth_experiment_design

> 假设卡→设计（分流/MDE/时长/互扰登记）→灰度→判读（08 出统计结论）→放量决策全链。13 管设计与决策，08 管统计。

## 1. 技能描述

本技能负责增长实验的工程化设计纪律：从诊断技能产出的假设卡出发，完成实验设计四要素（分流单元/最小可检测效应 MDE/最短时长/并行互扰登记），启动灰度（与 06 协同），发起 08 统计判读请求，依据结论与反向指标做放量/迭代/回滚决策并留痕归档。核心分权：**13 不得自行计算显著性后放量**——统计结论唯一来源是 08；13 的决策单必须引用 08 结论与反向指标检查双证据。

## 2. 触发条件

- 输入包含「增长实验」「A/B 实验」「放量」「灰度」「MDE」等关键词
- 存在已排序的假设卡（来自漏斗诊断或分层洞察）
- 放量决策需求或并行实验登记需求

## 3. 执行步骤

1. **假设卡核验**：预期指标（主指标）与反向指标（护栏指标）齐备；缺反向指标退回补充。
2. **实验设计四要素**：分流单元（用户级/会话级）/ MDE（依据基线转化率与业务最小价值）/ 最短时长（覆盖完整周期效应）/ 并行互扰登记（同期实验分流重叠评估）。
3. **灰度启动**：小比例放量 + 06 协同的实验 QA（埋点与分流正确性验证）。
4. **判读请求**：向 08 提交统计判读请求（主指标/反向指标/MDE/窗口），等待结论。
5. **决策三选一**：放量（结论显著+反向指标健康）/ 迭代（不显著但方向信号）/ 回滚（反向指标恶化），决策单留痕。
6. **档案归档**：假设→设计→数据→结论→决策全链归档，供后续假设校准（诊断技能回灌）。

## 4. 输入规范

```yaml
hypothesis: {insight_source, statement, primary_metric, guard_metrics, expected_direction}
baseline: {current_rate, sample_size_per_period}
parallel_experiments: [{id, traffic_share, overlap_unit}]
decision_thresholds: {significance_ref: "08", guard_tolerance}
```

## 5. 输出格式

```markdown
# 增长实验设计单（编号）
## 假设（来源/陈述/主指标/反向指标）
## 设计四要素（分流/MDE/时长/互扰登记）
## 灰度与 QA 记录
## 08 判读请求与结论引用
## 放量/迭代/回滚决策单（双证据：统计结论+反向指标）
## 归档编号与回灌标记
```

## 6. 质量标准

- 设计单四要素 100% 齐备（缺任一禁止启动）
- 决策单 100% 双证据（08 结论引用 + 反向指标检查记录）
- 并行实验 100% 登记互扰评估（未登记的同期实验判为纪律违规）
- 主指标 100% 配反向指标（虚荣指标防线）
- 实验档案 100% 含决策结论（禁止"做完了没结论"）

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 无对照/单臂实验禁止（铁律） |
| RISK-02 | 未过显著性放量 = GATE 违规（回滚并复盘） |
| RISK-03 | 13 自行计算显著性后放量 = 越权（统计权归 08） |
| RISK-04 | 时长不足提前判读须标注"周期效应未覆盖" |
| RISK-05 | 反向指标恶化时无论主指标多好必须回滚优先 |
