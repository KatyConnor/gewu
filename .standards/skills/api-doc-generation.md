# 技能模块：api_doc_generation

> 从 API 契约到对外文档：端点全覆盖、示例全可运行、错误码全闭环，契约为唯一事实源。

## 1. 技能描述

> 成文模板：`.standards/templates/TPL-APIREF.md`（API 参考文档——Reference 定位，示例 100% 可运行纪律与本技能对齐）。

本技能将 03 技术架构师定义的 API 契约（含 OpenAPI/Swagger 规范形态）转化为面向开发者的对外 API 文档。核心纪律：**契约为唯一事实源**（文档不得私改参数/错误码/限制语义）、**示例必须可运行**（每端点至少一个经过实际执行的请求-响应对）、**错误码闭环**（契约定义的每个错误码在文档中有触发条件与处置建议）。输出附契约-文档对账表，供漂移检测。

## 2. 触发条件

- 输入包含「API 文档」「接口文档」「OpenAPI」「Swagger」「端点文档」等关键词
- 存在 03 产出的 API 契约文档或 OpenAPI/Swagger 规范文件
- 新端点上线、契约变更同步、或文档准出检查需求

## 3. 执行步骤

1. **契约解析**：读取契约/OpenAPI 文件，提取端点、方法、参数、响应结构、错误码、鉴权、限流全量字段。
2. **结构映射**：每端点一节——描述（一句话用途+适用场景）、参数表（名/类型/必填/约束/示例值）、请求示例、响应示例（成功+至少一种错误路径）。
3. **示例编写**：每端点至少一个可运行示例（含鉴权头、真实路径参数、边界值）；示例经实际执行验证后标记「已验证」。
4. **错误码全表**：汇总全部错误码（码/含义/触发条件/客户端处置建议），与契约逐条对账。
5. **门禁自检**：死链检查（文档内引用）、交叉引用校验、示例执行记录归档。
6. **对账交付**：输出契约-文档对账表（端点/参数/错误码三维核对），漂移项显式标注。

## 4. 输入规范

```yaml
contract: 契约文档路径 | OpenAPI 文件路径
auth: 鉴权方式与示例凭据（测试环境）
env: 示例执行环境（测试/沙箱）
scope: 全量 | 增量（变更端点）
```

## 5. 输出格式

```markdown
# [服务名] API 文档（版本/基准契约版本）
## 认证与调用约定
## 端点 [METHOD /path]
- 用途 / 适用场景
- 参数表
- 请求示例（已验证标记）
- 响应示例（成功 + 错误路径）
## 错误码全表
## 契约-文档对账表（漂移项标注）
## 门禁自检记录
```

## 6. 质量标准

- 端点覆盖率 100%（契约端点全部成文，缺一即 FAIL）
- 示例可执行率 100%（每端点 ≥ 1 个实际运行验证的示例）
- 错误码闭环 100%（契约错误码全表化，含触发条件与处置建议）
- 对账表零未解释漂移（差异项必须标注原因：文档滞后/契约变更未同步）

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 示例未执行验证禁止发布（红线） |
| RISK-02 | 契约变更后 24h 内同步，超时预警进 AEGIS 文档缺陷域 |
| RISK-03 | 文档与契约冲突时以契约为准，文档侧修正 |
| RISK-04 | 错误码表缺项（契约有而文档无）阻断准出 |
| RISK-05 | 示例中泄露真实凭据/生产数据（安全红线，示例用测试凭据） |

## 8. 跨角色协作接口

```yaml
上游角色:
  - 03-技术架构师: 提供 API 契约/OpenAPI 规范（唯一事实源）
  - 04-全栈开发: 提供实现侧行为确认（响应格式核对）
下游角色:
  - 06-测试专家: 接收文档门禁报告（与测试准出并联）

传递字段: [文档集, 示例集, 错误码全表, 对账表, 门禁报告]
```
