# 技能模块：fullstack_implementation

> 全栈需求开发，前后端 + 数据库 + 部署全链路代码实现。

## 1. 技能描述

本技能用于将「功能需求 + 架构方案 + API 契约」一站式落地为可交付代码资产，覆盖前端（React/Vue/Angular）、后端（Java/Go/Python/Node.js）、数据库（MySQL/Redis/Elasticsearch）以及部署说明全链路。强调工程规范一致性、API 契约严格对齐、单元测试同步生成与可部署性。

## 2. 触发条件

- 输入包含「功能开发」「编码实现」「全栈开发」「接口开发」等关键词
- 已存在架构方案与 API 契约文档（前置依赖）
- 技术栈明确（前端框架 + 后端语言 + 数据库选型）
- 模块类型已标注（核心模块 / 普通模块）

## 3. 执行步骤

1. **确认场景**：识别 B 端业务系统 / C 端高并发 / AI 智能体 / 传统 Web / 小程序，匹配对应技术栈与规范集。
2. **解读架构方案**：严格遵循分层架构、API 契约、领域模型，记录架构落地疑问并反馈给架构师。
3. **设计数据模型**：输出数据库表结构、索引设计、缓存 Key 规范、ES 索引映射；复杂业务域先落 DDD 战术模式（聚合边界/实体/值对象/领域事件/仓储接口）再映射表结构（成文对齐 `TPL-DDD.md` 详细设计与 `TPL-DBDD.md` 数据库设计）。
4. **接口实现**：按 API 契约实现接口，参数校验、统一异常处理、统一返回结构。
5. **前端实现**：按页面原型实现 UI，对接接口，处理加载/错误/空态，性能优化（懒加载、SSR、虚拟列表）；组件边界遵循架构分层。
6. **同步生成单元测试**：调用 `unit_test_generator` 技能，核心模块 100% 覆盖。
7. **本地自测**：接口联调、性能基线达成、规范校验通过。
8. **可观测性内建**：结构化日志（统一字段：trace_id/用户/耗时）、trace 跨层传播（W3C traceparent 透传）、关键业务指标埋点（口径对齐角色 08 指标字典）。
9. **输出开发说明**：接口文档、部署说明、依赖说明、配置说明、回滚预案；跨边界接口同步契约测试（见技能 `contract-testing`）。

## 6. 质量标准

- 严格遵循阿里巴巴 Java 开发手册 / Google 编程风格
- 代码可扩展、可复用，单一职责，注释清晰
- 核心模块单元测试覆盖率 100%，普通模块 ≥ 80%
- 接口响应时间、QPS 达成预设基线
- 所有接口符合 API 契约规范，无契约漂移
- 提交前 Hook 通过 ESLint / Checkstyle / SonarQube 校验

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 编码前必须确认架构方案与 API 契约，禁止跳过 |
| RISK-02 | 核心模块未达 100% 覆盖率禁止提测 |
| RISK-03 | 数据库表结构变更必须经 DBA 评审 |
| RISK-04 | 禁止硬编码密钥、密码、Token，必须走配置中心 |
| RISK-05 | 引入新依赖必须通过兼容性与安全扫描 |
| RISK-06 | 性能基线未达成禁止合入主干 |

| RISK-07 | AI 生成代码未过 CR-RULES 评审门槛（`.standards/code-review/RULES.md` P0/P1 项） | 禁止交付 |
| RISK-08 | 跨边界接口无契约验证（技能 contract-testing） | 禁止合并 |

## 9. 场景检查清单（角色卡 §3.2 清单承诺实体）

> 命中「AI/智能体/大模型」或「C 端/高并发」或 B 端场景时按节执行；每项判通过/未通过/不适用（不适用须附理由）。

### 9.1 B 端业务系统（6 项）
| # | 检查项 | 通过判据 |
|---|--------|----------|
| B1 | 权限模型 | RBAC 到行/字段级，越权路径有默认拒绝 |
| B2 | 审计日志 | 关键写操作留操作者/时间/前后值 |
| B3 | 列表深分页 | 大表用游标分页，OFFSET 上限有保护 |
| B4 | 并发编辑冲突 | 乐观锁版本号或等价机制 |
| B5 | 导入导出 | 异步化+行数上限+失败行可下载 |
| B6 | 文案国际化 | 无硬编码文案（键值对管理） |

### 9.2 C 端高并发（8 项）
| # | 检查项 | 通过判据 |
|---|--------|----------|
| H1 | 缓存穿透 | 空值缓存或布隆过滤器二选一 |
| H2 | 缓存击穿 | 热点 key 互斥重建或逻辑过期 |
| H3 | 缓存雪崩 | TTL 打散+多级兜底 |
| H4 | 热点数据 | 热点 key 有本地缓存/打散方案 |
| H5 | 多层限流 | 接口/用户/IP 至少两层，超限返回降级内容 |
| H6 | 异步削峰 | 削峰路径有队列缓冲与积压预案 |
| H7 | 柔性降级 | 核心链路依赖故障时可用性预案 |
| H8 | 压测依据 | 上线前有压测报告（目标 QPS/实测/瓶颈） |

### 9.3 AI 应用（8 项）
| # | 检查项 | 通过判据 |
|---|--------|----------|
| AI1 | 流式输出 | 断线可续传（游标/序号） |
| AI2 | 注入防护 | 用户输入不直接拼接系统指令（有隔离层） |
| AI3 | 输出校验 | 模型输出过 schema 校验，失败有重试/兜底 |
| AI4 | 成本熔断 | 单会话/单用户 token 预算与熔断 |
| AI5 | 评测回归 | 提示词/模型变更跑评测集（对照基线） |
| AI6 | 会话状态 | 外置存储（多实例可恢复） |
| AI7 | 模型降级 | 主模型不可用有 fallback |
| AI8 | 成本打点 | 每请求成本/延迟可观测（对齐 08 口径） |
