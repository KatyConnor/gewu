# 技能模块：architecture_decision_records

> 轻量架构决策记录（ADR）：六字段决策卡 + superseded 链式失效 + AETC 留痕接线。架构级决策无 ADR 不编码。

## 1. 技能描述

本技能提供架构决策的轻量留痕方法：每个架构级决策（技术选型/结构选择/权衡取舍）落为一张决策卡，六字段（编号/状态/背景/决策/替代方案/后果），状态链 proposed→accepted→superseded（失效只链不删）。配套两条体系接线：①**AETC 留痕**——accepted 决策必须写入留痕（架构决策是留痕域最高价值对象）；②**角色 12 文档同步**——ADR 是增量记录，架构级成文仍走 TPL-ARC，重大决策变更通知 12 对账。轻量原则：单卡一页以内，超出说明决策该拆。

## 2. 触发条件

- 输入包含「架构决策」「ADR」「技术选型决策」「决策变更」等关键词
- 架构级选型/结构/权衡决策点（system-design-doc 流程内的选型环节）
- 既有决策被推翻（superseded 流程）

## 3. 执行步骤

1. **决策点识别**：区分架构级决策（影响结构/边界/依赖，须 ADR）与实现级决策（归 04，不留 ADR）。
2. **决策卡起草**：六字段——编号（ADR-NNN）/状态/背景（问题与约束）/决策（选定方案）/替代方案（≥2 个含放弃理由）/后果（收益**与代价**，代价必须写对冲措施）。
3. **替代方案完整性校验**：少于 2 个替代方案或无放弃理由 → 退回补充。
4. **后果代价对冲校验**：只写好处的决策卡不合格——每项收益须对照代价与对冲（性能↑→复杂度↑→对冲：隔离在 X 层）。
5. **状态流转**：proposed（评审中）→ accepted（生效，触发留痕）→ superseded（被 ADR-NNN 替代，原卡保留并加链接）。
6. **留痕与同步**：accepted 后写入 AETC 留痕；涉及成文契约/对外接口的决策，通知角色 12 更新对账。

## 4. 输入规范

```yaml
decision_point: 决策点描述（选型/结构/权衡）
constraints: 约束条件（成本/合规/团队能力/工期）
candidates: 备选方案清单（≥2）
existing_adrs: 既有 ADR 索引（查重与 superseded 判定）
```

## 5. 输出格式

```markdown
# ADR-NNN：[决策标题]
状态：proposed | accepted | superseded by ADR-MMM
## 背景（问题/约束/触发）
## 决策（选定方案与理由）
## 替代方案（≥2，各含放弃理由）
## 后果（收益/代价/对冲措施）
## 留痕与同步记录（AETC 编号/12 通知）
```

## 6. 质量标准

- 架构级决策 100% 有 ADR（无 ADR 的架构级决策禁止进入编码）
- 替代方案 100% ≥2 个且含放弃理由
- 后果 100% 含代价与对冲（单边收益卡不合格）
- superseded 100% 链式保留（零物理删除）
- accepted 决策 100% 留痕（AETC）

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 口头/聊天记录里的架构决策直接落地 = 违规（无卡不编码） |
| RISK-02 | superseded 卡被删除或断链 = 决策历史失证 |
| RISK-03 | 决策卡超过 1 页 = 决策该拆分，强制拆卡 |
| RISK-04 | 后果无代价对冲 = 单边论证，退回 |
| RISK-05 | 实现级决策强行升格 ADR = 噪声污染决策索引 |

## 8. 跨角色协作接口

```yaml
上游角色:
  - 02-产品经理: 提供决策背景的约束输入
  - 03-本角色system-design-doc: 选型环节触发决策卡
下游角色:
  - 04-全栈开发: 以 accepted ADR 为实现依据
  - 12-技术写作: 接收重大决策变更通知（TPL-ARC 成文对账）
  - AETC留痕域: 接收 accepted 决策留痕
  - OPS运维域: 接收架构债登记（代价项的技术债部分）
传递字段: [决策卡, 决策索引, superseded链, 留痕记录]
```
