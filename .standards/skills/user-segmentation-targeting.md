# 技能模块：user_segmentation_targeting

> RFM×生命周期分层、触达渠道矩阵、频控预算三分配，活动 SOP 五段式——触达以"不打扰"为第一约束。

## 1. 技能描述

本技能负责用户分层与触达策略的完整设计：分层模型（RFM 近度/频度/额度 × 生命周期 新客/活跃/沉默/流失预警/流失）选型与阈值定义 → 触达矩阵（渠道×分层×内容类型×时段）→ 频控预算（单用户日上限/单渠道频次/免打扰时段）→ 活动执行 SOP。纪律：触达方案必须过频控预算表与 07 合规送审后才可执行；分层数据不出域、名单最小化。

## 2. 触发条件

- 输入包含「用户分层」「RFM」「触达」「频控」「召回」「运营活动」等关键词
- 存在可用的用户行为数据窗口与渠道授权清单
- 活动策划需求或分层迁移监控告警

## 3. 执行步骤

1. **分层模型选型**：按业务形态选型（电商类 RFM 权重高/内容类生命周期权重高），定义阈值与刷新周期。
2. **分层计算**：产出分层分布与迁移矩阵（层间净流动），标记异常迁移（如活跃→沉默加速）。
3. **触达矩阵设计**：每分层×渠道×内容类型×时段的触达意图（激活/召回/转化/关怀），标注免打扰约束。
4. **频控预算分配**：单用户单日触达上限 → 渠道级频次 → 活动级预算扣减；例外须 07 会签。
5. **活动 SOP 五段式**：目标（指标+反向指标）→ 分层与机制 → 预案（超频/客诉激增熔断）→ 执行协同（04/09）→ 复盘归档。
6. **合规送审与执行**：新渠道/新频控参数送 07；大流量事件报备 09（提前 72h）。

## 4. 输入规范

```yaml
behavior_data: 数据窗口与口径版本
model: {type: RFM|lifecycle|hybrid, thresholds, refresh_cycle}
channels: [{name, authorized, caps}]
campaign: {goal, primary_metric, guard_metrics, window}
```

## 5. 输出格式

```markdown
# 分层与触达方案（版本/数据窗口）
## 分层分布与迁移矩阵
## 触达矩阵（分层×渠道×内容×时段）
## 频控预算表（上限/扣减/例外登记）
## 活动 SOP（五段式）
## 合规送审与容量报备记录
## 反向指标监控清单
```

## 6. 质量标准

- 分层阈值 100% 登记版本与刷新周期
- 触达矩阵 100% 含频控预算与免打扰约束
- 活动 100% 有反向指标（投诉/退订/卸载）监控与熔断预案
- 触达名单 100% 最小化（按分层最小集合）
- 送审/报备记录 100% 在场（执行前）

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 超频控触达直接阻断（任何理由，例外须 07 会签登记） |
| RISK-02 | 分层数据跨域流转禁止（隐私红线） |
| RISK-03 | 无熔断预案的活动禁止执行（客诉激增场景） |
| RISK-04 | 未授权渠道禁止入矩阵 |
| RISK-05 | 召回性价比连续两轮低于阈值须重新分层（策略失效信号） |
