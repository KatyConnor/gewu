# 技能模块：user_manual_authoring

> Diátaxis 四象限定型 + 任务导向结构：面向最终用户的交付级文档，每篇对应一个用户任务。

## 1. 技能描述

> 成文模板：`.standards/templates/TPL-UM.md`（用户手册）与 `.standards/templates/TPL-RN.md`（发布说明）；版式走技能 `document-visual-design`。

本技能将 02 产品经理的 PRD 转化为面向最终用户的文档集（手册/帮助中心/FAQ/新手引导/发布说明）。方法论核心：**Diátaxis 四象限定型**（教程-学习/指南-任务/参考-查阅/解说-理解，每篇文档必须且只能归属一象限）、**任务导向结构**（指南类每篇解决一个用户任务，禁止功能罗列式写法）、**术语一致**（全库走术语表单一真源）。所有步骤类内容必须通过可复现性自查。

## 2. 触发条件

- 输入包含「用户手册」「帮助文档」「FAQ」「新手引导」「发布说明」等关键词
- 存在明确的功能范围（PRD 或功能清单）与产品版本目标
- 新功能上线、版本发布、或用户反馈文档问题

## 3. 执行步骤

1. **PRD 解析**：提取功能清单、用户角色、核心任务、价值主张。
2. **Diátaxis 定型**：逐篇判定象限归属——新手任务流→教程；具体任务操作→指南；查阅面→参考；原理阐述→解说。混合内容拆分归档。
3. **结构设计**：指南类按「任务前提→步骤→验证→故障排查」四段式；教程类按线性任务流（一步不漏）；参考类按查阅场景组织（非功能罗列）。
4. **撰写与术语校验**：全库术语走术语表；新术语先入表后使用。
5. **可复现性自查**：按文档实际走一遍核心任务路径，记录偏差并修正。
6. **交付**：手册集 + 术语表增量 + 发布说明草稿（新功能/变更/破坏性变更三段）。

## 4. 输入规范

```yaml
prd: PRD 路径
audience: 终端用户画像（角色/技能水平）
tasks_core: 核心用户任务清单（可复现性自查范围）
terms: 术语表基线路径
version: 目标产品版本
```

## 5. 输出格式

```markdown
# [文档标题]
> Diátaxis 定型：[教程|指南|参考|解说] | 版本 | 受众
[任务前提（指南/教程类）]
[正文]
[验证方法 | 故障排查（指南/教程类）]
[术语引用 | 版本声明]
```

## 6. 质量标准

- 核心用户任务覆盖率 100%（PRD 任务清单全映射）
- Diátaxis 定型声明 100% 在场（无定型=未完成）
- 可复现性自查记录在场（核心路径全走过）
- 术语一致率 ≥ 98%（私造同义术语视为缺陷）
- 发布说明含破坏性变更段（版本兼容义务）

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 功能罗列式结构（无任务前提）退回重写 |
| RISK-02 | 未走可复现自查的步骤类内容禁止发布 |
| RISK-03 | 版本声明缺失或滞后（幽灵文档）阻断发布 |
| RISK-04 | 术语表外私造术语强制归一 |
| RISK-05 | 教程与指南混编（一篇文档双象限）强制拆分 |

## 8. 跨角色协作接口

```yaml
上游角色:
  - 02-产品经理: 提供 PRD、功能范围、用户旅程
  - 11-交互与体验设计师: 提供界面方案（截图与操作路径依据）
下游角色:
  - 06-测试专家: 接收文档准出材料
  - 09-SRE专家: 接收发布说明终版

```
