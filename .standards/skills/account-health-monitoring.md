# 技能模块：account_health_monitoring

> 健康分四维（采纳/关系/支持/商务）×三层预警（绿/黄/红）×干预 SOP 映射。红级 48h 响应是硬约束。

## 1. 技能描述

本技能负责具名客户账户的健康度体系运维：四维健康分计算与口径治理 → 三层预警分级 → 干预 SOP 匹配执行 → 复检闭环。健康分数据源由 08 数据基座供给（指标设计层归 08，本技能是**运营使用层**，与 13 漏斗诊断同规）；干预动作库覆盖培训补强、采纳活动、高层拜访、方案复盘；红级账户强制 48h 内启动干预，连续两个复检周期未改善升级 02/高层。系统性缺陷（多客户同因）必须转 AEGIS 缺陷单。

## 2. 触发条件

- 输入包含「健康度」「健康分」「流失预警」「客户分层」「QBR」「红级」等关键词
- 周期性健康度巡检或预警触发
- 大客户 QBR 筹备

## 3. 执行步骤

1. **数据核对**：四维数据源与口径版本核对（与 08 字典对齐）。
2. **健康分计算**：四维加权（采纳/关系/支持/商务——权重按业务形态登记版本）。
3. **分层分级**：绿/黄/红三层；黄=单维度恶化（30 天改善窗口）；红=流失风险（立即干预）。
4. **干预 SOP 匹配**：黄级→培训/采纳活动（协同 13）；红级→挽回动作包（高层拜访/方案复盘/商务协同）。
5. **复检闭环**：30 天复检，升/降级判定留痕；连续两周期未改善升级。
6. **多客户同因识别**：同一根因波及 ≥3 账户转 AEGIS 缺陷单（类 ODC 同因聚类规则）。

## 4. 输入规范

```yaml
data_sources: {adoption: 使用数据口径, relationship: 关系数据, support: 工单数据, commercial: 账期}
weights: 四维权重（版本登记）
thresholds: {green, yellow, red}
accounts_scope: 全量 | 指定分层（KA/腰部/长尾）
review_cycle: 巡检周期
```

## 5. 输出格式

```markdown
# 账户健康度报告（周期/口径版本）
## 健康分总览（分层分布/环比迁移）
## 预警清单（黄/红账户+归因维度）
## 干预记录（SOP 匹配/执行状态）
## 复检结果（升/降级判定）
## 升级单与 AEGIS 缺陷单（多客户同因）
```

## 6. 质量标准

- 健康分四维 100% 有数据来源与口径版本
- 红级账户 100% 在 48h 内启动干预（留痕）
- 复检 100% 有升/降级判定（禁止"干预了没结论"）
- 多客户同因（≥3 账户）100% 转 AEGIS
- QBR 材料 100% 含健康度趋势与价值证据

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 红级 48h 未响应判为流程违规（升级 02） |
| RISK-02 | 口径变更未登记即计算 = 数据违规 |
| RISK-03 | 干预无复检 = 开环动作（不计入完成） |
| RISK-04 | 单联系人账户强制黄级预警（关键人单点） |
| RISK-05 | NPS 深访不达样本量禁止趋势结论 |
