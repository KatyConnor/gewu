## 一、形态判据速查（规范 vs 技能 vs 混合）

| 判据 | 规范 | 技能 |
|---|---|---|
| 语义（义务论/工具论） | 应/不应/许可（deontic） | 如何做得更好（instrumental） |
| 强制（机制分离，Saltzer-Schroeder） | 违规可拦截：门禁/护栏/CI，运行在模型权限之外 | 提示词层影响意图，模型可选择不遵循 |
| 后果（失败成本） | 违反即危害（不可逆/外溢）→ fail-closed | 违反仅次优（上限损失） |
| 知识形态（Polanyi/SECI） | 显性约束：规则文本+schema+check | 隐性经验外化：触发描述+范例+踩坑 |
| 分发机制 | 装载生效/产物时机门禁 | 意图检索匹配（description 触发） |

**助动词测试（ISO/IEC Directives Part 2 / GB/T 1.1）**：
- 条款能写成 **应/不应** 且能写出验证方法 → 规范条款（requirement 必须 verifiable）
- 只能写成 **宜** → 指南/技能素材（recommendation）
- 写不出验证方法的"应" → 伪需求，退回重写或降格

**三条硬结论**：
1. 需要违规可拦截的 → 必须规范+门禁；靠提示词自律的一律是技能/意图层。
2. 规范管合规率下限，技能管一次通过率上限——同一域完整治理 = 两者配套（AEGIS 三层防线实证）。
3. 骨架强制 + 技巧多解 → **混合形态**：域流程规范 + 配套技能池（SDLC 实证）。

**元技能**：规范的生产知识（如何写规范/打包/校验）永远走技能（spec-pack 技能族），
产出物的运行约束走规范——生产与运行两层互不混淆。

## 二、层级判据速查（全局 vs 项目）

| 判据 | 全局级 | 项目级 |
|---|---|---|
| 变化频率（PMBOK OPA） | 组织级不变量，跨项目不动 | 仓库/产品变量，随项目走 |
| 绑定对象 | Agent 身份/组织律法 | 运行时目录（.lpu/.aegis）/工具链/令牌/冻结清单 |
| 失败半径 | 跨项目系统性风险 | 单项目交付风险 |
| 裁剪方向（CMMI） | 不可放松 | 只可收紧（单向棘轮） |

- 决策放能承担其后果的最低层（辅助性原则）：只影响本仓库 → 项目级；外溢多项目 → 全局级。
- 双层模式是常态：全局装"律法内核"，项目装"实施外壳"。
- 技能同理：工艺/调研/元技能 → 全局；项目专属技能（绑定特定项目与工具链）→ 项目级。

## 三、接入类型映射（类型模型五型）

| 类型 | 触发机制 | 互斥关系 | 实例 |
|---|---|---|---|
| 横切·常驻 | 装载即生效 | 无互斥 | AETC |
| 横切·条件激活 | 配置存在性 | 无互斥 | ATLAS |
| 任务型·互斥 | 意图词路由 | 互斥组内五方 | LPU/LR/OPS/SDLC/AEGIS |
| 任务型·响应式·叠加约束 | 任务内容词族+文件在场 | 可与任务型并存 | UI/CODING |
| 质量门型 | 产物时机 | 门禁语义 | CR、**META（治理产物门）** |

判型时以触发面起问：靠装载/靠配置/靠意图词/靠产物时机？
接入流程五步：注册表加行 → 触发矩阵加节 → 平台适配重派生 → suite_check 清单扩充 → 校验全绿发布。

## 四、判型七步 checklist（决策流程）

```
S1 内容定性     —— 约束/流程/经验/检查器？预期强制强度？
S2 形态判据     —— §一 五判据逐条对照（危害/强制/后果/知识形态/分发）
S3 形态结论     —— spec / skill / hybrid
S4 层级判据     —— §二 三判据（不变量/绑定/失败半径）
S5 接入类型     —— §三 类型模型五型（查触发矩阵找同类先例）
S6 生命周期     —— 晋升观察项 / 例外频次预算 / 复用频次埋点
S7 记录归档     —— 填 templates/form-classification-record.yaml → 过 meta_check.py
```

**仲裁优先序（判据冲突时）**：危害 > 强制 > 后果 > 形态 > 分发。
效率与分发便利性永远不敌危害与强制判据。

## 五、生命周期规则（晋升与降级）

- **晋升（技能→规范）触发条件**（满足其一即启动判型复审）：
  1. 该经验关联的违规已造成实际危害事件 ≥1 次；
  2. 复用频次达阈值（同一技能在 ≥3 个项目被调用）且违反形态可判定；
  3. 团队出现 ≥2 次对同一问题的不一致处理。
- **校准/降级（规范→指南）信号**：条款例外申请频次持续超标
  （AEGIS §3.3 原则：例外频次过高说明默认值需校准，而不是放宽铁律——
  先校准参数，参数校准无效再降格为指南，禁止静默删除）。
- **层级迁移**：不变量显性化后项目→全局（只能收紧）；全局内容出现项目特有分支 →
  拆双层而非全局放宽。
- 一切升降级走 S7 记录归档，记录表 `lifecycle` 节为必填。

## 六、常见误判对照（反模式库，持续扩充）

| 误判 | 症状 | 后果 | 纠正 |
|---|---|---|---|
| 红线做成提示词 | 安全约束写在技能/系统提示词里 | 违规无法拦截，合规率无下限 | 升格规范+门禁（危害判据一票） |
| 品味做成硬门禁 | 把视觉/文风偏好写成 BLOCK 级检查 | 门禁误报率高，审批疲劳 | 降格指南/技能（多解判据） |
| 全局装变量 | 工具链配置写进全局 AGENTS.md | 项目间互相污染 | 拆双层：全局红线+项目实施 |
| 项目定律法 | 安全红线只在某项目 rules 里 | 其他项目裸奔 | 不变量上收全局层 |
| 生产知识当运行约束 | 把"怎么写规范"的知识写成规范条款 | 规范内容自指膨胀 | 归位元技能（spec-pack 族） |
| 骨架技巧不分 | 域流程整体做成技能或整体做成规范 | 上限牺牲或下限失守 | 混合形态：流程规范+技能池 |
