## 二、判型结论摘要

- **形态分布**：spec ×10 · hybrid ×3（SDLC/AEGIS/UCSS/UTSS 中 4 例混合形态——
  混合 = 域流程规范 + 技能池/引擎/技能本体配套；META 判据 §3.4 的体系内实证从 2 例增至 4 例）
- **层级分布**：13/13 双层——组织不变量上收全局（铁律/红线/协议契约），
  仓库变量下放项目（运行时目录/工具链/令牌/清单），单向棘轮只收紧
- **互斥组**：六方（理解/重构/运维/开发/修复/**测试**）——V1.7 扩第六方
- **质量门**：三域（评审 CR / 扫描 UCSS / 治理 META）+ 准出段门禁（AEGIS 三道门、UTSS G0-G3）
- **技能面直装能力**：UCSS（.standards/ucss/→~/.zcode/skills/code-scan）与 UTSS
  （.standards/utss/→~/.zcode/skills/utss）本体即 Agent Skills 技能，技能面零改写复用；
  SDLC（.standards/skills/ 池）、AEGIS（guard 引擎）为组件级技能/机制配套

## 三、按 META 五判据的划分依据（新两套实录）

**UCSS**：q1 危害=true（C/H 漏报放行）→ 必须机制层强制；q2 可校验=true
（SARIF 门禁 exit 2）→ 规范面成立；q3 多解=partial（五步法/语言模式库是
程序性知识）→ 技能面保留原生形态。**裁决：混合形态**——规范面承担门禁纪律
（第十二套，质量门型·扫描域，与 CR 并行双门+SARIF 去重互证 M0-M3），
技能面即本体（Agent Skills 开放标准，可直装技能目录）。

**UTSS**：q1 危害=true（准出失效=带缺陷发布；铁律5 不伪造=审计链）；
q2 可校验=true（coverage_gate exit 2 + 12 字段硬门禁）→ 规范面成立；
q3 多解=partial（用例设计方法库/AI 缺陷模式）→ 技能面保留。**裁决：混合形态**
——规范面为第十三套（任务型·互斥·测试域第六方，测试工作流 Step 0-9），
技能面即本体可直装。

**判型拒绝项（本包未拆出纯技能的内容）**：无——两套的强制核心
（门禁/铁律/协议）均通过 q1/q2 测试，若按纯技能集成将丢失机制层强制，
违反 META 形态判据第 2 条（需要违规可拦截的必须规范+门禁）。

## 四、存量追溯判型说明

十一套存量规范按 META 七步追溯判型（记录 `decided_by` 标注 retro-classification）。
追溯结论与既有类型模型（TRIGGER-MATRIX V1.0-V1.5 五轮判型）完全一致，
无形态翻转——差异仅在粒度：META 记录补充了 lifecycle 节（晋升观察/
例外预算/降级信号），使每套规范首次具备可度量的生命周期元数据。
SDLC 与 AEGIS 在 META 判据下显式识别为**混合形态**（此前类型模型
未单独标注技能面/机制面配套）。

## 五、标准接入指引（Agent 消费面）

1. 项目级接入：装 `03_规范本体/` 平铺至项目根 → `.standards/suite_check.py` 校验 →
   按注册表触发面由调度器路由（本清单 §一 即路由元数据）
2. 技能目录直装（技能面）：`cp -r 03_规范本体/ucss ~/.zcode/skills/code-scan`
   / `cp -r 03_规范本体/utss ~/.zcode/skills/utss`（Claude Code 同理）
3. 全局级接入：不变量条款（铁律/红线/门禁默认值）进全局入口，
   实施变量（工具链/令牌/清单）留项目——各记录 `level_tests` 节为划分依据
4. CI 门禁：ucss_gate.py（SARIF）/ coverage_gate.py（覆盖率）直接挂流水线
5. 第十四套起：新治理内容接入必走 META 判型门（本清单是其产出物形态的样板）
