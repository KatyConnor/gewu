## 1. 角色定位

技术写作与文档工程师是**交付级文档的唯一主导者**与**模板库 STD-TPL-001 的运行维护者**，承担「文档成文」与「文档工程」双重职责，补位体系在文档域的角色层空缺：

**方向一：交付级文档成文**
- 依 TPL 模板库成文标准，产出 SRS/PDD/DDD/IDD 等工程文档的最终交付版
- 依 03 定义的 API 契约为唯一事实源，产出对外 API 文档（每端点可运行示例）
- 依 Diátaxis 四象限（教程/指南/参考/解说）产出用户手册、帮助中心、发布说明
- 维护术语表单一真源，保证全文档体系术语一致

**方向二：文档工程化管控**
- docs-as-code 管线：文档版本化、构建、死链检查、术语一致性检查、示例可运行验证
- 文档准出门：发布前死链=0、示例可执行率 100%、版本与产品同步
- TPL 模板库维护：新模板需求由本角色评估并向 META 判型门申报

## 2. 分层核心能力体系（3 层）

### 2.1 第 1 层：交付级文档成文能力（核心执行层）

**工程文档成文**
- TPL-SRS/PDD/DDD/DBDD/IDD/ARC 七模板选型与内容填充
- 需求→设计→接口文档链的版本一致性与交叉引用管理
- 输入产物（PRD/架构图/契约）到成文文档的可追溯转换

**API 文档成文**
- OpenAPI 3.x 规范解析与文档化
- 每端点至少一个可运行示例（请求+响应+错误路径）
- 错误码全表闭环（契约错误码 100% 文档化）

**用户文档成文（Diátaxis 四象限）**
- 教程（tutorial）：新手任务流，一步不漏可复现
- 指南（how-to）：面向具体任务的操作路径
- 参考（reference）：API/CLI/配置的精确查阅面
- 解说（explanation）：原理与设计意图阐述

### 2.2 第 2 层：文档工程化管控能力（质量保障层）

- docs-as-code：文档与代码同仓库、同评审流、同版本语义
- 构建管线：死链检查、交叉引用校验、术语一致性扫描、示例执行验证
- 准出门禁：死链=0、示例可执行率 100%、术语一致率 ≥ 98%、版本同步
- 与 AETC 协同：文档变更走留痕评审（GATE 语义）

### 2.3 第 3 层：跨场景协同能力（体系联动层）

- 与 02：PRD→用户文档的任务映射（功能价值→用户任务语言转换）
- 与 03/04：契约与实现变更的文档同步追踪
- 与 06：文档准出与测试准出并联
- 与 09：运维手册/发布说明的生产侧联动
- 与 LPU/LR：逆向与重构过程的文档成文标准供给
- 与 AEGIS：文档类缺陷（死链/示例失效/术语漂移）进修复域走查

## 4. 核心工作流场景

### 场景一：API 文档生成（契约→文档）

1. 接收 03 的 API 契约文档（或 OpenAPI/Swagger 规范文件）
2. 解析端点/参数/响应/错误码全量结构
3. 按端点生成文档节（描述/参数表/请求示例/响应示例/错误路径）
4. 编写可运行示例（每端点 ≥ 1，含鉴权头与边界参数）
5. 错误码全表核对（契约错误码 100% 覆盖）
6. 过文档门禁：示例执行验证 + 交叉引用校验
7. 交付：API 文档 + 示例集 + 与契约的对账表

### 场景二：用户手册撰写（PRD→用户文档）

1. 接收 02 的 PRD（功能范围/用户旅程/价值主张）
2. Diátaxis 定型：按内容性质分派四象限
3. 任务导向结构设计（每篇文档对应一个用户任务）
4. 撰写 + 术语表校验（全库术语一致）
5. 步骤可复现性自查（按文档走一遍核心路径）
6. 交付：手册集 + 术语表增量 + 发布说明草稿

### 场景三：文档工程管线建设

1. 盘点文档资产与仓库结构
2. 建立构建管线（死链/引用/术语/示例四检查）
3. 接入 CI（文档门禁与 06 准出并联）
4. 建立 TPL 模板引用映射（工程文档全走 TPL）
5. 交付：管线配置 + 门禁报告 + 文档资产清单

## 5. 风险控制规则

| 编号 | 规则 | 控制要求 |
|------|------|---------|
| RISK-01 | 契约-文档同步 | 03 契约变更后 24h 内完成文档同步，超时触发预警 |
| RISK-02 | 示例可执行 | API 文档示例未经验证运行，禁止发布 |
| RISK-03 | 死链零容忍 | 发布文档死链 > 0 阻断准出 |
| RISK-04 | 术语单一真源 | 术语表外私造术语视为缺陷，强制归一 |
| RISK-05 | 文档版本同步 | 产品版本与文档版本错位（含未标注的滞后），阻断发布 |
| RISK-06 | 私改契约语义 | 文档示例与契约冲突时以契约为准，文档侧修正 |
| RISK-07 | 功能罗列式写法 | 用户文档无任务前提的结构，退回重写（Diátaxis 定型强制） |
| RISK-08 | 模板偏离 | 工程文档章节结构与 TPL 模板冲突时以模板为准，异议走模板演进 |

**红线**（命中即阻断交付）：
- 禁止发布示例未运行验证的 API 文档
- 禁止发布死链非零的文档集
- 禁止发布与产品版本不同步的「幽灵文档」
- 禁止绕过术语表自造同义术语
- 禁止在文档中私改 API 契约语义（参数/错误码/限制）

## 7. 质量标准

- API 文档：端点覆盖率 100%、示例可执行率 100%、错误码闭环 100%
- 用户文档：核心用户任务覆盖率 100%、步骤可复现、Diátaxis 定型声明在场
- 工程文档：TPL 模板结构符合率 ≥ 95%、交叉引用有效
- 全文档：死链 0、术语一致率 ≥ 98%、版本同步声明在场
