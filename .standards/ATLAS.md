# 智能体执行留痕与人机协同平台对接规则（ATLAS）

  项目级：本文件与 .standards/atlas/ 目录一起复制到项目根目录

你是受《智能体执行留痕与人机协同平台规范》（ATLAS V1.0）约束的工程 Agent。
当本项目对接 ATLAS 平台时，你的全部执行留痕、人工决策与指令执行
必须经由三条通道与平台协同：**事件上行、决策回路、指令下行**。

## 一、触发面（条件激活）

| 条件（满足其一即生效） | 说明 |
|---|---|
| 项目根存在 `atlas/config.yaml` | 对接已配置，通道即生效，横切本项目一切 Agent 工作 |
| 用户指令要求对接 ATLAS / 接入留痕平台 / 上报平台 | 先复制模板生成根级 `atlas/config.yaml` 再进入对接状态 |

未对接平台的项目：本规范静默待命（不推送、不阻塞），AETC 本地留痕义务照常履行。

## 二、四条设计原则（任何取舍以此为准）

1. **全量可溯**：变更、决策、指令三者必须能通过 ID 互链追溯，无解释不了的孤岛。
2. **最小打断**：只有 D2 及以上决策点阻塞等待人工，D1 仅呈报不等待。
3. **闭环必需**：每张决策工单必须有结果与执行证据，每条指令必须有回执；
   悬空待办与丢失回执视作对接事故。
4. **平台单向可信**：平台是留痕的唯一事实源；两侧数据不一致时以平台账本为准，
   以哈希链校验裁决。本地缓存允许丢失，平台数据不允许丢失。

## 三、三通道职责速查

| 通道 | 方向 | 语义 | Agent 侧职责 |
|---|---|---|---|
| 事件上行 | Agent→平台 | 单向异步 | Trail Adapter：订阅本地留痕→转 TraceEvent→脱敏→哈希签名→WAL 缓存→批量推送 |
| 决策回路 | 双向同步 | 上报-挂起-领取 | 回路客户端：D2/D3 决策点上报工单、挂起长轮询领取决议、回传执行结果 |
| 指令下行 | 双向异步 | 领取-执行-回执 | 回路客户端：领取指令→四要素校验→执行→回执（拒绝也必须回执） |

所有连接一律由 Agent 侧发起出站请求（HTTPS），平台永不主动连接 Agent。

## 四、决策点分级（D0–D3）

| 级别 | 名称 | 触发条件示例 | 呈报与阻塞 | 审批人 |
|---|---|---|---|---|
| D0 | 免审 | 只读操作、沙箱试探、方案草稿 | 仅 L3 留痕，不呈报 | 无 |
| D1 | 事后审计 | 常规代码修改、单文件新增、文档变更 | ChangeReport 呈报，不阻塞 | 事后查阅 |
| D2 | 事前确认 | 跨文件重构、删文件、依赖变更、schema 迁移、推送远端 | 呈报+决策工单，Agent 挂起 | 单人 |
| D3 | 强审批 | 生产操作、对外发送、数据删除、付费调用、安全配置变更 | 呈报+决策工单，Agent 挂起 | 双人（四眼原则） |

- 各团队可在默认值上**收紧但不得放宽**。
- TTL 耗尽无人处理 → 工单 EXPIRED，Agent 按**默认拒绝**处理并回滚。
- `RESUMED` 之后必须回传执行结果才能 `CLOSED`；工单不允许从 PENDING 直接消失。

## 五、指令下行白名单与四要素校验

白名单五类：`task.dispatch`（派发任务）/ `task.cancel` / `task.rerun` / `policy.update` /
`decision.clarify`。白名单外类型一律拒绝执行。

每条指令执行前本地校验四要素，任一不通过拒绝执行并立即回执拒绝原因：
1. 类型在白名单内；2. scope 与当前授权项目匹配；3. 未过有效期（默认 60 分钟）；
4. 平台签名可验证。

校验逻辑不可绕过、不可配置关闭。指令不是审批的捷径：指令派发的任务触发
D2/D3 决策点时照常进入决策回路，两者正交。

## 六、与其他规范的协作

| 规范 | 协作关系 |
|---|---|
| AETC | 层次分界：AETC 本地账本照写，ATLAS 旁路汇聚（Trail Adapter 订阅 AETC 留痕转推平台） |
| AEGIS | AEGIS 审批门 GATE 映射本规范 D 级决策工单；修复全程事件按 TraceEvent 上报 |
| OPS | OPS 事件处置状态可选同步平台；E5 审批执行可走 D 级工单 |
| LR / SDLC | D2/D3 决策点（跨文件重构、依赖变更等）上报工单等待人工 |
