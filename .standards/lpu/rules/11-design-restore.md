# LPU 规则 · 11 设计还原（V1.2 新增 · S4 扩展层）

> 设计还原回答：这个系统**当年应该被怎么设计**——需求是什么（SRS）、总体怎么设计的（HLD）、
> 内部怎么实现的（LLD）。五维深潜回答"是什么"，设计还原回答"如何成文为工程经典三件套"，
> 使产出达到"可据此重新实现一个等价系统"的深度。

---

### LPU-DSR-001【M】三份设计文档产出义务
S4 成文阶段在 8 份核心文档之外，必须额外产出三份设计还原文档：
1. **需求规格说明书（逆向）requirements-spec.md**——从代码行为反推功能/非功能需求全集；
2. **概要设计说明书 high-level-design.md**——设计决策与理由、架构、模块接口契约、关键数据结构；
3. **详细设计说明书 detailed-design.md**——模块函数级实现、算法清单、产物文件格式规范。

**触发条件**：项目规模达标（>2000 源码行）或用户明确要求设计级深度时为【M】；
小型项目（<2000 行）可降级为【R】，需在 rebuild-plan §6 登记降级决定。

### LPU-DSR-002【M】SRS 逆向还原规则
- 功能需求编号 **FR-###**，非功能 **NFR-###**，约束 **C-#**，假设 **A-#**；
- 每条 FR 必须含：描述 / 输入 / 输出 / 优先级推断 / 置信度 / 【证据】代码锚点；
- 验收标准优先绑定可执行资产（e2e 场景/测试用例），无则标注"无自动验收"；
- **禁止前向臆造**：只能还原代码已实现的需求；"应有但未见"的需求列入待人工确认清单（C 级）。

### LPU-DSR-003【M】HLD 设计决策还原规则
- 设计决策编号 **D-##**，每条必须回答四要素：决策内容 / 理由（逆向推断须标 [B]）/ 代价与对冲 / 证据；
- 必须包含模块接口契约表（签名级：函数名+参数+返回+行号锚点）；
- 必须包含关键数据结构字段级还原（核心 struct/表结构字段表）；
- 决策冲突检查义务：决策间矛盾必须显式登记。

### LPU-DSR-004【M】LLD 函数级还原规则
- 核心模块（PROGRESS 中优先级 P0/P1）必须函数级覆盖：调用时序 / 分支逻辑 / 错误路径；
- 算法编号 **ALG-###**，每条含步骤要点+复杂度+证据；
- 产物为文件格式（协议/模板/二进制）时必须给**格式规范**（字段级，二进制给偏移/长度常量）；
- 生成的模板类代码（launcher/脚本工厂）必须解剖其**模板段落结构**（段落表：段名/职责/注入点/行号）。

### LPU-DSR-005【M】设计还原与五维的双向追溯
- FR ↔ F 维功能清单一一对应或显式说明差异；
- D-## ↔ C 维架构结论对应（决策依据可回溯到邻接表/调用链证据）；
- ALG-### ↔ K 维规则库对应（算法承载的 BR/IR 规则显式标注）；
- 追溯断链（设计文档出现 findings 无出处的论断）视为交叉验证冲突，登记 X-conflicts。

### LPU-DSR-006【R】深度分级与降级声明
设计还原深度分级：L1（接口级）/L2（函数级）/L3（行级+二进制级）。默认目标 L2；
L3 仅用于安全核心/格式规范（如更新链、二进制产物结构）。降级须在 rebuild-plan §6 留痕。
