# LPU 规则 · 05 功能维深潜（S2 · DIV-F）

> 功能维回答：这个系统对外提供了哪些能力、每个能力从哪里进来。
> 功能维是"用户视角"的映射——重构范围确认（哪些功能保留/合并/下线）的依据。

---

### LPU-DIV-F-001【M】功能清单还原
以 RCN-003 入口清单为基础，合并归类为用户可理解的功能（不是接口清单）：
`功能名 / 功能类型（页面|API|定时|消息|批处理） / 入口集 / 所属模块 / 证据`。
命名用业务语言（"订单导出"），不用技术语言（"ExcelController.download"）。

### LPU-DIV-F-002【M】功能-入口映射表
每个功能与其全部入口建立映射（一个功能常对应多个入口：页面按钮 + API + 定时任务各一份）。
反向检查：每个入口必须归入某功能。**归不进去的入口是"孤儿功能"**，单独登记（疑似废弃功能，S3 复核）。

### LPU-DIV-F-003【M】API 文档还原（自动化程度高的部分优先）
对每个 HTTP 接口登记：`方法+路径 / 入参（含隐式参数如 header、session 字段）/ 出参结构 /
副作用（写哪些表、发什么消息）/ 鉴权方式 / 证据位置`。
- 入参出参以代码中的绑定对象为准，**不以命名猜测**；
- 副作用标注尤其重要：重构时"看似只读实际有写"的接口是事故高发区。

### LPU-DIV-F-004【R】页面/路由地图
有前端的项目还原页面地图：`路由 / 页面名 / 调用的 API 集 / 谁能访问（权限标识）`。
JSP/模板渲染型项目记录模板路径与渲染入口的映射。

### LPU-DIV-F-005【M】鉴权与权限模型还原
还原"谁能做什么"：会话/令牌机制、角色/权限的存储表、校验拦截点（过滤器/中间件位置）、
硬编码的权限判断。权限模型是重构中不能破坏的安全基线，必须单独成节进入 features-api.md。

### LPU-DIV-F-006【R】配置驱动的功能开关
识别配置开关（properties/yaml/数据库配置表）控制的功能分支：`开关名 / 取值含义 / 控制的功能 / 证据`。
开关交织的功能在成文时必须注明"受 XX 开关控制"，避免重构时误删分支。

### LPU-DIV-F-007【O】外部触达渠道盘点
短信/邮件/推送/webhook 等出站触达的模板与触发条件盘点——它们是业务流程（P 维）的末端节点，
也是用户可感知的功能边界。
