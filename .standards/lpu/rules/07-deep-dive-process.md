# LPU 规则 · 07 流程维深潜（S2 · DIV-P）

> 流程维回答：业务在系统里如何流转。流程 = 状态随事件的迁移 + 参与者 + 时序。
> 流程维是五维的收官维度：它把 C/D/F/K 的碎片串成叙事。

---

### LPU-DIV-P-001【M】核心状态机还原
对每个带状态语义的核心实体（订单/工单/会员等）还原完整状态机：
- 状态全集：承接 DIV-D-004（数据库枚举）与 DIV-K（代码枚举）的并集，两源不一致处登记冲突；
- 迁移事件全集：`状态A → 状态B / 触发事件（用户操作|定时|消息|管理员） / 代码位置 / 守卫条件`；
- 输出 Mermaid stateDiagram 到 findings。

**状态机还原后立即做完整性自检**：每个非终态必须有出边；发现"进入后无法离开"的状态，
要么是分析遗漏，要么是业务死路——两者都要显式记录。

### LPU-DIV-P-002【M】主业务流程编排
还原 3-5 条主流程（用户视角叙事 + 时序图文本）：
`参与者（用户/系统/外部系统）→ 步骤序列 → 每步的代码锚点`。
主流程选取：入口流量最大的功能、涉及金额的功能、涉及外部协同的功能优先。

### LPU-DIV-P-003【R】异常与补偿流程
挖掘主流程的"暗面"：失败重试、人工干预入口（管理后台的改单/重置按钮）、
对账/冲正逻辑、超时兜底任务。异常流程在重构中最易被遗漏，单独成节。

### LPU-DIV-P-004【M】跨系统交互时序
对每个外部系统（支付/物流/短信网关/内部兄弟系统）还原交互时序：
`本系统动作 → 外部系统响应 → 本系统处理分支（成功/失败/超时各走哪）`。
**超时分支的处理方式（轮询?回调?人工?）是集成重构的关键约束，必须显式回答。**

### LPU-DIV-P-005【R】周期性业务节奏
还原系统的"生物钟"：日终批处理、月度结算、定时对账、缓存刷新周期。
以"时间表 + 干了什么 + 代码锚点"形式登记。周期任务之间的依赖顺序（谁必须先跑完）必须标注。

### LPU-DIV-P-006【O】业务日历与峰值
从注释/配置/数据分布推断业务高峰机制（大促开关、限流配置、历史遗留的"XX活动"代码）。
这些是容量规划与重构灰度设计的输入。
