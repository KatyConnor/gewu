# 等级体系与门禁（references/severity-gates.md）

## §1 五级等级定义（UCSS 第 7 章）

| 等级 | CVSS v3.1 | 定义 | 典型示例 |
|---|---|---|---|
| Critical | 9.0~10.0 | 可直接远程利用、核心数据泄露/系统失陷、无需交互 | SQL 注入、RCE、反序列化、SSTI、上传 getshell、硬编码生产密钥、CVSS≥9 依赖 |
| High | 7.0~8.9 | 利用需一定条件/权限，或重大可靠性故障 | 存储型 XSS、SSRF、越权、弱加密、路径穿越、XXE、主路径 NPE/资源泄漏 |
| Medium | 4.0~6.9 | 利用条件受限或影响可控 | 反射 XSS、CSRF、开放重定向、信息泄露、TOCTOU、异常吞噬、Medium CVE |
| Low | 0.1~3.9 | 纵深防御缺失、影响轻微 | 缺安全头、风格问题、Low CVE、注释缺失 |
| Info | — | 建议项 | 格式、重复代码、复杂度超软限 |

### 等级修正因子（基线 ± 一级；Critical 不降至 Medium 以下）

| 因子 | 方向 | 条件 |
|---|---|---|
| 可达性 | ↓一级 | Sink 所在接口未在任何路由/入口暴露 |
| 暴露面 | ↓一级 | 仅内网/管理后台可达（需证据） |
| 数据敏感度 | ↑一级 | 涉及 PII/金融/健康数据 |
| 利用链组合 | ↑一级 | 可与其他问题组合成完整利用链 |
| 补偿控制 | ↓一级 | WAF/网关鉴权明确覆盖（须记录控制点） |

调整必须注明：`severity: High（基线 Critical，内网专用接口，降一级）`。

## §2 门禁阈值

| 门禁 | 默认阻断条件 |
|---|---|
| 提交门禁（pre-commit / IDE） | 新增 Critical/High（C1/C2）= 0；密钥扫描命中 = 0 |
| 合并门禁（MR/PR CI） | 新增 Critical/High/Medium（C1）= 0；CWE Top25 命中 = 0；复杂度硬限超限 = 0 |
| 发布门禁 | 存量 Critical = 0；High ≤ 项目基线且无逾期修复单；SBOM 已生成；SCA 无 Critical CVE |
| 例外 | 所有豁免须带工单号 + 有效期（≤90 天），到期自动恢复阻断 |

## §3 置信度分级

| 级别 | 定义 | 门禁参与 | 处置 |
|---|---|---|---|
| C1 确定 | 完整污点链/确定性证据 | ✔ | 直接计入门禁 |
| C2 很可能 | 路径存在但个别传播点未验证 | ✔ | 计入门禁，可申诉（提供反证后撤销） |
| C3 可能 | 模式匹配、无数据流佐证 | ✘ | 待确认清单，72h 内复核 |

## §4 修复 SLA

| 等级 | 响应时限 | 修复时限 | 逾期动作 |
|---|---|---|---|
| Critical | 4h | 24~48h | 冻结发布、升级到安全负责人 |
| High | 1d | 7d | 通知负责人、纳入紧急迭代 |
| Medium | 3d | 30d | 纳入版本计划 |
| Low | 7d | 90d | 季度批量清理 |
| Info | — | 下个迭代 | — |

## §5 缺陷密度度量（ISO/IEC 5055 对齐）

报告需输出四类密度（每 KLOC）：
`security_density` / `reliability_density` / `performance_density` / `maintainability_density`

参考基线（成熟团队）：安全 ≤0.1、可靠 ≤0.5、可维护 ≤3.0（可按团队校准）。

## §6 报告可信度自评模板

```
扫描限制：
- 未执行：[工具/语言未覆盖项]
- C3 待复核：N 项（列出编号）
- 未覆盖路径：[如：未构建运行的模板/脚本]
```
