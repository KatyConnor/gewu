# AEGIS-RULES.md — 智能体代码问题修复作业细则（AEGIS V1.0）

> 本文件是《智能体代码问题修复方法与标准规范》（AEGIS V1.0）的 Agent 侧作业细则，
> 入口文件 `.standards/AEGIS.md` 触达后按本细则执行。规范 PDF 定本见
> `01_规范文档/智能体代码问题修复方法与标准规范AEGIS-V1.0.pdf`。
> 三单模板见本目录 `templates/`；修复护栏引擎（aegis_guard.py）见本目录 `guard/`。
> 核心立场：**规范执行不依赖模型自觉，依赖架构**——护栏的拒绝决定合规率下限，
> 模型的自觉只决定一次通过率（效率）。

## 一、八条修复铁律（L1–L8，任何情况下不可违反）

| # | 铁律 | 违反形态 |
|---|---|---|
| L1 | 边界律：修复只限当前问题单的根因范围 | 夹带重构、顺手优化、无关文件 |
| L2 | 根因律：先证明根因，再动手修复 | 只修症状（吞异常/加 try/注释代码/调日志级别） |
| L3 | 测试神圣律：测试文件只读 | 改断言/删用例/降预期迁就代码 |
| L4 | 声明律：实际 diff 不得超出方案单声明 | 计划外文件、超预算变更 |
| L5 | 红绿基线律：无红基线不得实施，无绿证据不得申报完成 | 未复现即修、无验证即报 |
| L6 | 单一职责律：一单一根因一提交一 PR | 混合承载、多根因打捆 |
| L7 | 可回滚律：修复须原子提交、可独立 revert | 揉进其他提交、不可逆变更 |
| L8 | 知情披露律：超范围/失败/不确定/衍生问题即时上报 | 静默处理、瞒报 |

**铁律冲突优先序**：安全底线（L8）> 正确性（L5）> 边界约束（L1/L3/L4/L6/L7）> 效率。
**铁律不可关闭**：可配置的只有一次性例外的审批门槛；每次例外必须留痕
（触发铁律、审批人、理由、影响面）并进入反哺循环。问题位于冻结文件时唯一合法路径：
停止实施 → 产出方案单 → GATE 审批获一次性修改授权 → 先解除限制再修复，禁止先改后补票。

## 二、问题定级与准入（S0–S4）

| 级别 | 判据 | 预算（文件/行/函数/依赖） | 处置时限 |
|---|---|---|---|
| S4 | 可利用安全漏洞、数据损坏路径、生产不可用 | 按分派预案 | 立即（含缓解） |
| S3 | 主功能不可用/关键降级、高危漏洞 | 3 / ±60 / 3 / 禁止 | 24 小时内 |
| S2 | 次功能不可用/高危告警 | 5 / ±150 / 6 / 审批后至多一项 | 3 个工作日 |
| S1 | 轻微功能缺陷/中危 | 8 / ±300 / 10 / 审批后至多一项 | 两周内 |
| S0 | 轻微/外观/文档 | 8 / ±300 / 10 / 审批后至多一项 | 排期 |

- 预算护栏：达 90% 告警，100% 停止写入；超预算处置=强制拆单或 GATE 审批（S3/S4 强制拆单）。
- 安全类映射 CWE/SCA 记录 CVE；按 IEEE 1044 两维法归入「类型 × 原因」。
- **V1.1 双轴定级（IEEE 1044 全量适用）**：S0–S4 是修复成本刻度（预算/时限由它定）；
  **severity（对用户的影响）× priority（业务修复紧迫）**是业务影响刻度，两者独立登记、
  severity 决定验证强度（Sev1 必须 e2e 级回归），priority 决定排期。禁止用 priority 高
  掩盖 severity 低而跳过回归（跳级须 GATE 审批留痕）。
- **准入五查**（不通过则拒绝接单）：单据完整（复现/环境/期望）· 非重复（查同类在修）·
  根因可定位（不可定位转 LPU）· 非架构级（架构级转 LR 立项）· 预算可容纳（不可容纳须先拆单）。

## 三、七阶段作业流程（P0–P6）

| 阶段 | 动作 | 强制产出 | 权限 |
|---|---|---|---|
| P0 接单与定级 | 核验单据、查重、S+双轴定级、排程；**批量受理时先拆单** | 问题登记（逐单） | 读 |
| P1 定位（只读锁） | 根因链追问（三问链）、复现红基线 | **根因单 RC** | 只读 |
| P2 方案设计 | 变更清单/预算/验证计划/回滚预案 | **方案单 FP** | 读 |
| P3 实施（沙箱） | 预算内最小修改、护栏拦截违规写入 | 变更 diff | 沙箱写（隔离分支+工具白名单） |
| P4 验证 | 三层验证门、安灯判定 | **验证单 VR** | 读 |
| P5 合入 | PR 通道、CI 与评审把门 | 提交（fix(范围): [单号] 根因一句话） | PR 合入（禁主干直推） |
| P6 复盘与反哺 | 教训条目入库、度量回写 | 教训条目 | 读 |

**权限阶梯**：Agent 永远不持有主干直推、git push 强推、历史改写三类权限（工具层禁用）。

**P1 根因定位方法论工具箱（V1.1）**——按 Zeller《Why Programs Fail》科学方法循环执行：
假设（可证伪陈述）→实验（最小干预）→观察→修正假设，循环至根因可证；每轮假设登记入 RC 链。
工具按情境选用：git bisect（回归类，变更优先）/ 差异最小化 delta 思想（输入相关类）/
日志与调用链追踪（运行时类）/ 覆盖谱统计思想（测试相关类：先看失败与通过用例的覆盖差）。
陌生代码域（无 LPU 产出且 >2 文件涉及）→ 先走 LPU 按需理解（SEQ-004 按需模式）再回 P1，
禁止在无理解基底的代码上连续盲改（两轮假设失败即触发安灯，见 §七）。
**方案变更**：实施中发现方案前提不成立 → 回 P2 重做方案单，禁止边改边设计。

## 三A、生命周期状态机（V1.1 强制）

```
new → triaged → in_progress → fixed → verified → closed
                                   ↑         ↑
                       （实施合入后）  （三道门通过+回归证据后才能前移）
```
- **fixed ≠ verified ≠ closed 三态强制分离**：fixed 仅为代码合入态；verified 需 VR 单
  三道门证据+红转绿+回归选择集通过；closed 需 ODC 定类完成+复盘条目入库。
- 回退规则：任何一态发现新证据（回归失败/衍生问题）→ 退回 in_progress 并登记衍生单。
- 无回归证据不得 close（铁律级，与 L5"无绿证据不得申报完成"同构）。

## 三B、批量受理与拆单（V1.1）

- **受理层允许批量**：输入可为缺陷清单/扫描报告/评审问题集（≥2 单）；
- **处理层强制逐单**：登记时必须拆为独立问题单（一单一编号一登记行），
  每单独立走 P0–P6 与三单契约；禁止一张 RC/FP/VR 覆盖多个根因（L1 单据驱动律的 V1.1 细化）。
- 批量场景的公共部分（同环境复现/同模块影响面）可引用共享证据块，但每单仍须引用指针+独立根因结论。

## 三C、热修旁路与回填义务（V1.1，S4/生产事故专用）

- **旁路条件（三者同时满足）**：S4 级（数据损坏/生产不可用）+ OPS R3 应急通道已获批 +
  阻断缓解方案与根治方案可分离。此时 D4 方案单可压缩为"缓解措施+风险声明"先行实施。
- **回填义务（不可免除）**：热修合入后 24 小时内补齐完整 RC/FP/VR 三单（根因可延至
  72 小时，须在热修提交信息中声明 deadline）；VR 必须含根治验证，热修不等于关闭。
- **反常态化护栏**：热修单占比 >10%（滚动 30 天）触发度量告警，安灯升级人工审视流程漏洞。

## 四、红绿基线法（L5 的落地）

1. 修前复现失败（红）：测试断言失败/扫描器命中/运行时异常，固化可重放的证据；
2. 修后通过（绿）：同一判据复跑通过，红绿证据归档于验证单；
3. 安全类无法构造运行时复现时的等价证据：原扫描器命中（红）→ 修复后复扫未命中且零新增（绿）；
   等价证据替换必须在方案单中声明，防止借机绕过验证。

## 五、三单结构化契约（P1/P2/P4 强制产出）

三单=根因单 RC、方案单 FP、验证单 VR。YAML 格式、schema 校验，**不合 schema 视同阶段未完成**。
模板见 `templates/{RC,FP,VR}-template.yaml`（字段与护栏引擎 `.standards/aegis/guard/aegis_guard.py docs` 命令
校验的 schema 一致）。P4 门一自动执行实际 diff 与 FP 声明的比对，计划外文件出现即触发 L4/L8 违例处置。

## 六、三层防线与冻结清单

**三层防线**：提示词层（守则注入八条）管意图、运行时护栏管行为、CI 门禁管结果；
全部关键约束同时落在防线二与防线三的机器规则里。

**默认冻结清单**（触碰即拦截，例外走 GATE 审批留痕；安全凭证类一律禁止）：

| 类别 | 示例 | 处置 |
|---|---|---|
| CI/CD 配置 | .github/workflows、Jenkinsfile、.gitlab-ci.yml | 触碰即拦截，修改走 GATE 例外 |
| 依赖清单 | package.json、requirements.txt、pom.xml | 变更必审，联动决策序 |
| 测试资产 | 既有测试文件、快照、基线 | 修改须经测试缺陷认定（双人） |
| 安全与凭证 | 密钥、证书、鉴权配置、安全策略 | 一律禁止触碰 |
| 基础设施与数据 | IaC 脚本、数据库迁移脚本 | 触碰即拦截，必审 |
| 其他 Agent 产物 | 其他智能体会话产生的代码 | 禁止修改（防套娃），转人工协调 |

**测试缺陷认定**：声明测试本身有误须走正式流程（双人审批），提交《测试缺陷认定单》；
护栏可自动比对"改测试迁就代码"与红基线证据的冲突。

## 七、三层验证门与安灯升级

- 门一静态一致性：lint 零新增告警 + 实际 diff ⊆ FP 声明 + 预算未超限。
- 门二定向验证：红用例转绿 + 受影响模块测试全过。
- 门三回归选择集：基于影响分析选出的回归子集（理论上与全量回归等价）全过；
  冒烟层必须全过，扩展层可异步补充；默认 20 分钟超时分层。
- **安全类专项准出四条**：复扫闭环（原告警关闭+零新增）· 无新弱点（不得引入新 CWE）·
  缓解有效（须附证据）· 误杀检查（合法业务流不破坏）。
- **有界重试与安灯**：验证失败至多重试两轮，回 P1 必须提出新根因假设（禁止无新假设的盲目重试）；
  连续两轮失败触发**安灯升级**——停止一切修改、输出升级说明（已尝试方案/失败证据/怀疑方向/需要的资源）、
  转人工接管。停线优先于带病继续。
- **部分修复**：根因为设计缺陷无法单点收敛时，产出部分修复+遗留问题单，禁止自行扩大范围。

## 八、准出检查单（DoD，10 条，仅第 9 条人工项）

1. 红绿基线归档可追溯；2. 三道门通过且记录完整；3. diff 在 FP 声明范围内；
4. 预算未超限；5. 冻结清单零触碰或有审批例外；6. 原子提交可独立 revert；
7. PR 强制字段完整（单号/根因/影响面/证据/回滚）；8. 安全项复扫通过零新增；
9. 复盘完成、教训条目入库；10. 全程留痕事件按 ATLAS 上报完整（平台对账）。

提交规范：`fix(范围): [问题单号] 根因一句话`；一个 PR 只承载一个修复单，混合承载直接驳回。

## 九、守则注入（系统提示层，第 2、3、4、8 条不可删减）

1. 只处理当前问题单，级别 S?；2. 未取得红基线前禁止写第一行修复代码；
3. 测试文件只读，修改预期须《测试缺陷认定单》并等批准；4. 冻结清单禁止触碰，命中即停上报不绕行；
5. 遵守变更预算，达 90% 立即收尾；6. 每阶段产出对应三单，schema 不过视阶段未完成；
7. 同一问题连续 2 轮验证失败即停止，输出升级说明转人工；8. 任何超范围/不确定/新发现问题即时披露。

（引擎生成器：`python3 .standards/aegis/guard/integration/aegis_agent/promptpack.py` 可按单据参数定制注入文本）

## 十、度量与反哺

| 指标 | 定义 | 目标 |
|---|---|---|
| 新缺陷引入率 | 合入后 30 天内新缺陷的修复单占比 | <5%（北极星） |
| 一次通过率 | P4 三道门一次通过占比 | ≥70%（试点 60%） |
| 发散指数 | 触发预算/范围拦截的修复单占比 | <10% |
| 测试篡改成功数 | 未授权测试修改进入主干 | 0（红线） |
| 安灯升级率 | 触发安灯的修复单占比 | 监控（不设上限） |

**ODC 正交缺陷分类（V1.1，P6 关闭前强制）**：每单关闭时按修复者视角定 defect type 十类——
赋值/检查/算法/时序/接口/功能/文档/构建/环境/回退；同因聚类（同 defect type+同模块≥3 单）
触发过程反馈：喂 LR（缺陷密度入 rebuild-plan 优先级）与 OPS（慢性升级候选）。
**首轮校准义务**：十类对 Agent 代码的适配在首批实跑中校准类别定义，禁止静态空转。

教训反哺：复盘教训条目回流避错记忆/技能库/判例库；同一铁律例外申请频次过高
说明定级/预算/冻结默认值需校准，而不是放宽铁律。

## 十一、护栏引擎（防线二/三的可运行实现）

```bash
python3 .standards/aegis/guard/aegis_guard.py demo                          # 双场景演示（场景一 BLOCK / 场景二 PASS）
git diff main...fix-branch | python3 .standards/aegis/guard/aegis_guard.py check - --plan docs/FP-003.yaml --level S2
python3 .standards/aegis/guard/aegis_guard.py docs --rc … --fp … --vr …     # 三单契约校验
```

退出码 0=PASS 1=BLOCK 2=仅警告 3=配置错误——即 CI 门禁的接线方式
（`.standards/aegis/guard/integration/ci/aegis-gate.yml`、`integration/hooks/pre-commit`）。
检查器与规范条款的映射表见 `.standards/aegis/guard/README.md`（DOC_SCHEMA/L5_REDLINE/FROZEN_TOUCH/
ASSERT_REMOVED/TEST_SKIPPED/TEST_TOUCHED/AP001–AP00x 反模式族/BUDGET/PLAN_DEVIATION）。

MCP 智能体集成：`.standards/aegis/guard/integration/mcp_server.py`（把 guard 暴露为 MCP 工具）；
阶段控制器与受护工具：`integration/aegis_agent/`（stage_controller.py / guarded_tools.py）。
