# S5 发布部署阶段规则（05-release.md）

阶段目标：以受控、可回退的方式把验证通过的版本交付到目标环境。
phase 值：release
本阶段整体属于 R3 高危区。

## Agent 职责边界
- 应做：发布清单（checklist）编制、发布脚本准备、回滚预案先行、
  发布步骤编排与留痕、发布后冒烟验证。
- 禁止：无回滚预案申请发布；直接操作生产环境（除非人工明确授权且全程 R3 流程）；
  发布中静默忽略告警；一次性发布多个无关变更。

## 必检点（G5 发布审批前逐项确认）
1. 回滚预案完整：触发条件、回滚步骤、预计耗时、数据回滚方式。
2. 发布清单逐项可勾选，每项有执行人（agent/human）标注。
3. 版本号、变更集、依赖清单、配置变更三件套齐备且与 G4 报告一致。
4. 发布窗口与相关方通知安排已确认。
5. 冒烟验证用例已定义（发布后立即执行的最小验证集）。

## 留痕要求
- 发布前强制检查点（CKP-002 强制场景），CHECKPOINT 记录回滚目标。
- 每个发布步骤一条 STEP_DONE；G5 审批单归档 audit/reviews/。
- 生产环境操作每步 RISK_PRE → 执行 → RISK_POST。
- 发布结果（成功/失败/中止）在 TASK_CLOSE 前以 RISK_POST 汇总。

## 审批门 G5（发布审批，R3）
- 请求时机：必检点全绿。
- 内容：变更摘要、影响面、回滚预案、验证结果、发布窗口。
- 通过标准：授权发布人 approved；任何一项必检缺失即不得请求。

## 常见风险与回退
- 发布失败：立即执行回滚预案（RLB 五步法），回滚本身留痕。
- 部分成功：冻结现场→评估（继续修复 or 回退）→人工决策，Agent 不得自行续发。
- 数据迁移类变更：必须有前向兼容期设计，禁止一步切换。
