# S4 测试验证阶段规则（04-testing.md）

阶段目标：以可复现的证据证明实现满足验收标准。
phase 值：testing

## Agent 职责边界
- 应做：测试计划（映射验收标准）、用例设计与执行、失败分析、修复建议、
  回归执行、测试报告撰写。
- 禁止：为让测试通过而修改断言/放宽验收标准（发现测试本身错误须走 CORRECTION）；
  选择性执行用例；掩盖失败结果。

## 必检点（G4 前逐项确认）
1. 验收标准 → 用例映射表完整（每条标准至少一个用例）。
2. 全量用例执行结果如实记录（含跳过用例及原因）。
3. 失败用例全部有分析：缺陷定位/环境问题/用例缺陷，分类清楚。
4. 缺陷修复后回归执行，且新增回归用例防复发。
5. 测试环境与差异已声明（数据、依赖版本、配置）。

## 留痕要求
- 测试执行结果作为 STEP_DONE 记录：命令、范围、通过率。
- 缺陷分析用 BLOCKED（阻塞实现）或 CORRECTION（测试修正）记录。
- 修复动作按 S3 规则走（修复既有代码=R2）。

## 审批门 G4（测试通过）
- 请求时机：用例全部执行、失败项闭环。
- 内容：通过率、未通过项与风险豁免说明、报告路径。
- 任何关键用例失败不得申请通过；豁免须人工明确批准并记录理由。

## 常见风险与回退
- 环境性失败：重跑前先留痕（避免静默重试，铁律5）。
- 回归失败：恢复到 G3 时检查点，按缺陷修复流程处理。
