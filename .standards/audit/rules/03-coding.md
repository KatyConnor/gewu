# S3 编码实现阶段规则（03-coding.md）

阶段目标：按设计基线以最小正确变更实现功能，全过程可追溯、可回退。
phase 值：coding

## Agent 职责边界
- 应做：先读后改（理解上下文再动手）、按计划步骤实施、单元测试随代码提交、
  自审（可结合《代码审查规则规范体系》）、持续留痕。
- 禁止：先斩后奏式重构；一次变更跨多个无关目标；跳过测试直接交付；
  未经 GATE 执行 R2/R3 操作。

## 必检点（G3 编码自审前逐项确认）
1. 每个文件修改都有对应计划步骤与 STEP_DONE 记录。
2. 变更最小性：diff 中无与目标无关的改动。
3. 新增依赖已评估并在 RISK_PRE 中列明（安装依赖=R2）。
4. 单元测试覆盖新增逻辑，测试随代码一起提交。
5. 无 TODO/FIXME 遗留未记录（有则列入 TASK_CLOSE 遗留项）。
6. 代码风格符合项目既有规范（沿用项目 lint 配置）。

## 留痕要求
- 任务开始前创建检查点（CKP-002 推荐）。
- 每个计划步骤一条 STEP_DONE（含分析/技能/执行三段，TRC-005）。
- 重构动作单独 DECISION：动机、范围、验证方式。
- 修改既有代码一律 R2 流程；纯新增文件 R1。
- 执行测试命令属于 R0/R1（写入 detail），失败的测试必须 BLOCKED 记录。

## 审批门 G3（编码自审）
- 请求时机：计划步骤全部完成、自检清单全绿。
- 内容：变更摘要、测试结果、检查点ID、自审发现与处理。
- 通过后进入 S4 正式测试。

## 常见风险与回退
- 实现走偏：以最近检查点为基准回退，CORRECTION 记录偏差原因。
- 依赖冲突：恢复依赖文件检查点，重新评估选型（回到 S2 决策点）。
- 半途而废的任务：TASK_CLOSE 未写前中断的，下次会话以 BLOCKED/CORRECTION 续接。
