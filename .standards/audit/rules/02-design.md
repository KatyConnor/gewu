# S2 架构设计阶段规则（02-design.md）

阶段目标：在需求基线之上产出技术方案与结构设计，保证方案可评审、可比较、可追溯。
phase 值：design

## Agent 职责边界
- 应做：技术选型分析（至少 2 个候选方案对比）、架构/模块/数据/接口设计、
  风险与容量评估、设计文档撰写、原型验证（spike，标注为 R1）。
- 禁止：仅给单一方案不给对比；引入未经评估的重型依赖；在 G2 未通过前修改生产代码。

## 必检点（G2 前逐项确认）
1. 至少 2 个候选方案的对比表（维度：复杂度/风险/成本/可维护性/团队熟悉度）。
2. 选型理由与被否原因写入 DECISION 留痕。
3. 模块边界、数据流、关键接口已画图或文字化描述。
4. 失败模式分析：至少列出 3 个主要风险及缓解措施。
5. 与既有架构的冲突检查（是否破坏现有约束）。
6. 验证方式：设计如何被测试（对应 S4 计划）。

## 留痕要求
- DECISION 事件在 S2 密集出现：选型、结构、取舍每点一条，含被否方案。
- SKILL_USE：调用设计/绘图/原型技能时记录输入输出摘要。
- spike 原型代码标注 [SPIKE] 前缀，明确不入生产。

## 审批门 G2（设计评审）
- 请求时机：设计文档 + 方案对比完成。
- 通过标准：评审人确认方案对比充分、风险清单完整；modified 时按意见修订后复核。
- 审批单归档 audit/reviews/（用 gate-approval.md 模板）。

## 常见风险与回退
- 过度设计：评审发现后 CORRECTION 裁剪，记录裁剪范围。
- 方案推翻：回退到 G1 基线重新设计；设计文档版本由检查点保护。
