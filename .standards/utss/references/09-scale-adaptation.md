# 09 项目规模裁剪指南（Scale Adaptation）

UTSS 的完整性靠全档位共用一套协议保证（不漏项），差异化靠裁剪表保证（不滥测）。
**裁剪 = 显式声明「本轮不做什么」，不是默默省略。** 测试计划必须声明档位并逐条给出裁剪理由。

## 1. 档位判定

| 判定维度 | A 原型/演示 | B 小型工具 | C 标准项目 | D 关键系统 |
|---|---|---|---|---|
| 用户面 | 自用/演示 | 团队内/CLI | 对外/生产 | 生产+资金/安全/合规 |
| 生命周期 | 一次性/短期 | 短期迭代 | 持续迭代 | 长期演进 |
| 失败代价 | 可容忍 | 低（可快速重发） | 中（用户受损） | 高（资损/违规/事故） |
| 合规要求 | 无 | 无 | 一般 | 有（等保/审计/行业监管） |

判定规则：取四维中的**最高档**（涉及资金 → 直接 D，即使只是内部工具）。
存疑时上调一档并告知用户。

## 3. 各档位最低可接受交付（不可再裁）

- **A 档**：冒烟记录 + 结论（PASS/FAIL）+ 「本档位未执行项」声明。
- **B 档**：以上 + 核心路径功能用例与执行记录 + 实测覆盖率数值。
- **C 档**：完整五件套（计划/用例/执行/缺陷/报告）+ 门禁评估表。
- **D 档**：C 档全部 + RCA 记录 + 残余风险清单（含右移监控建议）+ 符合性声明
  （references/01 第 5 节模板）。

## 4. 特殊场景裁剪

- **纯文档/配置变更**：档位不高于 B；重点 = 一致性核对（引用路径、版本号、生效条件）。
- **依赖升级**：回归范围 = 全量核心回归池（升级影响面不可枚举）+ 兼容性清单。
- **Bug 修复单独提测**：修复验证 + 影响面回归（可不含 S2），致命缺陷修复必须走 S3。
- **重构（行为不变）**：先建「特征测试网」（改造前先固化现状用例）再动手，否则按新功能测。
