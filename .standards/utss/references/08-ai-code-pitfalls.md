# 08 AI 生成代码的缺陷模式与针对性测试（AI Code Pitfalls）

AI 生成的代码有统计规律性的缺陷模式（2025-2026 多项研究一致结论：
AI 代码的逻辑/正确性问题显著高于人类基线，幻觉 API、占位实现高发）。
凡测试对象含 AI 生成代码（含本智能体自己写的），在常规流程之上**必须**执行本章清单。

## 1. 高发缺陷模式 → 针对性测试策略

| # | 缺陷模式 | 典型表现 | 针对性测试 |
|---|---|---|---|
| P1 | **幻觉 API / 不存在的方法** | 调用库中不存在的函数、参数签名错误、过期 API | 静态：编译/lint/类型检查全过（这是 T0 准入，不是可选）；动态：import 与首次调用路径全触发 |
| P2 | **占位实现 / 静默降级** | `# TODO`、空函数、`pass`、捕获异常后返回假成功、mock 数据残留 | grep 扫描 TODO/FIXME/pass/`NotImplemented`；断言真实数据流（给真实输入验证真实输出，防「假通道」） |
| P3 | **逻辑正确性缺陷** | 边界差一、条件反转、状态机遗漏、浮点精度 | BVA 三点法全覆盖 + 判定表全规则 + 状态迁移含非法迁移（references/03） |
| P4 | **异常路径质量差** | catch 里吞异常/返回错值、finally 遗漏、错误码与文档不符 | 逐个 catch 块审查：是否保留错误信息、是否假恢复；强制异常注入用例（依赖超时/断连/坏数据） |
| P5 | **并发与幂等缺陷** | 重复提交、竞态、锁范围错、重试风暴 | 幂等测试：同请求重放断言结果一致；并发用例：多协程/线程同时写同一资源 |
| P6 | **资源泄漏** | 未关闭的连接/文件/游标、无超时的请求、无界的缓存 | 压力循环（如 1000 次调用）后检查句柄数/内存/GC；全部外部资源走 with/defer/try-with 验证 |
| P7 | **契约漂移** | 接口实现与文档/前端期望不一致、字段名大小写、日期格式、时区 | schema 断言（类型/必填/枚举）；契约测试对照调用方期望；时间字段一律断言时区语义 |
| P8 | **测试作弊（AI 自测的高发问题）** | 为过测试而弱化断言、catch 里返回固定值让测试变绿、删测试、test-only 特殊分支 | **断言有效性抽查（强制）**：随机抽 ≥3 条测试，人审断言是否真的校验了行为；变异抽查：临时改坏实现一行，测试必须变红 |
| P9 | **需求误解（验证缺失）** | 每个函数都对但整体场景错 | 端到端场景确认用例（references/02 第 4 节）：完整用户旅程走一遍对业务结果断言 |
| P10 | **跨文件不一致** | 改了 A 处忘改 B 处（常量两处定义、新旧实现并存） | grep 关键常量/规则的全项目出现点核对一致性；影响面回归（Step 1 清单） |

## 2. AI 代码测试的三道强制检查（嵌入流程位置）

1. **T0 前静态门禁**：编译 + 类型检查 + lint + （如接入）UCSS 扫描零 error → 否则不提测
2. **S1 中断言有效性抽查**：按 P8 执行（防「测试全绿」假象）——**这是 AI 场景独有的必查项**，
   人类团队测试者会怀疑开发，智能体自测时最缺的就是这一步
3. **S3 后变异抽查**（C/D 档）：对 1-2 个核心函数做手工变异（改比较符/删一行/换返回值），
   对应测试必须失败——失败说明测试网真实有效

## 3. 生成测试代码时的额外要求

- 测试代码与产品代码**不得由同一提示一次生成后不验证**：先跑一遍确认测试真的在执行
  （人为埋一个错误断言看它红不红，再修正）。
- 禁止生成「永远通过」的结构性测试（如 assert True、空 try）。
- Mock 边界最小化：只 mock 外部 IO，禁止 mock 被测逻辑本身（mock 掉被测对象 = 测试空气）。
- 快照测试（snapshot）须抽查快照内容是否被无脑更新。

## 4. 残余风险披露

AI 代码即使通过全部测试，报告中「残余风险」必须包含一条固定披露：
「本交付含 AI 生成代码，已按 UTSS references/08 完成针对性检查（列出执行项），
未覆盖项：{列出}，建议上线后重点监控：{关联指标}。」
