# 06 质量度量与门禁阈值（Metrics & Quality Gates）

度量回答两个问题：「测够了吗」「质量够高了吗」。所有指标必须有数据来源，
禁止估计值进入门禁评估表。

## 1. 覆盖率门禁阈值（按档位）

| 档位 | 语句/行覆盖 | 分支覆盖 | 核心模块（高风险区） | 说明 |
|---|---|---|---|---|
| A 原型 | 不设硬阈值（报告实测值即可） | — | — | 但冒烟与主流程必须过 |
| B 小型 | ≥ 60% | 不强制 | ≥ 70% | |
| C 标准 | ≥ 70% | ≥ 60% | ≥ 80% | |
| D 关键 | ≥ 80% | ≥ 70% | ≥ 90%（核心算法/资金/安全逻辑推荐 MC/DC 思维） | |

- 覆盖率统计范围：本次变更涉及的代码（增量优先于全量——存量遗留代码可用排除清单声明）。
- **反指标操纵**：覆盖率是必要条件不是充分条件——断言为空的测试同样拉高覆盖率。
  抽查规则：覆盖率报告须伴随 ≥3 条单测样本检查断言有效性。
- 工具：`scripts/coverage_gate.py`（支持 pytest-cov / coverage.py / jest / go cover）。

## 2. 过程度量（测试过程健康度）

| 指标 | 定义 | 门禁/预警 |
|---|---|---|
| 用例执行率 | 已执行 / 计划执行 | 准出硬条件 = 100%（BLOCKED 单列并说明） |
| 用例通过率 | 通过 / 已执行 | S3 末 ≥ 档位阈值（B 90% / C 95% / D 98%），且致命全清 |
| 缺陷密度 | 缺陷数 / KLOC 或 / 变更点数 | 无绝对阈值，用于纵向对比与风险区识别 |
| 缺陷修复率 | 已关闭 / 已提出 | 准出 ≥ 95%，致命/严重 100% |
| 缺陷收敛比 | 本轮新发现 / 上轮新发现 | ≤ 20% 且趋势下降（references/05） |
| 回归通过率 | 回归通过 / 回归执行 | ≥ 97%（低于说明修复质量差，警惕「打地鼠」） |

## 3. 结果度量（交付质量信号）

- **缺陷逃逸率**（需要历史数据）：测试阶段后发现的缺陷 / 总缺陷。用于长期改进，不在单轮门禁内。
- **遗留缺陷画像**：数量 × 严重级分布 + 是否有绕行方案 + 用户确认记录。
- **残余风险清单**：PASS-WITH-RISK 的必填项——每条含：风险描述、触发条件、影响面、
  缓解措施（监控/回滚/限流）、责任归属。

## 4. 门禁评估表（Step 7 产出，写入测试报告）

```
| 门禁项 | 阈值 | 实测值 | 数据来源 | 判定 |
|---|---|---|---|---|
| 语句覆盖率(增量) | ≥70% | 76.3% | coverage_gate.py 输出 | ✅ |
| 分支覆盖率(核心模块) | ≥80% | 71.2% | 同上 | ❌ |
| 致命/严重缺陷 | 0 | 0 | defect-report 汇总 | ✅ |
| 用例执行率 | 100% | 100% (12 执行 + 3 阻塞已豁免) | test-cases 执行列 | ✅ |
| 回归通过率 | ≥97% | 100% | S3 记录 | ✅ |
```

任何一项 ❌ → 整体结论最高只能是 PASS-WITH-RISK，且该 ❌ 项必须进入残余风险清单。

## 5. 度量反模式（自我检查）

- ❌ 用用例数量衡量工作质量（写 500 条弱断言用例 ≠ 好测试）
- ❌ 只报全量覆盖率掩盖增量质量（新代码 40% 被存量 90% 稀释）
- ❌ 覆盖率达标即宣布质量达标（不管断言有效性与场景覆盖）
- ❌ 用「自动化率」替代「自动化有效性」（跑得起来的测试 ≠ 测得出来的测试）
