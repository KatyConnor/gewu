# 缺陷报告（Defect Report）——UTSS v1.1 模板

> 对应 ISO/IEC/IEEE 29119-3 事件报告；字段与生命周期见 references/07。
> 单条缺陷一个条目；项目内缺陷多时按严重级分区。

```markdown
# 缺陷清单：{项目/迭代名}

## 1. 汇总
| 严重级 | 提出 | 关闭 | 遗留（延期/豁免） |
|---|---|---|---|
| S1 致命 | {n} | {n} | {n} |
| S2 严重 | {n} | {n} | {n} |
| S3 一般 | {n} | {n} | {n} |
| S4 轻微 | {n} | {n} | {n} |

归类统计：{需求理解 x / 逻辑 y / 边界漏 z / 异常路径 w / 并发 v / 其他 u}

## 2. 缺陷明细

### DEF-{编号} {标题}
- **严重级**：S{1-4} ｜ **优先级**：P{0-3} ｜ **状态**：{新建/已确认/修复中/待验证/关闭/延期/拒绝}
- **环境**：{版本 / commit / 部署形态}
- **来源**：{用例 ID / 探索 Charter / 用户反馈}
- **复现步骤**：
  1. {步骤}
  2. {步骤}
- **实际结果**：{现象，附日志片段/截图证据}
- **预期结果**：{依据：需求条目/接口文档/常识}
- **复现概率**：{必现/偶现 n/m}
- **根因**：{修复时填，S2 以上必做 RCA，方法见 references/07 第 4 节}
- **修复版本**：{commit}
- **回归验证**：{原复现步骤重跑结果 + 影响面回归结果 + 用例 ID}

> 每条缺陷重复上述结构。

## 3. 遗留缺陷结论
| ID | 严重级 | 处理(延期/豁免) | 理由 | 用户确认 |
|---|---|---|---|---|

## 4. 预防建议（每轮 1-3 条）
- {依据归类统计，写进测试报告并对下轮生效}
```
