# 测试用例集（Test Cases）——UTSS v1.1 模板

> 用例编写前置：先完成需求与功能实现分析（测试项来自测试计划第 2 章），
> 按 references/03 选型路由选设计方法，再按下述字段逐条编写——**用例完备性检查通过
> （references/03 第 5 节清单）后才允许进入执行**。
> 执行记录：每条用例的「执行结果」区在执行当时填写；批次级执行计划与逐条记录、
> 结果汇总 → 独立文档 templates/test-execution.md（EXE 批次制）。

```markdown
# 测试用例集：{项目/迭代名}

## 1. 用例汇总
- 总数：{N}（P0:{a} / P1:{b} / P2:{c} / P3:{d}）
- 功能覆盖：{功能模块/测试项 → 用例 ID 对照，确保 100% 测试项有用例}
- 方法分布：{等价类 x / 边界值 y / 判定表 z / 场景法 w / 状态迁移 v / ...}
- 冒烟池：{P0 用例 ID 列表}
- 完备性检查：{通过日期/检查结论，未通过不得执行}

## 2. 用例明细（每条用例一个条目，字段不得缺省）

### TC-{编号} {用例标题：对象+动作+预期一句话}

| 字段 | 内容 |
|---|---|
| **所属功能/模块** | {功能模块名，对应测试计划测试项编号 T{n}} |
| **关联需求** | {需求条目/用户故事编号；变更类任务填 diff:{文件#行}} |
| **业务规则** | {被验证的业务规则原文或转述，注明出处；如「单日提现上限 5 万元，见需求 §4.2」} |
| **所属场景** | {业务场景/用户旅程：如「用户发起提现-正常出款」「并发重复提交」} |
| **优先级** | P{0-3} ｜ **类型**：{功能/边界/异常/并发/安全/兼容} ｜ **级别**：{单元/集成/系统} |
| **设计方法** | {BVA 三点法/判定表 R2/场景法异常流...} |
| **测试目标** | {一句话：本条用例要证明什么，如「金额=50000 边界值允许通过且落库正确」} |

**前置条件（环境状态）**：
- {系统/服务状态：如「用户 A 已实名且余额 10 万元」「服务已启动 v{commit}」}

**前置数据（准备清单）**：
| 数据项 | 值/规则 | 准备方式 |
|---|---|---|
| {账户余额} | {100000.00 元} | {SQL 插入 / API 调用 / 配置} |
| {测试账号} | {test_a / 权限组:普通用户} | {seed 数据 / 注册流程} |

**依赖**：
- {外部接口/服务：依赖 X 服务的 Y 接口（真实/mock:方式）}
- {配置项/环境变量/第三方凭证；数据库表结构版本}

**测试步骤**（每步含步骤级预期，执行到哪步失败即定位到哪步）：
| # | 操作动作 | 步骤级预期 |
|---|---|---|
| 1 | {打开提现页，输入金额 50000} | {页面显示可提现，无校验错误} |
| 2 | {点击确认提现} | {返回成功响应 code=0，订单号生成} |
| 3 | {查询账户余额与流水} | {余额 50000.00，流水一条支出 50000} |

**期望结果（最终判定断言）**：
- {可判定的具体断言：值/状态码/状态变更/副作用；禁止「功能正常」}

**执行结果**（执行时填写）：
- 状态：{通过/失败/阻塞/未执行} ｜ 实际结果：{现象+关键数据} ｜ 缺陷：{DEF-xxx/—}
- 执行环境：{版本 commit} ｜ 执行批次：{EXE-{n}} ｜ 日期：{date}
- 证据：{日志片段/截图/响应 JSON}

> 每条用例重复上述结构。字段空缺 = 用例不合格，完备性检查不通过。
```

## 3. 反例说明（完备性检查要拦住的典型不合格用例）

- ❌ 「测试登录功能」——无业务规则、无前置数据、步骤与预期不可判定
- ❌ 步骤「输入合法数据」——「合法」未定义，前置数据表必须给出具体值
- ❌ 期望「处理成功」——未写成功后的可观察结果（响应值/状态/数据变化）
- ❌ 依赖外部支付网关但未声明 mock 方式——执行时必然 BLOCKED
