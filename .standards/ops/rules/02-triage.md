# 事件分诊 · 02-triage（OPS-STD-001）

> E1/E2 规则：把原始告警变成"带上下文的分级事件"。AI 智能体在此全自动，
> 人只在分级修正与派单确认时介入。

## 1. E1 捕获与分诊

动作序列：
1. **接收与归并**：应用降噪三规则（同源聚合/依赖抑制/时段感知）；
2. **初步分级**：按 01-perception §3 的业务影响标准定级 P0~P3；
3. **生成事件**：登记台账（D-OPS-09），分配事件编号 `INC-{YYYYMMDD}-{序号}`；
4. **派单**：P0/P1 通知值班链（含 AI 智能体的初判结论摘要）；P2/P3 进队列待处理。

## 2. E2 上下文富化（自动执行，并入分诊单）

| 富化项 | 来源 | 作用 |
|---|---|---|
| 日志窗口 | 日志平台 | 告警时刻 ±10 分钟、相关服务错误日志 TopN 模式 |
| 变更关联 | 变更系统 | 最近 24h 内该服务/依赖的发布、配置、扩缩容清单 |
| 依赖拓扑 | CMDB/服务目录 | 上下游链路，标出告警位置与影响传播方向 |
| 历史相似 | 知识库 | 匹配历史事件（症状/组件/时间特征），附既往根因与方案 |
| 影响面 | 业务指标 | 受影响功能、用户量级、SLA 偏离 |

富化的产出直接决定 E3 根因分析的起点：**若变更关联命中，根因调查从变更下钻开始**
（见 03-rca §2 变更优先原则）。

## 3. D-OPS-03 事件分诊单（必输）

必要章节：事件标识（编号/级别/状态）、告警溯源（原始告警 ID 清单——铁律 5）、
初判分级与依据、上下文富化五项、影响面评估、通知与派单记录、
分级修正记录（含修正理由）。

## 4. 分诊质量规则

- 分诊完成的定义：分级 + 五项富化齐备 + 已派单（或已入队），缺一不算完成。
- 分级错误的事后审计：E7 复盘时核对初判级别 vs 最终级别，连续误判 3 次的分级规则
  须调优并记入周报。
- AI 初判与人工修正冲突时，**修正以人工为准但必须留痕理由**——这是知识库的
  重要训练素材（分诊规则持续改进的依据）。
