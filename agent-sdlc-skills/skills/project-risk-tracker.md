# project_risk_tracker | 项目风险识别与跟踪

## 1. 技能描述

本技能面向项目管理与敏捷教练，提供项目风险的识别、分级、跟踪、闭环全流程管理能力。覆盖风险识别、等级评估、责任人指派、应对策略制定、跟踪报告输出、闭环确认六大模块，确保项目风险可见、可控、可闭环。

## 2. 触发条件

满足以下任一条件即触发：
- 输入包含「风险识别 / 风险分级 / 风险台账 / 风险跟踪 / 风险闭环」等关键词
- 业务方要求输出项目风险报告或风险应对方案
- 角色 10 被激活且场景为「风险识别与跟踪」

## 3. 执行步骤

1. **风险识别**：基于项目计划、进度状态、资源状态、依赖关系识别潜在风险
2. **风险分类**：按技术风险 / 进度风险 / 资源风险 / 合规风险 / 外部依赖风险分类
3. **风险评估**：按影响度（高 / 中 / 低）× 发生概率（高 / 中 / 低）二维评估
4. **风险分级**：综合影响度 × 概率得出风险等级（P0 / P1 / P2 / P3）
5. **责任人指派**：每个风险必须指派责任人与时限
6. **应对策略制定**：规避 / 转移 / 减轻 / 接受四策略选择
7. **风险台账构建**：建立可动态更新的风险台账
8. **跟踪报告输出**：按周 / 双周输出风险跟踪报告
9. **闭环确认**：风险解除后必须由责任人确认闭环
10. **风险控制校验**：标注置信度、调整空间、应急触发条件

## 4. 输入规范

```yaml
项目计划: "[来自 epic-task-breakdown 的排期表]"
进度状态: "进行中 / 滞后 / 阻塞"
资源状态: "[人员可用工时与负载]"
依赖关系: "[内部依赖 + 外部依赖清单]"
已识别风险: "[既有风险清单]"
输出格式: "风险台账 + 跟踪报告 + 应对策略"
```

## 5. 输出格式

```markdown
## 项目风险跟踪结果

### 一、风险台账
| 风险编号 | 风险描述 | 类别 | 影响度 | 概率 | 等级 | 责任人 | 应对策略 | 时限 | 状态 |

### 二、风险等级分布
- P0 / P1 / P2 / P3 数量统计

### 三、应对策略
| 风险编号 | 策略类型 | 应对方案 | 应急预案 | 触发条件 |

### 四、跟踪报告（按周 / 双周）
- 新增风险 + 已闭环风险 + 等级变化 + 待决风险

### 五、闭环确认
- 闭环风险清单 + 责任人确认 + 闭环时间

### 六、风险预警
- 即将到期风险 + 等级上升风险 + 阻塞风险
```

## 6. 质量标准

- 风险台账必须含 10 项核心字段：编号 / 描述 / 类别 / 影响 / 概率 / 等级 / 责任人 / 策略 / 时限 / 状态
- 每个风险必须指派责任人与闭环时限
- 风险等级必须基于影响度 × 概率二维评估
- 应对策略必须含触发条件 + 应急预案
- 跟踪报告必须按周 / 双周更新，标注新增 / 闭环 / 等级变化
- 风险闭环必须由责任人确认，禁止自动闭环
- 所有评估标注置信度与 ±10% 调整空间

## 7. 风险控制

| 规则编号 | 风险点 | 控制动作 |
|---------|--------|---------|
| R-01 | 风险识别不全 | 必须覆盖技术 / 进度 / 资源 / 合规 / 外部依赖五类 |
| R-02 | 风险无责任人 | 每个风险必须指派责任人 + 时限 |
| R-03 | 等级评估主观 | 必须基于影响度 × 概率二维评估 |
| R-04 | 应对策略缺失 | 必须含触发条件 + 应急预案 |
| R-05 | 自动闭环 | 闭环必须由责任人确认 |
| R-06 | 跟踪报告滞后 | 必须按周 / 双周更新 |
| R-07 | 绝对性承诺 | 禁止「保证无风险」措辞 |
| R-08 | 调整空间预留不足 | 所有评估附加 ±10% 调整空间 |
