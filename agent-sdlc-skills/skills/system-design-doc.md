# system_design_doc | 系统架构设计文档

## 1. 技能描述

本技能面向资深技术架构师，提供系统架构设计文档的标准化生成能力。覆盖业务场景分析、技术栈选型、分层架构设计、核心流程梳理、高可用与容灾预案、性能与容量规划、安全合规设计、分阶段落地步骤八大模块，输出可指导研发落地的架构设计文档。

## 2. 触发条件

满足以下任一条件即触发：
- 输入包含「系统架构 / 架构设计 / 技术选型 / 分层架构 / 高可用 / 容灾预案」等关键词
- 业务方要求进行新系统立项架构设计或现有系统重构
- 角色 03 被激活且场景为「系统架构设计」

## 3. 执行步骤

1. **业务场景分析**：基于角色 02 的 PRD 与角色 01 的业务逻辑初稿，明确业务场景
2. **非功能性需求梳理**：用户规模、QPS、TPS、响应时延、可用性 SLA、数据规模
3. **技术栈选型对比**：从功能匹配度、性能、生态、成本、运维复杂度五维度对比
4. **分层架构设计**：接入层 / 应用层 / 服务层 / 数据层 / 基础设施层
5. **核心流程梳理**：核心业务流程的时序图 + 部署拓扑图
6. **高可用与容灾预案**：多活部署、故障切换、降级方案、灰度发布
7. **性能与容量规划**：容量测算 + 扩容预案 + 性能基线
8. **安全合规设计**：调用角色 05 与角色 07 的安全合规输入
9. **分阶段落地步骤**：MVP → 增强 → 优化的里程碑拆解
10. **风险控制校验**：标注技术风险、置信度、调整空间

## 4. 输入规范

```yaml
业务场景: "AI 驱动的智能投研助手"
用户规模: "机构客户 1000+，日活用户 5000+"
性能要求: "QPS 500，响应时延 <2s"
成本约束: "年成本预算 500 万以内"
合规约束: "私有化部署，数据不出域"
技术栈偏好: "Java + Spring Cloud + MySQL + Redis + 开源大模型"
输出格式: "架构设计文档 + 技术选型对比 + 落地步骤"
```

## 5. 输出格式

```markdown
## 系统架构设计文档

### 一、业务场景与非功能性需求
- 业务场景 + 用户规模 + 性能 + 可用性 + 安全合规

### 二、技术选型对比
| 候选方案 | 功能匹配 | 性能 | 生态 | 成本 | 运维复杂度 | 推荐度 |

### 三、分层架构图
- 接入层 / 应用层 / 服务层 / 数据层 / 基础设施层

### 四、核心业务流程时序图
- 关键流程的时序图 + 部署拓扑图

### 五、高可用与容灾预案
- 多活部署 + 故障切换 + 降级方案 + 灰度发布

### 六、性能与容量规划
- 容量测算 + 扩容预案 + 性能基线

### 七、安全合规设计
- 数据安全 + 接口安全 + 合规要点

### 八、分阶段落地步骤
- MVP → 增强 → 优化的里程碑
```

## 6. 质量标准

- 技术选型必须提供至少 2 个候选方案对比，禁止单一方案默认
- 高可用方案必须覆盖故障切换 + 降级 + 灰度三要素
- 容量规划必须含容量测算公式与扩容预案
- 安全合规设计必须调用角色 05 与角色 07 输入
- 分阶段落地步骤必须含明确里程碑与验收标准
- 所有架构决策必须标注理由与权衡
- 所有方案标注置信度与 ±10% 调整空间

## 7. 风险控制

| 规则编号 | 风险点 | 控制动作 |
|---------|--------|---------|
| R-01 | 跳过架构评审直接写代码 | 强制架构评审前置 |
| R-02 | 技术选型无对比 | 必须至少 2 个候选方案对比 |
| R-03 | 高可用方案缺失 | 必须覆盖故障切换 + 降级 + 灰度 |
| R-04 | 容量规划缺失 | 必须含容量测算 + 扩容预案 |
| R-05 | 安全合规缺位 | 必须调用角色 05 / 07 复核 |
| R-06 | 绝对性建议 | 禁止「必须用某技术」措辞，输出推荐方案 |
| R-07 | 调整空间预留不足 | 所有方案附加 ±10% 调整空间 |
