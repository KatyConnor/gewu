# api_contract_definition | API 契约规范定义

## 1. 技能描述

本技能面向资深技术架构师，提供 API 契约规范文档的标准化生成能力。覆盖接口定义、请求参数规范、响应格式定义、错误码体系、调用限制与限流策略、版本管理、安全认证七大模块，输出可指导前后端并行开发的契约文档，避免接口对接返工。

## 2. 触发条件

满足以下任一条件即触发：
- 输入包含「API 契约 / 接口规范 / 请求参数 / 响应格式 / 错误码」等关键词
- 业务方要求定义前后端对接规范或微服务间调用契约
- 角色 03 被激活且场景为「API 契约定义」

## 3. 执行步骤

1. **接口需求梳理**：基于角色 02 的 PRD 与业务流程，梳理接口清单
2. **RESTful 规范确认**：遵循 RESTful 风格，明确资源命名与 HTTP 方法语义
3. **请求参数定义**：路径参数 + 查询参数 + 请求体 + 请求头规范
4. **响应格式定义**：统一响应包装结构 + 数据模型 + 分页规范
5. **错误码体系设计**：业务错误码 + 系统错误码 + HTTP 状态码映射
6. **调用限制与限流策略**：QPS 限制 + 令牌桶 / 漏桶策略 + 熔断降级
7. **版本管理规范**：URL 版本 + Header 版本策略，向后兼容承诺
8. **安全认证设计**：调用角色 05 输入，OAuth2 / JWT / API Key 选择
9. **接口文档输出**：OpenAPI / Swagger 规范文档
10. **风险控制校验**：标注安全风险、向后兼容风险、性能风险

## 4. 输入规范

```yaml
业务流程: "[来自角色 02 的业务流程]"
接口需求清单: "用户登录 / 报告查询 / 报告生成 / 报告导出"
技术约束: "RESTful + HTTPS + JSON"
认证方式: "JWT"
调用方: "Web 前端 + 移动端 + 第三方对接"
性能要求: "单接口 QPS ≤200，响应时延 <500ms"
输出格式: "OpenAPI 3.0 + Markdown 文档"
```

## 5. 输出格式

```markdown
## API 契约规范文档

### 一、接口清单
| 接口名 | Method | Path | 描述 | 认证 |

### 二、统一响应格式
- 状态码 + 消息 + 数据 + 时间戳

### 三、请求参数规范
- 路径参数 + 查询参数 + 请求体 + 请求头

### 四、响应数据模型
- 字段名 + 类型 + 必填 + 描述 + 示例

### 五、错误码体系
| 错误码 | HTTP 状态 | 含义 | 处理建议 |

### 六、调用限制与限流
- QPS 限制 + 限流策略 + 熔断降级

### 七、版本管理
- 版本策略 + 向后兼容承诺 + 废弃流程

### 八、安全认证
- 认证方式 + 鉴权流程 + 敏感数据保护
```

## 6. 质量标准

- 接口必须遵循 RESTful 风格，资源命名清晰
- 每个接口必须含完整请求参数与响应数据模型
- 错误码必须覆盖业务错误 + 系统错误，与 HTTP 状态码明确映射
- 调用限制必须含 QPS 限制 + 限流策略 + 熔断降级三件套
- 版本管理必须明确向后兼容承诺与废弃流程
- 安全认证必须调用角色 05 输入，敏感字段必须脱敏或加密
- 接口文档必须可被 OpenAPI / Swagger 工具解析

## 7. 风险控制

| 规则编号 | 风险点 | 控制动作 |
|---------|--------|---------|
| R-01 | 接口契约不一致 | 前后端必须基于同一契约文档并行开发 |
| R-02 | 错误码体系混乱 | 必须覆盖业务 + 系统错误，禁止裸 HTTP 状态码 |
| R-03 | 限流策略缺失 | 必须含 QPS 限制 + 限流 + 熔断三件套 |
| R-04 | 向后兼容破坏 | 必须明确版本策略 + 废弃流程 + 兼容承诺 |
| R-05 | 安全认证缺位 | 必须调用角色 05 复核 |
| R-06 | 敏感数据裸传 | 敏感字段必须脱敏或加密 |
| R-07 | 调整空间预留不足 | 所有方案附加 ±10% 调整空间 |
