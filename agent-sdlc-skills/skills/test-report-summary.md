# 技能模块：test_report_summary

> 测试报告输出与质量准出决策。

## 1. 技能描述

本技能汇总测试执行结果，输出包含覆盖率、缺陷分布、未解决问题清单的测试报告，并给出明确的质量准出建议。覆盖率门禁：核心模块 ≥ 95%，普通模块 ≥ 85%。准出决策基于多维指标（覆盖率、缺陷遗留、性能、安全、合规），输出「通过 / 有条件通过 / 不通过」明确结论。

## 2. 触发条件

- 输入包含「测试报告」「质量准出」「上线评估」「测试总结」等关键词
- 已完成测试执行，存在测试结果数据
- 已有缺陷清单与覆盖率数据
- 上线时间已确定（驱动准出决策）

## 3. 执行步骤

1. **数据汇总**：收集测试执行结果、缺陷清单、覆盖率、性能基线、安全审计结论。
2. **覆盖率分析**：核对核心模块 ≥ 95%、普通模块 ≥ 85% 门禁，未达标阻断。
3. **缺陷分布**：按模块、严重程度、状态分类，识别缺陷集中区域。
4. **遗留缺陷评估**：分级评估未解决缺陷，严重 / 高危必须清零，中危可有条件放行。
5. **多维指标综合**：
   - 功能完整性（需求覆盖率）
   - 性能基线（QPS、P99、错误率）
   - 安全审计结论
   - 合规审查结论
   - 兼容性（多端、多浏览器）
6. **准出决策**：综合评估，输出「通过 / 有条件通过 / 不通过」结论。
7. **风险评估**：识别上线后可能风险，给出预案。
8. **输出报告**：测试报告 + 质量准出报告 + 风险预案。

## 4. 输入规范

```yaml
任务类型: 测试报告与准出
版本: v2.1.0
测试执行结果: [Allure/Tester 报告链接]
缺陷清单: [Jira 缺陷列表]
覆盖率数据:
  核心: 96.5%
  普通: 88.2%
性能基线: [压测报告]

合规审查: [合规审查结论]
上线时间: 2026-08-20
```

## 6. 质量标准

- 覆盖率门禁：核心 ≥ 95%，普通 ≥ 85%，未达标禁止准出
- 严重 / 高危缺陷必须清零方可准出
- 准出结论必须明确（通过 / 有条件通过 / 不通过），禁止模糊措辞
- 测试报告必须包含数据来源与统计时间窗口
- 准出决策必须基于多维指标，单维度不达标即整体不通过

## 7. 风险控制

| 规则 | 内容 |
|------|------|
| RISK-01 | 严重 / 高危缺陷未清零禁止准出 |
| RISK-02 | 覆盖率、安全审计、合规审查、性能基线任一不达标禁止准出 |
| RISK-03 | 「有条件通过」必须列出遗留风险与监控预案 |
| RISK-04 | 准出报告必须由测试负责人签字确认 |

