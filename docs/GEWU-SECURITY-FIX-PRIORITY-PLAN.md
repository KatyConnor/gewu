# 格物致虚平台安全问题修复优先级计划

> 基于 `docs/CODE-SECURITY-REVIEW-REPORT.md` 制定，当前阶段：**Wave 1-4 全部完成** ✅

## 一、总体策略

### 1.1 修复原则

| 原则 | 说明 |
|------|------|
| **先止血，后重构** | P0/P1 先封堵可被利用的漏洞，P2/P3 再优化架构和代码质量 |
| **默认拒绝，最小权限** | 所有接口默认需认证，管理员功能显式授权 |
| **安全左移** | 每个修复必须配套单元测试/集成测试，禁止无测试覆盖的安全改动 |
| **向后兼容** | 涉及密码哈希、API Key 加密的改动需设计兼容方案，避免用户无法登录 |
| **配置与代码分离** | 密钥、白名单、域名等必须通过环境变量或配置中心注入 |

### 1.2 优先级评估模型

每项问题按三个维度评分（1-5 分），总分 = 严重度 × 2 + 可利用性 × 1.5 + 影响范围 × 1.5：

| 维度 | 权重 | 说明 |
|------|------|------|
| 严重度 | 2.0 | 是否可直接导致数据泄露/系统沦陷 |
| 可利用性 | 1.5 | 攻击门槛（公开接口/需认证/需内网） |
| 影响范围 | 1.5 | 影响用户/数据/系统组件数量 |

## 八、决策点

在正式修复前，需要确认以下决策：

1. **CORS 可信域名**：生产环境域名是什么？是否允许本地开发域名？
2. **管理员角色**：使用 `ROLE_ADMIN` 还是 `ROLE_SYSTEM`？
3. **沙箱执行权限**：是否仅 ADMIN 可执行，还是为 Agent 创建单独角色？
4. **API Key 加密算法**：使用 SM4（现有国密能力）还是 AES-GCM？
5. **密码哈希算法**：使用 `bcrypt`（Spring 内置）还是 `Argon2id`？
6. **SSRF 白名单**：是否默认拒绝所有未配置白名单的工具？
7. **Actuator 访问**：是否限制为内部 IP，还是统一走管理网关？

请确认以上决策后，即可按 Wave 顺序开始修复。
