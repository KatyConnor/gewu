## 1. 引言

### 1.1 目的

本文档描述「格物知行」AI 智能协作平台的完整软件需求规格，作为设计、开发、测试、验收的统一依据。

### 1.2 范围

**产品是什么**：
格物知行是一个企业级 AI 智能协作平台，集成智能对话、智能体管理、项目管理、工作流编排、沙箱安全执行于一体，通过 Wenshi 知识增强层（记忆+推理+学习）提升 AI 协作效率。

**产品不是什么**：
- 不是纯聊天工具（而是协作平台）
- 不是低代码平台（不面向非技术人员）
- 不包含硬件设备管理
- 不提供移动端原生 App（当前仅 Web）

## 2. 总体描述

### 2.1 产品背景

**业务背景**：
随着大语言模型技术的快速发展，企业对于 AI 辅助协作的需求日益增长。当前市场上缺乏一个能够整合智能对话、智能体编排、项目管理、工作流引擎的一站式协作平台。格物知行致力于解决以下核心痛点：

1. **AI 上下文断裂**：传统聊天工具无法持久化记忆，每次对话从零开始
2. **智能体管理分散**：缺乏统一的 Agent 创建、发布、监控平台
3. **协作与 AI 分离**：项目管理和 AI 对话在不同工具间切换
4. **工作流无法自动化**：重复性任务无法通过 AI 自动编排执行

**市场机会**：
- 企业级 AI 协作平台市场年增长率 40%+
- 开发者对 AI 辅助开发工具需求强烈
- 企业数字化转型加速，AI 成为核心竞争力

### 2.2 产品定位

**一句话定位**：
格物知行是一个企业级 AI 智能协作平台，帮助技术团队通过智能体编排、知识增强、工作流自动化提升协作效率。

**核心价值主张**：
1. **Wenshi 知识增强**：记忆+推理+学习三层认知架构，AI 越用越聪明
2. **一站式协作**：对话+Agent+项目+工作流，一个平台全覆盖
3. **企业级安全**：JWT Token 家族检测、登录锁定、审计日志、等保合规
4. **开放生态**：MCP 协议支持，可扩展任意外部工具

## 4. 模块详细需求

### 4.1 模块一：认证域

#### F-001：用户注册

| 属性 | 内容 |
|------|------|
| 功能编号 | F-001 |
| 优先级 | P0 |

**用户故事**：
> As a 新用户, I want 通过用户名/邮箱/密码注册账号, so that 可以使用平台的完整功能

**前置条件**：
- 用户访问登录页并切换到注册模式
- 用户名和邮箱未被注册

**主流程**：

| 步骤 | 用户操作 | 系统响应 |
|------|----------|----------|
| 1 | 点击"注册新账户" | 切换到注册表单 |
| 2 | 输入用户名（3-64字符） | 实时校验格式 |
| 3 | 输入邮箱 | 实时校验格式 |
| 4 | 输入密码（6-128字符） | 实时校验强度 |
| 5 | 输入显示名称 | - |
| 6 | 点击"注册"按钮 | 显示 loading 状态 |
| 7 | - | 调用 POST /api/v1/auth/register |
| 8 | - | 创建用户 + 分配默认角色 USER |
| 9 | - | 生成 Token 对并返回 |
| 10 | - | 持久化 Token 到 localStorage |
| 11 | - | 自动跳转到仪表盘 |

**备选流程**：

| 编号 | 触发条件 | 处理流程 |
|------|----------|----------|
| AF-01 | 用户名已存在 | 提示"用户名已存在，请更换" |
| AF-02 | 邮箱已注册 | 提示"邮箱已被注册" |
| AF-03 | 密码强度不足 | 提示"密码至少6位" |
| AF-04 | 网络超时 | 提示"网络异常，请稍后重试" |

**异常流程**：

| 编号 | 异常场景 | 系统处理 |
|------|----------|----------|
| EF-01 | 服务端500错误 | 记录日志，展示友好错误提示 |
| EF-02 | 数据库连接失败 | 重试3次，仍失败则提示服务不可用 |

**验收标准**：

```gherkin
Scenario: 使用有效信息注册成功
  Given 用户访问登录页
  And 用户名 "newuser" 未被注册
  When 输入用户名 "newuser"、邮箱 "new@example.com"、密码 "Pass123456"
  And 输入显示名称 "新用户"
  And 点击"注册"按钮
  Then 系统创建用户账号
  And 自动跳转到仪表盘
  And localStorage 中保存了 accessToken

Scenario: 用户名已存在
  Given 用户名 "existing" 已被注册
  When 输入用户名 "existing" 并提交
  Then 页面提示"用户名已存在，请更换"
```

**业务规则**：

| 规则编号 | 规则描述 | 校验逻辑 |
|----------|----------|----------|
| BR-001 | 用户名唯一性 | 数据库唯一索引 + 前置校验 |
| BR-002 | 邮箱唯一性 | 数据库唯一索引 + 前置校验 |
