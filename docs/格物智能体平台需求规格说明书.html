1. 引言

1.1 目的

本文档描述「格物智能体平台」的软件需求规格，作为开发、测试、验收的统一依据。本文档基于项目当前已实现的功能和需求调研分析资料，形成完整的需求基线。

1.2 范围

产品是什么： 格物智能体平台是一个 AI 驱动的智能开发协作平台，提供 Agent 智能体会话、工作流编排、代码沙箱执行、项目管理、知识增强等核心能力。平台采用模块化单体 + 微服务混合架构，支持多数据库、多缓存、多消息队列，满足信创合规要求。

产品不是什么：

  • 不包含完整的 IDE 功能（仅提供代码沙箱执行能力）
  • 不包含企业资源计划（ERP）功能
  • 不包含客户关系管理（CRM）功能
  • 不包含财务管理系统

2. 总体描述

2.1 产品背景

业务背景： 随着 AI 大模型技术的快速发展，企业对于 AI 智能体的需求日益增长。传统开发协作工具缺乏 AI 能力集成，无法有效利用大模型提升开发效率。格物智能体平台旨在构建一个企业级 AI 协作平台，通过 Agent 智能体、工作流编排、代码沙箱等能力，帮助企业提升研发效率。

市场机会：

  • AI 智能体市场规模持续增长，预计 2026 年达到数百亿美元
  • 企业级 AI 协作平台需求旺盛，尤其在信创合规领域
  • 国产替代趋势明显，信创合规成为企业选型的重要考量

竞争格局：

竞品 优势 劣势
GitHub Copilot 生态完善、用户基数大 无信创合规、无工作流编排
Cursor IDE 集成度高 无团队协作、无沙箱执行
Dify 工作流编排能力强 无信创合规、无知识增强
Coze 字节生态、模型丰富 无企业级权限、无信创合规

2.2 产品定位

格物智能体平台是一个企业级 AI 开发协作平台，帮助开发团队通过 Agent 智能体、工作流编排、代码沙箱和知识增强能力，提升研发效率、规范开发流程、积累团队知识。

核心价值主张：

  • 信创合规：100% 满足信创目录要求，国密算法支持
  • 知识增强：Wenshi 三层增强架构，让 LLM 越用越聪明
  • 自主可控：自研 API 网关、自研工作流引擎
  • 安全合规：等保 2.0 三级合规，92/100 分 A 级

3.3 模块一：用户认证模块

3.3.1 模块概述

用户认证模块负责平台的身份认证和权限管理，包括用户注册、登录、Token 管理、密码策略校验等功能。采用 JWT 无状态认证方案，支持 Access Token + Refresh Token 双 Token 机制。

3.3.2 功能详细需求

F-001：用户注册

属性 内容
功能编号 F-001
优先级 P0
估算工作量 3 人天

用户故事：

As a 新用户, I want 通过用户名、邮箱和密码注册账号, so that 可以使用平台的完整功能

前置条件：

  • 用户访问注册页面
  • 用户名和邮箱未被注册

主流程：

步骤 用户操作 系统响应
1 访问注册页面 展示注册表单（用户名、邮箱、密码、确认密码）
2 输入注册信息 实时校验格式（邮箱格式、密码强度）
3 点击"注册"按钮 提交注册请求
4 - 校验用户名/邮箱唯一性
5 - 使用 SM3 哈希密码
6 - 创建用户账号
7 - 生成 JWT Token（Access + Refresh）
8 - 返回 Token 和用户信息

备选流程：

编号 触发条件 处理流程
AF-01 用户名已存在 提示"该用户名已被使用"
AF-02 邮箱已注册 提示"该邮箱已注册，请直接登录"
AF-03 密码强度不足 实时提示"密码至少8位，包含大小写字母、数字、特殊字符"
AF-04 两次密码不一致 提示"两次输入的密码不一致"

异常流程：

编号 异常场景 系统处理
EF-01 服务端500错误 记录日志，展示友好错误提示
EF-02 数据库连接失败 重试3次，仍失败则提示服务不可用

验收标准：

Scenario: 使用有效信息注册成功
  Given 用户访问注册页面
  And 用户名 "testuser" 未被注册
  And 邮箱 "test@example.com" 未被注册
  When 输入用户名 "testuser"
  And 输入邮箱 "test@example.com"
  And 输入密码 "Passw0rd!"
  And 点击"注册"按钮
  Then 系统创建用户账号
  And 返回有效的 Access Token 和 Refresh Token
  And 跳转到首页

Scenario: 使用已注册邮箱注册
  Given 邮箱 "existing@example.com" 已被注册
  When 输入邮箱 "existing@example.com"
  And 点击"注册"按钮
  Then 页面提示"该邮箱已注册，请直接登录"

Scenario: 密码强度不足
  When 输入密码 "123456"
  Then 实时提示"密码至少8位，包含大小写字母、数字、特殊字符"
  And "注册"按钮不可点击

业务规则：

规则编号 规则描述 校验逻辑
BR-001 用户名格式校验 3-20 位字母、数字、下划线
BR-002 邮箱格式校验 符合 RFC 5322 标准
BR-003 密码强度要求 ≥8位，包含大写字母+小写字母+数字+特殊字符
BR-004 注册频率限制 同一IP每小时最多注册5个账号
BR-005 密码加密存储 使用 SM3 加盐多轮迭代哈希

数据需求：

字段 类型 必填 约束 说明
username VARCHAR(50) 是 唯一，3-20位 用户名
email VARCHAR(255) 是 唯一，有效邮箱格式 用户邮箱
password_hash VARCHAR(255) 是 - SM3 密码哈希
display_name VARCHAR(100) 否 - 显示名称
status TINYINT 是 默认1 0=禁用,1=正常
created_at BIGINT 系统生成 - 注册时间（毫秒时间戳）

F-002：用户登录

属性 内容
功能编号 F-002
优先级 P0
估算工作量 2 人天

用户故事：

As a 已注册用户, I want 通过用户名/邮箱和密码登录, so that 可以访问我的账户和使用平台功能

前置条件：

  • 用户已注册且账号状态正常
  • 用户访问登录页面

主流程：

步骤 用户操作 系统响应
1 访问登录页面 展示登录表单
2 输入用户名/邮箱、密码 -
3 点击"登录"按钮 验证账号密码
4 - 校验密码（SM3 哈希比对）
5 - 生成 JWT Token（Access + Refresh）
6 - 设置 httpOnly Cookie（可选）
7 - 返回 Token 和用户信息

备选流程：

编号 触发条件 处理流程
AF-01 密码错误 提示"用户名或密码错误"，显示剩余尝试次数
AF-02 连续5次失败 锁定账号30分钟
AF-03 账号被禁用 提示"账号已被禁用，请联系管理员"

验收标准：

Scenario: 使用正确凭证登录成功
  Given 用户 "testuser" 已注册且密码为 "Passw0rd!"
  When 输入用户名 "testuser" 和密码 "Passw0rd!"
  And 点击"登录"按钮
  Then 登录成功，跳转到首页
  And 返回有效的 Access Token（30分钟有效期）
  And 返回有效的 Refresh Token（7天有效期）

Scenario: 密码错误
  When 输入用户名 "testuser" 和密码 "WrongPass"
  Then 提示"用户名或密码错误，还有4次尝试机会"

Scenario: 账号被锁定
  Given 用户已连续5次输入错误密码
  When 再次尝试登录
  Then 提示"账号已锁定，请30分钟后重试"

业务规则：

规则编号 规则描述
BR-006 Access Token 有效期 30 分钟
BR-007 Refresh Token 有效期 7 天
BR-008 连续5次失败锁定30分钟
BR-009 同一IP每分钟最多10次登录尝试
BR-010 支持 httpOnly Cookie 和 Bearer Token 两种认证方式

F-003：Token 刷新

属性 内容
功能编号 F-003

  And 旧 Refresh Token 失效

Scenario: Refresh Token 已过期
  Given 用户的 Refresh Token 已过期
  When 请求刷新接口
  Then 返回 401 错误

7. 业务规则

规则编号 规则名称 描述 触发条件 处理逻辑
BR-001 用户名唯一性 同一用户名只能注册一个账号 注册时 查询用户名是否已存在
BR-002 邮箱唯一性 同一邮箱只能注册一个账号 注册时 查询邮箱是否已存在
BR-003 密码强度 密码≥8位，含大小写+数字+特殊字符 注册/修改密码 正则校验
BR-004 登录锁定 连续5次失败锁定30分钟 登录失败 计数并判断锁定
BR-005 Token 刷新 Refresh Token 只能使用一次 刷新时 旧 Token 加入黑名单
BR-006 项目权限 只有项目成员可访问项目数据 访问项目时 校验成员关系
BR-007 模型配置权限 只有管理员可配置模型 配置模型时 校验管理员角色
BR-008 沙箱安全 危险代码必须被拦截 执行代码时 安全策略校验
BR-009 API Key 加密 API Key 必须加密存储 保存 API Key 时 SM4-GCM 加密
BR-010 上下文压缩 超过 token 阈值时自动压缩 对话时 保留 system + 最近 6 条
