## 概述

工作流画布是「格物·致虚」AI 协作平台的核心功能之一，提供可视化的流程编排能力。通过拖拽节点、连接端口、配置属性，用户可以快速构建复杂的自动化流程，无需编写代码。

### 设计参考

本画布参考了 n8n、Node-RED、Dify、Coze 等成熟流程设计框架，在保持专业性的同时尽可能简化操作。

### 核心概念

| 概念 | 说明 |
|------|------|
| **节点（Node）** | 流程中的一个执行单元，代表一个操作或判断 |
| **端口（Port）** | 节点上的连接点，分为输入端口（左侧）和输出端口（右侧） |
| **连接（Connection）** | 两个端口之间的连线，定义数据流向 |
| **分支（Branch）** | 条件/开关节点的多个输出路径 |
| **画布（Canvas）** | 可视化编辑区域，支持缩放和平移 |

### 工作流状态系统

工作流采用**双维度状态**设计：

#### 设计状态（Design Status）

控制工作流的生命周期：

| 状态 | 图标 | 说明 |
|------|------|------|
| **草稿** | ✏️ | 工作流正在设计中，不可运行 |
| **已发布** | 📤 | 工作流已发布，可以运行和调度 |

#### 运行状态（Run Status）

控制工作流的执行状态（仅已发布的工作流才有）：

| 状态 | 图标 | 说明 |
|------|------|------|
| **已停止** | ⏹️ | 工作流未在运行 |
| **运行中** | ✅ | 工作流正在执行或等待触发 |
| **已暂停** | ⏸️ | 工作流已暂停，可恢复运行 |

#### 状态流转

```
创建 → 草稿 → 发布 → 已发布
                          ↓
                    启动 → 运行中 ↔ 暂停
                          ↓
                    停止 → 已停止
```

**重要规则：**
- 草稿状态的工作流**不能运行**，必须先发布
- 已发布的工作流才能启动、暂停、停止
- 画布编辑完成后必须点击「发布」按钮

## 入门

### 创建工作流

1. 在左侧导航栏点击「工作流」进入列表页
2. 点击右上角「创建工作流」按钮
3. 在弹窗中填写：
   - **工作流名称**（必填）：为工作流命名
   - **描述**（可选）：说明工作流的用途
   - **触发方式**：选择默认触发类型
4. 点击「创建并设计」进入画布

### 发布工作流

工作流设计完成后，必须发布才能运行：

1. 在画布中点击工具栏「发布」按钮
2. 或在列表页点击「更多操作」→「发布」
3. 发布成功后，工作流状态变为「已发布」

### 运行工作流

已发布的工作流可以启动运行：

1. 在列表页点击 ▶️ 启动按钮
2. 运行中点击 ⏸️ 暂停
3. 暂停后点击 ▶️ 恢复运行

### 退出画布

- 点击工具栏「返回」按钮回到列表页
- 未保存时系统会提示确认

## 节点库详解

节点库按功能分为 **6 大类，22 种节点**：

### 🔴 触发器（4种）

触发器是工作流的起点，定义了流程何时启动。

| 节点 | 说明 | 配置项 |
|------|------|--------|
| **手动触发** | 用户手动点击启动 | 节点名称 |
| **定时触发** | 按 Cron 表达式定时执行 | Cron 表达式、时区 |
| **Webhook** | 接收外部 HTTP 请求触发 | 请求方法、路径 |
| **事件触发** | 监听系统事件（文件创建/数据更新/用户操作） | 事件类型 |

### 🟡 逻辑控制（4种）

控制流程的执行路径和逻辑。

| 节点 | 说明 | 分支出口 |
|------|------|----------|
| **条件判断** | If/Else 二分支，根据条件走不同路径 | True / False |
| **多路分支** | Switch 多分支，根据值匹配走对应路径 | 分支1 / 分支2 / 默认 |
| **循环遍历** | 遍历数组，逐个处理元素 | 循环体 / 完成 |
| **门控过滤** | 过滤不符合条件的数据 | 通过 / 拦截 |

### 🟢 AI 能力（4种）

集成 AI 大模型和智能体能力。

| 节点 | 说明 | 配置项 |
|------|------|--------|
| **大模型调用** | 调用 LLM 生成内容 | 模型、提示词、温度、最大Token |
| **知识检索** | 从知识库检索相关内容 | 知识库、检索数量、相似度阈值 |
| **智能体** | 调用 AI Agent 自主执行任务 | 智能体选择、任务描述 |
| **代码执行** | 执行 Python/JavaScript 代码 | 语言、代码内容 |

### 🔵 数据处理（3种）

对数据进行转换、解析和赋值操作。

| 节点 | 说明 | 配置项 |
|------|------|--------|
| **数据转换** | 转换数据结构和格式 | 字段映射（JSON） |
| **JSON 解析** | 解析 JSON 字符串为对象 | 待解析字段 |
| **变量赋值** | 设置或修改变量值 | 变量列表（key=value） |

### 🟣 集成对接（4种）

与外部系统进行交互。

| 节点 | 说明 | 配置项 |
|------|------|--------|
| **HTTP 请求** | 发送 HTTP 请求到外部服务 | 方法、地址、请求头、请求体 |
| **数据库操作** | 查询或修改数据库 | 操作类型、表名、SQL |
| **发送邮件** | 发送电子邮件通知 | 收件人、主题、正文 |
| **通知推送** | 推送消息到 IM 平台 | 渠道、消息内容 |

### ⚫ 流程控制（3种）

控制流程的执行节奏和结构。

| 节点 | 说明 | 配置项 |
|------|------|--------|
| **延时等待** | 暂停等待指定时间 | 时长、单位 |
| **计数器** | 统计通过的数据条数 | 重置条件 |
| **子工作流** | 调用另一个工作流 | 子工作流选择 |
| **返回结果** | 结束并返回结果 | 输出表达式 |

## 节点操作

### 添加节点

**方法一：拖拽添加**
1. 在左侧节点库中找到需要的节点类型
2. 按住鼠标左键拖拽节点到画布目标位置
3. 松开鼠标完成放置

**方法二：复制添加**
1. 右键点击已有节点
2. 选择「复制节点」
3. 新节点会出现在原节点右下方

### 移动节点

1. 将鼠标移到节点**标题栏**区域
2. 按住鼠标左键拖动到目标位置
3. 松开鼠标放置

> 提示：节点会实时跟随鼠标移动，松开后自动对齐网格

### 删除节点

**方法一：**
1. 点击节点选中它
2. 按键盘 `Delete` 或 `Backspace` 键

**方法二：**
1. 右键点击节点
2. 选择「删除节点」

> 注意：删除节点会同时删除与该节点相关的所有连接

### 复制节点

1. 右键点击节点
2. 选择「复制节点」
3. 新节点会复制原节点的所有配置

## 连接操作

### 创建连接

**方法一：端口拖拽（推荐）**
1. 将鼠标移到源节点的**输出端口**（右侧圆点）
2. 按住鼠标左键拖拽
3. 将连线拖到目标节点的**输入端口**（左侧圆点）
4. 松开鼠标完成连接

**方法二：点击连接**
1. 选中源节点，在右侧配置面板点击「连接下游节点」
2. 点击目标节点完成连接

### 连接规则

| 规则 | 说明 |
|------|------|
| **端口类型** | 只能从输出端口连接到输入端口 |
| **单输入限制** | 一个输入端口只能接收一条连接 |
| **多输出允许** | 一个输出端口可以连接多个目标 |
| **禁止自环** | 不能将节点连接到自身 |
| **分支标签** | 条件/开关节点的连接线上会显示分支名称 |

### 删除连接

**方法一：**
1. 将鼠标移到连接线上
2. 点击连线（会高亮显示）

**方法二：**
1. 右键点击源节点
2. 选择「断开所有连接」

### 条件分支说明

**条件判断节点**有 2 个输出端口：
- **True**：条件成立时执行
- **False**：条件不成立时执行

**多路分支节点**有 3 个输出端口：
- **分支1 / 分支2**：匹配到对应值时执行
- **默认**：未匹配到任何值时执行

**循环遍历节点**有 2 个输出端口：
- **循环体**：每次循环执行
- **完成**：循环结束后执行

## 节点配置

### 打开配置面板

点击任意节点，右侧会显示该节点的配置面板。

### 配置字段类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **文本输入** | 单行文本 | 节点名称、URL |
| **多行文本** | 多行文本/代码 | 提示词、SQL、代码 |
| **下拉选择** | 从预设选项中选择 | 模型、请求方法 |
| **数字输入** | 数值输入 | 温度、时长、数量 |

### 配置面板功能

- **节点名称**：修改节点的显示名称
- **字段配置**：根据节点类型显示不同的配置项
- **分支出口**：条件/开关节点显示各分支的连接状态
- **快捷操作**：复制、断开连接、删除节点

### 各节点配置详解

#### 大模型调用

| 字段 | 说明 | 建议值 |
|------|------|--------|
| 模型 | 选择 LLM 模型 | GPT-4o（通用）/ Claude 3.5（长文本） |
| 系统提示词 | 定义 AI 角色和任务 | 清晰描述角色和输出格式 |
| 温度 | 控制输出随机性 | 0.3（精确）/ 0.7（平衡）/ 1.2（创意） |
| 最大 Token | 限制输出长度 | 2048（短）/ 4096（中）/ 8192（长） |

#### HTTP 请求

| 字段 | 说明 | 示例 |
|------|------|------|
| 请求方法 | GET/POST/PUT/DELETE | POST |
| 请求地址 | 目标 URL | https://api.example.com/data |
| 请求头 | JSON 格式 | `{"Authorization": "Bearer xxx"}` |
| 请求体 | POST/PUT 时填写 | `{"key": "value"}` |

#### 条件判断

| 字段 | 说明 | 示例 |
|------|------|------|
| 判断字段 | 要判断的数据字段 | `data.status` |
| 操作符 | 比较方式 | equals / gt / contains |
| 比较值 | 用于比较的值 | `200` |

## 典型场景示例

### 场景一：代码审查自动化

```
[手动触发] → [HTTP 请求(获取PR)] → [大模型调用(审查代码)] → [条件判断]
                                                              ├─ True → [通知推送(审查通过)] → [返回结果]
                                                              └─ False → [通知推送(需修改)] → [返回结果]
```

**配置要点：**
1. HTTP 请求：调用 Git API 获取 PR 内容
2. 大模型调用：提示词设为「你是一个资深代码审查者，请审查以下代码...」
3. 条件判断：判断字段 `data.result`，操作符 `contains`，值 `通过`
4. 通知推送：根据结果发送不同消息

### 场景二：定时数据同步

```
[定时触发(每天9点)] → [数据库操作(查询)] → [数据转换] → [HTTP 请求(推送)]
                                                          → [发送邮件(报告)]
```

**配置要点：**
1. 定时触发：Cron 表达式 `0 9 * * *`
2. 数据库操作：SELECT 查询需要同步的数据
3. 数据转换：映射字段格式
4. HTTP 请求 + 发送邮件：并行推送数据和报告

### 场景三：智能客服流程

```
[Webhook(接收消息)] → [知识检索] → [大模型调用(生成回答)] → [条件判断(是否需要人工)]
                                                              ├─ True → [通知推送(转人工)] → [返回结果]
                                                              └─ False → [HTTP 请求(回复用户)] → [返回结果]
```

**配置要点：**
1. Webhook：接收用户消息
2. 知识检索：从 FAQ 知识库检索相关内容
3. 大模型调用：结合知识库内容生成回答
4. 条件判断：判断是否需要转人工（如置信度低于阈值）

### 场景四：批量数据处理

```
[手动触发] → [数据库操作(查询列表)] → [循环遍历]
                                          ├─ 循环体 → [大模型调用(处理单条)] → [数据库操作(更新)]
                                          └─ 完成 → [发送邮件(完成通知)] → [返回结果]
```

## 常见问题

### Q1: 如何判断连接是否成功？

连接成功后：
- 两个端口之间会出现贝塞尔曲线连线
- 条件/开关节点的连线上会显示分支标签（True/False/分支1 等）
- 连线上有箭头指示数据流向

### Q2: 节点配置中的字段路径怎么写？

使用点号 `.` 访问嵌套字段：
- `data` — 根数据
- `data.status` — 访问 status 字段
- `data.items.0.name` — 访问数组第一个元素的 name

### Q3: 如何调试工作流？

1. 点击「运行」按钮启动工作流
2. 观察各节点的执行状态（后续版本支持）
3. 检查最终输出结果是否符合预期

### Q4: 节点数量有限制吗？

当前版本建议单个工作流不超过 50 个节点，以保证性能和可维护性。复杂流程建议使用「子工作流」节点拆分。

### Q5: 如何复用已有的流程？

- 使用「子工作流」节点调用其他工作流
- 通过复制节点复用配置
- 后续版本将支持导出/导入工作流模板

### Q6: 条件判断的操作符有哪些？

| 操作符 | 含义 | 适用场景 |
|--------|------|----------|
| equals | 等于 | 状态码判断 |
| not_equals | 不等于 | 排除特定值 |
| gt / gte | 大于/大于等于 | 数值比较 |
| lt / lte | 小于/小于等于 | 阈值判断 |
| contains | 包含 | 字符串/数组包含 |
| empty | 为空 | 空值检查 |
| not_empty | 非空 | 非空检查 |

## 最佳实践

1. **从简单开始**：先构建最小可用流程，再逐步添加节点
2. **命名规范**：为每个节点起有意义的名字，方便后续维护
3. **善用注释**：在关键节点名称中标注用途
4. **拆分复杂流程**：超过 10 个节点时考虑使用子工作流
5. **充分测试**：正式运行前多次测试各种分支情况
6. **保存习惯**：每完成一个阶段就点击保存
