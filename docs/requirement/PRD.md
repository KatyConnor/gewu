# 需求管理模块 — 产品需求文档（PRD）

> 版本：V1.0  
> 日期：2026-07-27  
> 状态：设计完成，待开发

---

## 一、产品概述

### 1.1 背景

格物致虚 AI 智能协作平台当前缺少独立的需求管理模块。项目全生命周期中，需求从提出到上线的跟踪依赖会话和文档，缺乏结构化的需求流转机制。

### 1.2 目标

构建独立的需求管理模块，支持：
- 需求全生命周期管理（草稿→评审→设计→开发→测试→上线→归档）
- 多级评审流程（需求评审→设计评审→测试案例评审）
- 需求与项目/会话/文档的关联
- 表格+看板双视图展示
- 角色权限控制

### 1.3 用户角色

| 角色 | 核心职责 |
|------|---------|
| **产品经理** | 创建/编辑/删除需求、提交评审、原型设计 |
| **项目经理/技术负责人** | 评审需求、需求设计、设计评审、制定计划、分配任务 |
| **测试负责人** | 评审需求、评审测试案例、分配测试任务 |
| **开发工程师** | 查看需求、开发实现、更新开发状态 |
| **测试工程师** | 查看需求、编写测试案例、执行测试、关联测试用例 |

## 二、功能需求

### 2.1 需求 CRUD

| 功能 | 描述 | 验收标准 |
|------|------|---------|
| 创建需求 | 填写标题、类型、优先级、描述等 | 自动生成需求编号 REQ-YYYY-NNN |
| 编辑需求 | 修改需求信息 | 仅草稿状态可编辑核心字段 |
| 删除需求 | 软删除需求 | 逻辑删除，数据保留 |
| 查看详情 | 查看需求完整信息 | 展示基本信息、评审记录、任务、评论 |

### 2.2 需求类型

| 类型 | 编码 | 图标 | 说明 |
|------|------|------|------|
| 用户故事 | STORY | 📖 | 作为【角色】，我想要【功能】，以便【价值】 |
| 任务 | TASK | ✅ | 具体的工作任务 |
| 缺陷 | BUG | 🐛 | 系统缺陷或问题 |
| 改进 | IMPROVEMENT | ⬆️ | 现有功能的优化改进 |
| 功能需求 | FEATURE | ✨ | 新功能需求 |
| 史诗 | EPIC | 🏔️ | 大型需求，可拆分为多个子需求 |

### 2.3 优先级

| 级别 | 编码 | 颜色 | 说明 | 响应时间要求 |
|------|------|------|------|------------|
| P0 | 0 | 红色 | 紧急 | 立即处理 |
| P1 | 1 | 橙色 | 高 | 24 小时内 |
| P2 | 2 | 蓝色 | 中 | 1 周内 |
| P3 | 3 | 灰色 | 低 | 排期处理 |

### 2.4 需求状态流转

#### 主流程

```
草稿 → 待需求评审 → 评审中 → 已通过 → 设计 → 待设计评审 → 设计评审中 → 计划制定 → 任务分配 → 待开发 → 开发中 → 开发完成 → 冒烟测试 → SIT测试 → UAT测试 → 已上线 → 已归档
```

#### 分支流程

- **原型分支**：任何阶段 → 原型 → 返回主流程
- **取消分支**：任何阶段 → 已取消

#### 状态操作权限

| 状态 | 可执行操作 | 操作角色 |
|------|-----------|---------|
| 草稿 | 编辑/删除/提交评审 | 产品经理 |
| 待需求评审 | 撤回 | 产品经理 |
| 评审中 | 通过/驳回/添加意见 | 项目经理/技术负责人/测试负责人 |
| 已通过 | 进入设计 | 项目经理/技术负责人 |
| 设计 | 编辑设计文档/提交设计评审 | 项目经理/技术负责人 |
| 待设计评审 | 撤回 | 项目经理/技术负责人 |
| 设计评审中 | 通过/驳回 | 项目经理/技术负责人 |
| 计划制定 | 创建计划/分配任务 | 项目经理/技术负责人 |
| 任务分配 | 调整分配 | 项目经理/技术负责人 |
| 待开发 | 开始开发 | 开发工程师 |
| 开发中 | 更新进度/提交完成 | 开发工程师 |
| 开发完成 | 开始冒烟测试 | 测试工程师 |
| 冒烟测试 | 通过/驳回 | 测试工程师 |
| SIT测试 | 通过/驳回 | 测试工程师 |
| UAT测试 | 通过/驳回 | 测试负责人 |
| 已上线 | 归档 | 产品经理 |
| 已归档 | 查看 | 所有角色 |
| 原型 | 返回主流程/取消 | 产品经理 |
| 已取消 | 重新激活 | 产品经理 |

### 2.5 多级评审

| 评审类型 | 评审节点 | 评审人角色 | 评审内容 |
|---------|---------|-----------|---------|
| **需求评审** | 产品评审 → 技术评审 → 业务评审 | 产品经理 → 技术负责人 → 业务方 | 需求合理性、技术可行性、业务价值 |
| **设计评审** | 设计评审 | 技术负责人 | 设计方案、架构合理性 |
| **测试案例评审** | 测试评审 | 测试负责人/技术负责人 | 测试案例覆盖度、测试策略 |

### 2.6 需求关联

| 关联类型 | 说明 | 数据来源 |
|---------|------|---------|
| 关联项目 | 需求所属项目 | 项目管理模块 |
| 关联会话 | 需求相关的 AI 对话记录 | 会话模块 |
| 关联文档 | 需求相关的设计文档、PRD 等 | 文档模块 |

### 2.7 需求任务

| 功能 | 描述 |
|------|------|
| 创建任务 | 将需求拆分为具体开发任务 |
| 分配任务 | 指定任务负责人 |
| 更新状态 | 待处理→进行中→已完成 |
| 工时记录 | 预估工时/实际工时 |

### 2.8 评论功能

| 功能 | 描述 |
|------|------|
| 添加评论 | 对需求发表评论 |
| 回复评论 | 支持嵌套回复 |
| 删除评论 | 软删除评论 |

### 2.9 视图展示

#### 表格视图

| 列 | 说明 |
|---|------|
| 需求编号 | REQ-YYYY-NNN |
| 标题 | 需求标题 |
| 类型 | 带图标的需求类型 |
| 优先级 | P0-P3 标签 |
| 状态 | 状态标签 |
| 负责人 | 负责人姓名 |
| 截止日期 | 截止日期 |
| 操作 | 编辑/查看详情 |

#### 看板视图

- 按状态分列展示
- 每个卡片显示：类型图标、标题、优先级标签、负责人头像
- 支持拖拽变更状态

### 2.10 搜索与筛选

| 筛选项 | 类型 | 说明 |
|-------|------|------|
| 关键词 | 文本搜索 | 搜索标题、描述 |
| 需求类型 | 多选 | STORY/TASK/BUG/IMPROVEMENT/FEATURE/EPIC |
| 优先级 | 多选 | P0-P3 |
| 状态 | 多选 | 所有状态 |
| 负责人 | 单选 | 按负责人筛选 |
| 截止日期 | 范围 | 按截止日期范围筛选 |
