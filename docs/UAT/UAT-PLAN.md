# 格物平台用户验收测试 (UAT) 方案

> 用户验收测试执行计划与检查清单

## 1. UAT 概述

### 1.1 测试目标

- 验证系统满足业务需求
- 确认用户体验符合预期
- 识别并修复残留缺陷
- 获得用户验收签字

### 1.2 测试范围

| 模块 | 测试重点 |
|------|----------|
| 认证模块 | 注册、登录、Token 刷新 |
| 项目管理 | 创建、编辑、删除项目 |
| 会话管理 | 创建会话、消息发送、历史查看 |
| Agent | Agent 配置、执行、工具绑定 |
| 工作流 | 工作流设计、执行、监控 |
| AI 对话 | 流式对话、模型选择 |
| 沙箱 | 创建、启停、销毁沙箱 |

### 1.3 测试环境

| 环境 | 地址 | 用途 |
|------|------|------|
| 测试环境 | https://staging.gewu.com | 功能测试 |
| 预生产环境 | https://pre.gewu.com | 验收测试 |
| 生产环境 | https://gewu.com | 正式发布 |

## 2. 测试计划

### 2.1 测试周期

| 阶段 | 时间 | 说明 |
|------|------|------|
| 测试准备 | 第 1 周 | 环境准备、用例评审 |
| 功能测试 | 第 2 周 | 功能模块测试 |
| 集成测试 | 第 3 周 | 模块间集成测试 |
| 性能测试 | 第 4 周 | 性能、压力测试 |
| 回归测试 | 第 5 周 | 缺陷修复验证 |
| 验收测试 | 第 6 周 | 用户验收测试 |

### 2.2 测试团队

| 角色 | 人数 | 职责 |
|------|------|------|
| 测试经理 | 1 | 测试计划、协调 |
| 测试工程师 | 3 | 功能测试、自动化 |
| 开发工程师 | 2 | 缺陷修复、技术支持 |
| 产品负责人 | 1 | 需求确认、验收签字 |

## 4. 缺陷管理

### 4.1 缺陷分级

| 级别 | 定义 | 修复时间 |
|------|------|----------|
| P0 | 阻塞性缺陷 | 24 小时 |
| P1 | 严重缺陷 | 48 小时 |
| P2 | 一般缺陷 | 1 周 |
| P3 | 轻微缺陷 | 2 周 |

### 4.2 缺陷流程

1. 提交缺陷
2. 分配责任人
3. 修复缺陷
4. 验证修复
5. 关闭缺陷

### 4.3 缺陷模板

```markdown
**缺陷标题**: [简短描述]

**重现步骤**:
1. 打开页面
2. 点击按钮
3. 输入数据

**预期结果**: 应该显示成功提示

**实际结果**: 显示错误提示

**环境信息**:
- 浏览器: Chrome 120
- 操作系统: Windows 11
- 分支: dev

**附件**: 截图/日志
```
