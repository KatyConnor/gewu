# 报告体系 · 05-reporting（OPS-STD-001）

> 必输文档契约：报告是 OPS 智能体的第一交付物。模板章节即 ops_check.py 的
> 校验对象（文档门禁）。

## 1. 报告矩阵（10 份契约）

| 编号 | 报告 | 触发时机 | 消费者 |
|---|---|---|---|
| D-OPS-01 | 日常巡检报告 | 每日定时 | 运维团队 |
| D-OPS-02 | 运维周报/月报 | 每周/每月 | 团队 + 管理层 |
| D-OPS-03 | 事件分诊单 | 每事件（E1/E2） | 值班/处理人 |
| D-OPS-04 | 根因分析报告 | 每事件（E3） | 处理人 + 复盘会 |
| D-OPS-05 | 处置方案与执行记录 | 每事件（E4~E6） | 处理人 + 审批人 |
| D-OPS-06 | 事件复盘报告 | P0/P1 事件（E7） | 全团队 |
| D-OPS-07 | 应急预案条目（Runbook） | 预先编写/复盘后更新 | AI 自动执行 + 人 |
| D-OPS-08 | 值班交接报告 | 换班 | 交接双方 |
| D-OPS-09 | 事件登记台账 | 持续维护（索引） | 全员 |
| D-OPS-10 | 知识库条目 | 复盘后沉淀 | AI 检索 + 人 |

## 2. 报告质量规则

- **证据可溯**：所有数据引用带来源（监控指标名@时间 / 日志检索式 / 事件编号）；
- **结论分层**：事实（数据）→ 推断（标注置信度）→ 建议（标注依据）三段式，
  不混写；
- **一事件一链路**：03→04→05→06 四份报告以事件编号串联，
  台账（D-OPS-09）是索引入口；
- **失败也记录**：误判、无效处置、复发过程全部入复盘——报告的价值一半在教训；
- 时限：D-OPS-01 当日出；D-OPS-06 在 P0/P1 事件关闭后 3 个工作日内出。

## 3. 巡检报告内容标准（D-OPS-01）

固定章节：整体健康度（红黄绿 + 一句话）、昨日事件回顾（台账引用）、
指标巡检（核心业务/系统指标 vs 基线）、慢变量预警（磁盘/证书/配额/成本趋势）、
异常苗头（P3 清单）、待办与风险。**巡检的价值在"没出事的日子也能看出要出事的苗头"**。

## 4. 周报/月报内容标准（D-OPS-02）

固定章节：SLA 达成、事件统计（分级/根因分类/MTTR 分布/趋势）、
Top3 反复事件（慢性问题，建议转 LPU/LR）、变更质量（变更相关事件占比）、
告警系统自身健康（误报率/规则调优记录）、容量与成本趋势、下期风险预判。

## 5. 与既有体系文档的衔接

- 事件的代码级根因需要深入分析时 → 引用 LPU 的证据锚点格式（路径:行号）；
- 慢性问题立项治理 → 周报中的建议转 LR（以 OPS 事件数据作为重构依据）；
- 处置中的代码修复 → CR 质量门（P0/P1 清零后才能发布）。
