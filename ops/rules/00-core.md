# OPS 核心 · 00-core（OPS-STD-001 V1.0）

> 生产运维 AI 智能体规范。定位：让 AI 智能体在生产运维中**第一时间发现问题、
> 证据化定位根因、给出可执行方案**，同时用硬性安全边界保证它不会伤害生产系统。

## 0. 定位与双拓扑

本规范与既有体系的分工：

| 规范 | 对象 |
|---|---|
| LPU-STD-001 | 静态代码库的逆向理解（"这个系统是什么"） |
| LR-STD-001 | 重构工程实施（"怎么改造它"） |
| **OPS-STD-001（本规范）** | **运行时系统与生产事件（"它现在健康吗、出事了怎么办"）** |
| AETC-STD-001 | 全程留痕；OPS 的 L2/L3 级处置走其 GATE 审批 |
| CR-RULES / SDLC | 修复代码时的质量门与角色能力 |

运维不是线性阶段，是**双拓扑**：
- **常态循环**：巡检 Agent 定时巡视 → 日常报告 → 趋势发现慢性问题 → 反哺 LPU/LR；
- **事件主线**：告警触发 → E1 分诊 → E2 富化 → E3 根因 → E4 方案 → E5 审批执行 →
  E6 验证恢复 → E7 复盘沉淀。事件是主线，常态是基线。

## 1. 五条铁律（任何情况下不可违反）

1. **只读诊断默认**：AI 智能体对生产系统的默认权限是只读（查指标/查日志/查配置/查拓扑）。
   任何写操作（重启/回滚/改配置/清数据）不在默认权限内。
2. **无证据，不结论**：根因结论必须带证据链（日志行/指标时间戳/trace ID/变更单号），
   置信度标注 [A]直接证据 / [B]多源推断 / [C]单源假设；[C] 级不得触发处置动作。
3. **写操作三确认**：执行任何处置前须同时满足——证据链完整（[A] 或 [B]）、
   处置方案含回滚预案、人工审批通过（AETC R2/R3 级 GATE）。
4. **事件必闭环**：每个登记事件必须有分诊→根因→处置→复盘的完整链路，或在台账中
   显式记录豁免原因；未遂事件（被自动恢复/未影响业务）同样复盘。
5. **降噪不丢信息**：告警聚合去重必须保留原始样本引用（聚合条目附原始告警 ID 清单），
   禁止以"降噪"为名丢弃证据。

## 2. 三层能力架构

| 层 | 职责 | 组成 |
|---|---|---|
| 感知层 | 知道"有事" | 指标（Metrics）/ 日志（Logs）/ 链路（Traces）/ 事件（Events：变更、发布、扩缩容）四信号 |
| 分析层 | 知道"为什么" | 告警降噪、分诊分级、上下文富化、根因分析、影响面评估、方案推荐 |
| 执行层 | 知道"怎么做且安全" | 只读诊断 → 建议输出 → 白名单自动动作 → 高危人工执行（四级处置） |

## 3. 事件主线（E1~E7）与门禁

| 步 | 动作 | 必输文档 | 时限（P0/P1/P2） |
|---|---|---|---|
| E1 | 捕获与分诊（聚合/分级/派单） | D-OPS-03 事件分诊单 | 5min / 15min / 1h |
| E2 | 上下文富化（日志窗口/变更关联/拓扑/历史相似） | 并入 D-OPS-03 | 随 E1 |
| E3 | 根因分析（证据链六法） | D-OPS-04 根因分析报告 | 初判 15min / 1h / 4h |
| E4 | 处置方案（缓解+根治双轨） | D-OPS-05 处置方案与执行记录 | 30min / 4h / 次日 |
| E5 | 审批与执行（AETC GATE） | 并入 D-OPS-05 | — |
| E6 | 验证恢复与观察期 | 并入 D-OPS-05 | P0 ≥2h 观察期 |
| E7 | 复盘与知识沉淀 | D-OPS-06 事件复盘报告 | P0/P1 事件 3 个工作日内 |

门禁校验：`python3 ops/scripts/ops_check.py`（G1~G8，报告落 `.ops/ops-check-report.md`）。

## 4. 处置四级与 AETC 协同

| 级别 | 内容 | 管控 |
|---|---|---|
| L0 只读诊断 | 查询类全部动作 | AETC R0/R1，免审批 |
| L1 建议输出 | 产出方案文档，不执行 | AETC R1 留痕 |
| L2 白名单自动动作 | 预批 runbook 内动作（重启无状态实例/清缓存/发布回滚） | AETC R2：预案库预批 + 事件中单次 GATE |
| L3 高危人工执行 | 数据修复/流量切换/扩缩容/配置变更 | AETC R3：强制审批 + 回滚预案就绪 |

## 5. 触发与续跑

进入 OPS 的条件（其一）：用户提到线上故障/告警/生产事件/根因分析/应急/值班/巡检；
`.ops/` 工作目录存在（续跑：读 `.ops/progress/PROGRESS.md`）；定时巡检触发。
初始化：`ops/init/` 复制为 `.ops/`；报告产出落 `docs/ops/`。

## 6. Agent 行为规范

- 事件处理顺序遵循 E1~E7，不可跳步（E3 未出不得进 E4 执行）。
- 每完成一份必输文档即更新 PROGRESS 并跑 `ops_check.py`。
- 铁律 1/3（安全类）不因用户口头指令让步；流程类可经 D-OPS-06 豁免记录放行。
- 慢性问题（重复发生 ≥3 次同类事件）自动升级：登记技术债并建议进入 LPU/LR 流程。
