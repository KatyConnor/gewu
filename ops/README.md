# ops/ — OPS-STD-001 生产运维 AI 智能体规范 · 项目级执行包

> 规范编号 OPS-STD-001 · V1.0 · 2026-09-02
> 目标：让 AI 智能体在生产运维中第一时间发现问题、证据化定位根因、给出可执行方案，
> 并以硬性安全边界（只读默认 / 三确认 / 白名单自动执行）保证生产安全。

## 双拓扑工作流

- **常态循环**：巡检（每日 D-OPS-01）→ 周月报（D-OPS-02）→ 慢性问题升级（反哺 LPU/LR）
- **事件主线**：E1 分诊 → E2 富化 → E3 根因（证据链六法）→ E4 方案（双轨）→
  E5 审批执行（AETC L2/L3）→ E6 验证观察 → E7 复盘沉淀（知识库/预案库）

## 目录

| 路径 | 内容 |
|---|---|
| `rules/00-core.md` | 五条铁律 + 双拓扑 + 处置四级 + AETC 协同 |
| `rules/01~06-*.md` | 感知降噪 / 分诊富化 / 根因分析 / 处置执行 / 报告体系 / 复盘沉淀 |
| `templates/` | 10 份必输报告模板（D-OPS-01~10，章节即校验对象） |
| `scripts/ops_check.py` | G1~G8 门禁校验 |
| `init/` | 初始化模板（config.json + progress/PROGRESS.md） |
| `docs/` | 运行时报告落位 |

## 快速开始

1. 触发：用户提到线上故障/告警/生产事件/根因分析/值班/巡检 →
   将 `ops/init/` 复制为项目根 `.ops/`，报告写 `docs/ops/`。
2. 事件处理严格走 E1~E7（不可跳步），每环节产出对应 D-OPS 报告。
3. 每完成一份报告：更新 `.ops/progress/PROGRESS.md` →
   跑 `python3 ops/scripts/ops_check.py`。

## 安全边界（摘要）

只读诊断默认；根因结论须带证据链与置信度（[C] 级不触发处置）；
写操作三确认（证据链 + 回滚预案 + 人工审批）；白名单自动执行不超过连续 2 步。
