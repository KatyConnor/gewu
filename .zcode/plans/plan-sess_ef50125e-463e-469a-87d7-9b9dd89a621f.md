# 文件展示三形态改造方案（审查 diff / 打开代码预览 / Markdown 阅读）

## 一、三点需求的现状与差距分析

**点1 · 审查 = 图1 内联 diff（修改区+上下文行）**
现状：点「审查」打开 Monaco DiffEditor 左右分栏（`FileEditorPanel.tsx:240`、`MonacoDiff.tsx`），无内联红绿 diff、无上下文折叠。
数据已具备：`GET /file-changes/diff` 返回 `before/after` 全文（`sessionFileChanges.ts:15-24`），前端用现有零依赖 `lineDiff.ts`（LCS，与时间线同口径）即可算出红绿行，**diff 本身无需后端改动**。
唯一后端缺口：`SessionFileWorkspaceService.diff()` 第 127 行直接读沙箱当前内容，文件已删除/沙箱销毁时整个接口抛错 →「审查」失败。需加降级。

**点2 · 打开代码文件 = 图2 只读高亮视图**
现状：「打开」直接进可编辑 Monaco（`MonacoEditor.tsx`，wordWrap on），语法高亮已有但形态是"编辑器"而非图2 的"只读阅读视图"，且 Markdown 也被当代码显示。

**点3 · Markdown = 阅读模式**
现状：`.md` 映射 Monaco markdown 语言（`FileEditorPanel.tsx:154`）按源码高亮，无渲染视图。已有 `MarkdownRenderer`（react-markdown+GFM+Prism，`ui/MarkdownRenderer.tsx`）可直接复用。

已确认的三个决策：① 内联 diff 默认+可切分栏；② 打开默认只读预览+可切编辑（保留 Ctrl+S 保存）；③ 全部入口同步升级（文件面板 + FileCard + WorkspacePage + DevWorkspacePage）。

## 二、总体设计

数据流不变（仍走现有 6 个 file-changes 接口），改造以前端为主 + 后端 1 处降级。新增 4~5 个文件、修改 6 个文件、新增 1 个依赖。

### 新增文件（gewu-web）
1. **`src/lib/fileLanguage.ts`** — 扩展名→语言映射公共工具（从 `FileEditorPanel.tsx:148-158` 的 languageOf 迁出），导出 `monacoLangOf(path)` 与 `isMarkdownPath(path)`；FileCard/Workspace/DevWorkspace 复用。
2. **`src/lib/diffHunks.ts`** — 纯函数：`buildDiffHunks(rows, contextLines=3)` 把 `lineDiff` 的 rows 切成 hunk 序列；连续未变行 > `2×3+4` 时头尾各留 3 行、中段折叠为 `{collapsed, rows, count}` 块（保留原 rows 供展开）。
3. **`src/components/pages/InlineDiffView.tsx`** — 图1 式内联 diff 视图：
   - Props：`before/after/changeType/path`；内部 `lineDiff` → `buildDiffHunks` → 渲染。
   - 行样式对齐图1与现有 ProcessEditDiff 风格：删行 `bg-red-500/10 text-red-300/90`、增行 `bg-green-500/10 text-green-300/90`、上下文行无背景；**单列行号**（删行显旧行号、增行/同行显新行号，同图1）；等宽 11px、`min-w-max` 横向滚动、整块 `max-h` 内滚动。
   - 折叠块渲染为居中按钮「⋯ 未变更 N 行 · 展开ости」，点击原地摊开该块全部行（state: expandedIndexes）。
   - 头部信息条：路径 + changeType 徽标（新建绿/修改黄/删除红）+ `+N -M`。
   - 空态：CREATE=全绿+「新建文件」徽标；DELETE=全红+「文件已删除」徽标；MODIFY 且 after=null=警示条「当前内容不可读（沙箱已销毁），仅展示修改前快照」+快照全红。
   - （增强项，评审可裁剪）行内语法着色：新依赖 `prismjs`（+`@types/prismjs`，pnpm 安装），`Prism.highlight` 逐行 token 化输出 HTML（Prism 自带转义，安全），仅对渲染行着色并按 `lang:line` 缓存。已知局限：跨行注释/字符串续行不着色——不可接受时可退回纯色文本，其余设计不受影响。
4. **`src/components/ui/MarkdownReader.tsx`** — 阅读模式薄容器：滚动容器 + `max-w-3xl` 居中 + 内嵌现有 `MarkdownRenderer`，供面板/文件卡片复用。
5. **`src/lib/prismHighlight.ts`** —（随增强项）prism 语言组件静态导入与逐行着色封装。

### 修改文件
1. **`FileEditorPanel.tsx`**（核心）：
   - tab 模型改为 `{ path, kind: 'diff' | 'file' }`；`openRequest` 对外签名不变（仍 'diff'|'edit'，内部映射），ChatPage 无需改。
   - diff tab：默认 `InlineDiffView`，头部「分栏/内联」切换按钮切回 MonacoDiffEditor（懒加载保留），切换态按 path 记忆。
   - file tab：默认**预览态**——代码=Monaco 只读（图2）；markdown=MarkdownReader，配 [阅读|源码] 分段切换（源码=Monaco 只读）；头部「编辑」按钮进入**编辑态**=可编辑 Monaco+保存按钮+未保存标记+错误条（现有保存/脏检查逻辑整体保留，仅移入编辑态显示；退出编辑时 dirty 需 confirm）。Ctrl+S 仅编辑态生效。
   - 「打开」已删除文件失败时自动回退为 diff tab 展示 before 快照并提示。
2. **`MonacoEditor.tsx`** — props 扩展 `readOnly?: boolean`、`wordWrap?: 'on'|'off'`（预览态 wordWrap 'off'，贴近图2；默认值保持现行为）。
3. **`ui/FileCard.tsx`** — 预览弹窗分流：markdown→MarkdownReader；code/json/yaml→react-syntax-highlighter（Prism/vscDarkPlus/行号，已在依赖内，弹窗场景比 Monaco 轻量）；其余保持 `<pre>`。
4. **`WorkspacePage.tsx` / `DevWorkspacePage.tsx`** — textarea 替换为同一"预览/编辑"状态机（默认预览：代码 Monaco 只读、markdown 阅读模式；「编辑」进可编辑 Monaco），保存按钮与 Ctrl+S 链路保留（Workspace 保存后 version toast 不变）。Monaco 用 `next/dynamic ssr:false` 懒加载。
5. **后端 `gewu-application/.../session/SessionFileWorkspaceService.java`** — `diff()` 读当前内容包 try/catch：失败时 `after=null, diffText=null`，仍返回 before 快照与 changeType（DTO 已 nullable，前端按空态渲染）。这是审查删除文件/沙箱销毁场景可用性的前提。

## 三、交互规格速查

| 入口 | 默认展示 | 可切换 |
|---|---|---|
| 审查（diff tab） | 内联 diff：3 行上下文、修改区折叠、单列行号、红删绿增 | 分栏 Monaco Diff |
| 打开·代码文件 | Monaco 只读高亮（图2，不换行） | 编辑（可写+保存） |
| 打开·Markdown | Markdown 阅读模式（渲染） | 源码（只读）/ 编辑 |
| 文件卡片预览 | md 渲染 / 代码高亮 / 其余 pre | — |
| 工作空间两页 | 预览（同上规则） | 编辑+保存（链路不变） |

## 四、明确不做（边界）

- 不做审查意见/按行评论持久化（后端无模型，另行立项）。
- 不升级后端 `diffText` 为带 hunk 头的 unified diff（前端自算已够，口径与时间线一致）。
- Markdown 的 diff 按源码行展示，不做渲染化 diff（业界通行做法）。
- `ProcessEditDiff`（时间线编辑条目）本次不动。

## 六、风险与对策

- prismjs 逐行着色跨行注释续行不亮（记录局限，可整体裁剪不影响主体）。
- 超大新建文件全量行渲染 DOM 压力：折叠机制已覆盖 MODIFY 场景；CREATE 大文件加 >3000 行提示条（仍渲染）。
- Monaco 引入两工作空间页无新增 bundle（自托管+懒加载，面板已在用）。
- 后端降级属小改动，DTO 兼容，无迁移。
