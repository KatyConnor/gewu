# 重进会话 live 时间线"流式动态感"优化方案

## 根因（代码级）

重进会话的 live 时间线目前是 **5 秒一跳的"全闭合"快照**，与本地流式视图的差异有三：

1. **未闭合段被渲染成已完成**：后端 live 快照给进行中的思考/正文段也写了结束偏移 `e`（AiChatController.java:391/:398 附近），前端 `parseProcessItems` 把所有 thinking 映射为 `status:'done'`——而 ThinkingRow 组件**本身已支持 active 态**（旋转图标 + 尾部滚动预览 + 增长光标 + "持续了 X…"），只是数据没给出口径；正文段同理（组件已有 lastContentIdx 流式光标逻辑）。
2. **节奏太粗**：轮询 5s 一次（ChatPage startRunPolling），条目成批跳变，无连续流式感。
3. **横幅与滚动**：横幅只有静态 pulse 圆点缺 spinner；外层消息区滚动跟随的 effect 依赖里没有 liveRun，时间线增长时页面不自动跟底。

## 修改内容（切口小、组件零改动）

1. **后端 AiChatController**（live 快照构建处）：未闭合思考/正文段**不写 `e`**（保留 s/t），已闭合条目不变——前端据 `e` 是否存在区分 active/流式态；历史回放（metadata.process）所有条目恒有 `e`，口径完全兼容。
2. **前端 ChatPage `parseProcessItems`**：thinking 条目 `e` 为空 → `status:'active'`（ThinkingRow 的旋转/预览/光标逻辑零改动即可生效）；content 条目不依赖 e（lastContentIdx 流式光标既有逻辑覆盖）。
3. **轮询节奏**：startRunPolling 的 interval 5000ms → **1500ms**（run/status + run/process 两请求，本地代理开销可忽略）。
4. **横幅动态**：脉冲圆点旁增加 `Loader2 animate-spin` 旋转指示（与时间线头部一致）。
5. **滚动跟随**：滚动跟随 effect 的依赖数组加入 `liveRun`（既有"贴近底部才跟随"保护不变，不打扰用户上翻查看）。

## 验证

- tsc + next build；
- E2E：长任务执行中经 5001 轮询 run/process，断言未闭合思考段**无 e 字段**（前端将渲染 active 态）、条目随时间增长；完成后回放仍全部带 e（历史口径不回归）；
- 部署重启 interface+web；动态观感由你登录实测。

## 边界

- 1.5s 轮询非逐字符 SSE，正文增长为小步连续（近流式观感）；分支子流细节仍不做 live 暴露（维持一期口径）。
