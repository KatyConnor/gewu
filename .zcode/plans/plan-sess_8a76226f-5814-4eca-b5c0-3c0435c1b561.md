# AI 推理内容输出到文件 + 摘要卡片 - 实现方案

## 一、架构总览

在推理链路末端新增**内容分类 -> 文件生成 -> 摘要输出**环节：

```
推理完成，得到 answer 文本
  │
  ▼
ContentClassifier（混合判定）
  │  ├── Planner 标注 FILE_OUTPUT 策略 → 强制输出文件
  │  └── 内容特征：代码块>50行 / 总长>2000字符 / 多级标题+长表格 → 自动判定为复杂内容
  │
  ├── 简单问答（短文本无代码块）→ 直接对话框输出（现状不变）
  │
  └── 复杂内容 → FileOutputService
        ├── 判定文件类型（.java/.py/.md/.json/.csv 等）+ 拆分多个文件（多个代码块各自独立）
        ├── 存储路由：
        │     ├── 有 projectId → RequirementFileService（项目需求空间，MinIO）
        │     └── 无 projectId → WorkspaceService（用户工作空间，MinIO）
        ├── 生成摘要（LLM 调用，3-5 句话概括）
        └── 发射 file 事件（文件卡片）+ content 事件（摘要文本）
              │
              ▼
        前端渲染：摘要 Markdown + 文件卡片（预览/下载）
```

## 四、ContentClassifier 混合判定逻辑

```java
@Component
public class ContentClassifier {

    private static final int MIN_FILE_LENGTH = 2000;      // 总字符阈值
    private static final int MIN_CODE_LINES = 50;          // 代码块行数阈值
    private static final int MIN_TABLE_ROWS = 10;          // 表格行数阈值

    public OutputDecision classify(String answer, List<SubgoalNode> subgoals) {
        // 1. Planner 标注检查：子目标策略含 FILE_OUTPUT → 强制输出文件
        boolean plannerFlagged = subgoals.stream()
            .anyMatch(s -> "FILE_OUTPUT".equals(s.getStrategy()));

        // 2. 内容特征检查
        List<CodeBlock> codeBlocks = extractCodeBlocks(answer);
        boolean hasLongCode = codeBlocks.stream().anyMatch(b -> b.lineCount > MIN_CODE_LINES);
        boolean isLong = answer.length() > MIN_FILE_LENGTH;
        boolean hasLongTable = countTableRows(answer) > MIN_TABLE_ROWS;
        boolean hasMultiLevelHeaders = countHeaderLevels(answer) >= 3;

        boolean isComplex = plannerFlagged || hasLongCode || (isLong && (hasLongTable || hasMultiLevelHeaders));

        if (!isComplex) {
            return OutputDecision.direct(answer);  // 简单问答直接输出
        }

        // 3. 拆分文件
        List<FileArtifact> files = new ArrayList<>();
        for (CodeBlock block : codeBlocks) {
            if (block.lineCount > MIN_CODE_LINES) {
                files.add(FileArtifact.of(block.language, block.code));
            }
        }
        // 如果没有独立代码块但是长文档，整体存为 Markdown
        if (files.isEmpty() && isLong) {
            files.add(FileArtifact.of("markdown", answer));
        }

        return OutputDecision.fileOutput(files);
    }
}
```

## 五、FileOutputService 存储路由

```java
@Service
public class FileOutputService {

    private final WorkspaceService workspaceService;
    private final RequirementFileService requirementFileService;
    private final MinioStorageService storageService;
    private final LlmClientFactory llmClientFactory;
    private final ModelConfigService modelConfigService;

    public List<FileInfo> generateFiles(List<FileArtifact> artifacts,
                                          String userId, String projectId) {
        List<FileInfo> results = new ArrayList<>();
        for (FileArtifact artifact : artifacts) {
            String content = artifact.getContent();
            String fileName = generateFileName(artifact);
            String mimeType = resolveMimeType(artifact.getFileType());

            // Word 文档特殊处理
            if ("docx".equals(artifact.getFileType())) {
                content = wordDocumentService.markdownToWord(artifact.getContent());
                mimeType = "application/vnd.openxmlformats-officedocument.wordprocessingml.document";
            }

            String downloadUrl;
            if (projectId != null) {
                // 项目需求空间
                RequirementFile rf = requirementFileService.createFileFromContent(
                    requirementId, "docs", fileName, content, mimeType);
                downloadUrl = storageService.getPresignedUrl(rf.getObjectKey());
            } else {
                // 用户工作空间
                FileNodeDTO node = workspaceService.createFileFromContent(
                    fileName, content, mimeType);
                downloadUrl = workspaceService.getDownloadUrl(node.getFileId());
            }

            results.add(FileInfo.builder()
                .fileName(fileName)
                .fileType(artifact.getFileType())
                .mimeType(mimeType)
                .fileSize(content.getBytes(StandardCharsets.UTF_8).length)
                .downloadUrl(downloadUrl)
                .previewContent(content.substring(0, Math.min(500, content.length())))
                .source("ai")
                .build());
        }
        return results;
    }

    public String generateSummary(String fullContent, String model) {
        // LLM 生成 3-5 句话摘要
        String[] pm = resolveProviderAndModel(model);
        LlmClient client = llmClientFactory.getClient(pm[0]);
        LlmRequest request = LlmRequest.builder()
            .model(pm[1])
            .messages(List.of(
                Message.builder().role("system").content(
                    "你是内容摘要生成器。用3-5句话概括以下内容的核心要点。").build(),
                Message.builder().role("user").content(
                    fullContent.substring(0, Math.min(4000, fullContent.length()))).build()))
            .stream(false).build();
        return client.chat(request).getContent();
    }
}
```

## 八、Token 消耗优化

| 场景 | 原方案 | 新方案 | 节省 |
|---|---|---|---|
| 长代码生成（500 行） | 全部输出到对话框（500 行 output token） | 完整代码存文件，对话框只输出摘要（~100 token） | **省 90% output token** |
| 长文档生成（5000 字） | 全部输出到对话框 | 文件存储 + 摘要输出 | **省 80% output token** |
| 简单问答 | 直接输出（不变） | 直接输出（不变） | 无额外开销 |

摘要生成增加 1 次 LLM 调用（input ~4000 token, output ~100 token），但相比完整内容的 output token 大幅节省。
