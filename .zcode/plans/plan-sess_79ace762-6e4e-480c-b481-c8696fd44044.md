# 需求管理页面交互流程修复

## 问题根因

| # | 问题 | 根因 |
|---|---|---|
| 1 | 点击需求管理菜单不能直接进入需求列表 | 路由本身正确（`setPage('requirements')` → `RequirementsPage`），但详情页 hash 路由失效导致整体交互卡住 |
| 2 | 详情页无法打开 | `page.tsx` 在渲染时读 `window.location.hash`，但 `RequirementsPage` 点击行只设 hash 不触发重渲染，React 不会重新 render |
| 3 | 表格没有操作列 | `RequirementsPage.tsx` 表格视图只有展示列，无查看/编辑/取消/发起评审等操作按钮 |
| 4 | 编辑功能未连通 | `RequirementEditor` 已支持编辑模式（传入 `requirement` prop），但 `RequirementsPage` 只用于新建 |

## 修改清单（2 个文件）

### 1. `page.tsx` — 修复 hash 路由触发重渲染

**文件**: `gewu-web/src/app/page.tsx`

添加 `hashchange` 事件监听 + 一个强制重渲染的 state：

```tsx
const [, forceUpdate] = useState(0);

useEffect(() => {
  const handler = () => forceUpdate(n => n + 1);
  window.addEventListener('hashchange', handler);
  return () => window.removeEventListener('hashchange', handler);
}, []);
```

当 `RequirementsPage` 中点击行设置 `window.location.hash = '#/requirements/{id}'` 时，`hashchange` 事件触发 `forceUpdate`，`page.tsx` 重新渲染并匹配到详情页路由。返回时设 `#/requirements` 同样触发回到列表页。

### 2. `RequirementsPage.tsx` — 添加操作列 + 编辑/取消/发起评审功能

**文件**: `gewu-web/src/components/pages/RequirementsPage.tsx`

#### 2a. 表格添加「操作」列

在表格末尾新增操作列，每行包含：

**固定操作**（图标按钮）：
- **查看**（Eye 图标）— 跳转详情页 `#/requirements/{id}`
- **编辑**（Edit 图标）— 打开 `RequirementEditor` 编辑模式（仅 DRAFT 状态显示，其他状态隐藏编辑按钮，因为后端只允许草稿/可编辑状态修改）
- **取消**（X 图标）— 确认弹框后调用 `updateRequirementStatus(id, 'CANCELLED')`（终态 ARCHIVED/CANCELLED 不显示）

**动态操作**（文字按钮，根据状态显示）：

| 当前状态 | 动态操作 | 调用 API |
|---|---|---|
| DRAFT | 发起评审 | `submitReview(id, 'REQUIREMENT')` |
| APPROVED | 进入设计 | `updateRequirementStatus(id, 'DESIGN')` |
| DESIGN | 开始开发 | `updateRequirementStatus(id, 'PENDING_DEV')` |
| PENDING_DEV | 开始开发 | `updateRequirementStatus(id, 'IN_DEV')` |
| IN_DEV | 开发完成 | `updateRequirementStatus(id, 'DEV_COMPLETED')` |
| DEV_COMPLETED | 冒烟测试 | `updateRequirementStatus(id, 'SMOKE_TEST')` |
| SMOKE_TEST | SIT测试 | `updateRequirementStatus(id, 'SIT_TEST')` |
| SIT_TEST | UAT测试 | `updateRequirementStatus(id, 'UAT_TEST')` |
| UAT_TEST | 上线 | `updateRequirementStatus(id, 'RELEASED')` |
| RELEASED | 归档 | `updateRequirementStatus(id, 'ARCHIVED')` |
| PENDING_REVIEW / IN_REVIEW | （无，评审操作在详情页进行） | — |
| ARCHIVED / CANCELLED | （无，终态） | — |

> 状态流转映射复用 `RequirementHeader.tsx` 中已定义的 `statusConfig`（含 `nextStatus`/`nextLabel`），避免重复定义。

#### 2b. 添加编辑弹框

新增 state：`editingRequirement: RequirementDTO | null`

点击编辑按钮时：`setEditingRequirement(requirement)` → 渲染 `RequirementEditor`（传入 `requirement` prop）

提交时调用 `updateRequirement(id, data)` 而非 `createRequirement`：

```tsx
const handleEditSubmit = async (data: Record<string, unknown>) => {
  await updateRequirement(editingRequirement.id, data);
  toast('需求已更新', 'success');
  setEditingRequirement(null);
  loadData();
};
```

#### 2c. 取消操作确认弹框

简单 `confirm` 对话框（与 `ProjectsPage` 的 `handlePause` 一致风格）：

```tsx
const handleCancel = async (id: string, title: string) => {
  if (!confirm(`确定要取消需求 "${title}" 吗？`)) return;
  await updateRequirementStatus(id, 'CANCELLED');
  toast('需求已取消', 'success');
  loadData();
};
```

#### 2d. 新增 import

```tsx
import { Eye, Edit, X } from 'lucide-react';
import { updateRequirement, submitReview } from '@/lib/requirement';
import { statusConfig } from './RequirementHeader'; // 复用已定义的状态映射
```

#### 2e. 移除行的 onClick 跳转

当前行 `onClick` 跳转详情页的行为改为仅通过「查看」按钮触发，避免误触。

## 不需要修改的部分

- **后端** — 所有 API 已实现，无需改动
- **`RequirementDetailPage.tsx`** — 详情页已完整实现（4 Tab），路由修复后即可正常使用
- **`RequirementEditor.tsx`** — 编辑模式已实现，只需在 `RequirementsPage` 中传入 `requirement` prop 即可
- **`RequirementHeader.tsx`** — 详情页头部已含状态流转按钮，导出的 `statusConfig` 可复用
- **`RequirementBoard.tsx`** — 看板视图不在本次修改范围

## 修改后的交互流程

1. 点击「需求管理」菜单 → 直接进入需求列表页（表格视图）
2. 点击「新建需求」→ 打开 `RequirementEditor` 新建模式 → 保存后回到列表
3. 列表每行操作列：
   - 点击「查看」→ 进入需求详情页（4 Tab：概览/评审/任务/评论）
   - 点击「编辑」→ 打开 `RequirementEditor` 编辑模式 → 保存后回到列表
   - 点击「发起评审」/「进入设计」等动态按钮 → 状态流转 → 列表刷新
   - 点击「取消」→ 确认后状态变为 CANCELLED → 列表刷新
4. 在详情页点击「返回」→ 回到需求列表页
