# S8「稳定性与部署硬化」实施计划（细化版）

## 背景与勘察新发现（三个代理实测）

本轮部署实测暴露的问题经勘察升级为**四层缺陷链**，且发现两个此前未知的重大隐患：

1. **Flyway 定时炸弹（最高危）**：`application.yml` 中 flyway 已启用且 `baseline-version: 0`——**下次 interface 重启时** Flyway 会对既有库从 V1 全量重放 → 种子数据 1062 冲突 → **应用启动直接失败**。库内无 flyway_schema_history（从未成功运行）。V33~V37 内容已手工同步过（实测无冲突），故修正 `baseline-version: 37` 即安全接管。
2. **网关默认 1s TimeLimiter（未知的重大隐患）**：spring-cloud gateway 的 CircuitBreaker 未配置 TimeLimiter → 默认 **1 秒**掐断所有请求——SSE 流式与分钟级 LLM 推理全部被掐断转 17002，且计入失败率加速熔断开门。这解释了此前 17002 的快速出现。
3. **K8s 探针恒失败**：探针打业务口 8080 的 `/actuator/**`，但 SecurityConfig 对该路径 `denyAll`（管理口 9081 才是 actuator）→ K8s 部署下 Pod 会陷入重启循环。
4. **取证设施缺失**：无 access log、无文件日志滚动（prod rollingpolicy 是死配置）、dev 无 GC log/HeapDump——挂起类问题无法取证。
5. 其余已修缺陷（XSS/agent_tool/JSON 列/上下文注入/毒丸）不再重复。

## 阶段 A：拆弹与配置加固（P0，先行）

### A1. Flyway baseline 修正（拆定时炸弹）
- `application.yml`：`baseline-version: 0 → 37`（V33~V37 已实测与库一致，baseline 后 V38+ 增量正常）
- 产线 yml 同步；`V38__sandbox_audit_created_at.sql`：补 `sandbox_audit_log.created_at BIGINT NOT NULL`（唯一 ORM 必需缺口，全表 0 行无回填；其余 8 表仅计划性补 created_by，合并进 V38）
- 验证：重启 interface × 2 次，确认 flyway_schema_history 出现 baseline 37 行且应用正常启动（不触发 V1 重放）

### A2. 网关熔断配置修正（拆 1s TimeLimiter 炸弹）
- gateway `application.yml`：`spring.cloud.circuitbreaker.resilience4j.disable-time-limiter: true`（SSE/LLM 长请求不被 1s 掐断）；`interfaceCB` 补 `minimum-number-of-calls: 20`、`slow-call-duration-threshold: 30s`、`slow-call-rate-threshold: 80`、`automatic-transition-from-open-to-half-open: true`
- `RateLimitFilter`：Redis 异常捕获降级放行（防 Redis 故障时网关全 500）；event loop 阻塞调用标注待办
- `JwtAuthFilter`：claims 缺失防御（null 时 401 而非 NPE 500）

## 阶段 B：interface 挂起修复与取证设施（P0）

### B1. 已知代码缺陷修复
- `AiChatController` 流式写失败 catch（L184-186）：补 `latch.countDown()` + dispose，防异步线程占用至 10 分钟超时
- `SseController`：`SseEmitter(0L)` → 30 分钟超时（防永不超时的半开连接堆积）

### B2. Tomcat 版本覆写（挂起根因的最大概率修复）
- 根 pom 加 `<tomcat.version>10.1.36</tomcat.version>`（Boot 3.2 兼容、本地物料已有；10.1.21→10.1.36 含 16 个月 NIO/Poller/async 修复——直接针对本次挂起形态）
- 同步加 access log（`server.tomcat.accesslog` 含 `%D %F %s %b` + 目录）与 GC log/HeapDumpOnOutOfMemoryError JVM 参数（dev 与 prod 对齐）

### B3. 取证与自愈设施
- `health-check.sh` 重写：改测 9081 管理口 health（免认证、独立于业务线程池）+ 业务口 agents 探活（带 `--max-time`）+ 连续 N 次失败自动重启 interface 并告警输出；修 `((ERRORS++))` set -e 陷阱
- 部署手册 FAQ 同步（access log/GC log 取证说明）

## 风险与回滚
- Tomcat 10.1.36 覆写：Boot 3.2 官方支持范围外的小版本前跳——单属性可逆，回归面为 Servlet 6.0 API（不变），风险低
- Flyway baseline：失败场景为 V1 重放冲突——已通过先改配置规避；rollback = 还原 baseline-version=0（但下次重启仍会炸，故必须成功）
- 网关 disable-time-limiter：长请求不再被网关超时——需确认 interface 自身 async timeout（10min）兜底仍在
