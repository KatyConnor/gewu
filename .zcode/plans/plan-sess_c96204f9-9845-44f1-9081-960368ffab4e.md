# 前端 API 收敛（A 组）与 ChatPage 三按钮接线实施计划

## 背景修正
勘察实测待收敛模块为 **16 个 authFetch + 1 个第三轨 = 17 个**（此前说 9 个为低估），本次仅执行 A 组 11 个低风险模块，B/C/D 组模式验证后另行安排。

## 第 0 步：修复 chat.ts file 分支损坏（独立 bug fix 提交）
- T4.5 编辑事故导致 `case 'file':` 后只剩孤立 `}`（L391-393），onFile 分发体丢失、语法错误
- 恢复为：`case 'file': if (event.file && callbacks.onFile) { callbacks.onFile(event.file); } break;`

## 第 1 步：API 收敛 A 组 11 个模块（约 65 函数）
以 session.ts 试点范式（`unwrap<T>() + request`）机械迁移，函数签名与导出保持不变：
- **模块**：agent(11 函数)、workflow(12)、skill(9)、menu(7)、role(7)、org(4)、sandbox(7)、user(5)、stats(2)、mcp(4)、audit(8)
- **迁移要点**：
  - 删除各模块自带 getBaseUrl/authFetch/handleResponse（约 300 行样板）
  - mcp.ts 保留 `page.records` 解包与 serverId→id DTO 映射；audit.ts 的 verifyAuditChain 保留 `Boolean(json.data)` 语义；workflow 的 PageResult `current` 字段名保持后端兼容
  - 各模块类型定义（含 7 份重复 PageResult）本次不动，仅迁移 HTTP 层（统一类型留给 B 组时做）
  - URL 路径从绝对 base 改为相对路径（request baseURL '/api' 走 rewrites 代理）
- **明确不做**（留待后续）：B 组 4 个含 multipart/裸文本模块、orchestration 的 SSE 流式函数（保留 fetch 直连）、model-config 第三轨

## 第 2 步：ChatPage 三按钮接线
1. **重发**：
   - chat.ts 新增 `regenerateMessageStream(sessionId, messageId, callbacks)`：SSE 直连（getStreamBaseUrl + POST `/v1/ai/sessions/{sid}/messages/{mid}/regenerate`），回调结构与 chatStream 一致
   - types Message 加可选 `fromBackend?: boolean`；loadConversation 加载历史时置 true（L212 处）
   - AI 消息气泡（L491 头像旁）hover 显示重发按钮，仅 `fromBackend` 消息可用
   - 点击流程：本地移除目标 AI 消息及之后的消息 → regenerateMessageStream（复用 ProcessTracker/setStreamText 展示）→ 完成后调 listMessages 重载会话（回填真实 messageId）
2. **置顶**：两处会话列表项（L389-400/L450-459）标题行 hover 加 Pin/PinOff 按钮（pinned===1 时常显图钉），调 session.ts 已有 `pinSession` 后 `loadSessions()`（后端 pinned desc 排序直接透传）
3. **分享**：头部 Share2 死按钮（L484）接 onClick → `shareSession` → 复制 `${origin}${shareUrl}` 到剪贴板并 toast 提示；已分享状态再点走 `unshareSession`（toggle）
4. 顺带清理 deleteSession 死 import

## 第 3 步：验证与提交
- 后端全量测试照跑确认零回归（本计划不动后端）
- 前端本机无 node：靠逐文件类型/导入核对 + CI 兜底（如实记录前端构建验证依赖 CI）
- 提交拆分：① chat.ts 修复（独立 fix）② A 组收敛 ③ 三按钮接线 ④ 完成报告入库 docs/plan/done/

## 风险与边界
- A 组收敛后错误信息变丰富（原 15 个"仅 res.ok"函数）——UI 依赖 Error.message 的地方显示更友好，非回归
- 本机无 node 无法本地类型检查（与 T4.3 试点相同约束），迁移严格对照 session.ts 模式逐文件核对
- B/C/D 组与后端 done 事件带 messageId 改造不在本次范围（用户未确认，保留决策空间）
