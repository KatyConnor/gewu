# 会话回合级「修改文件汇总条 + 明细展开 + 撤销」实施方案

## 架构设计（已确认：范围=最近一次回复；历史每条回复常驻汇总条；全部撤销弹确认/单文件直接执行）

**核心机制——回合快照（内存态）**：`SessionFileWorkspaceService` 新增会话级回合状态。`beginTurn`（聊天流开始时调用）创建新回合状态并使上一回合快照失效；每次 `writeFile` 时若该文件在本回合首次被改，先记录其回合前内容（null=本回合新建）；回合结束（消息落库）后快照保留，供撤销；下一次 `beginTurn` 清掉。**撤销 = 恢复快照内容（新建文件则 rm 删除），精确且不受多次编辑影响**。

**数据流**：
1. 回合开始：`AiChatController` 流式端点 `beginTurn(sessionId)`（置 activeTurns 防撤销并发写入）
2. 写文件：writeFile 钩子记录 `beforeByPath[path] = 回合前内容`
3. 回合结束：persist 块调 `turnChanges(sessionId)` 计算每文件 `+A -D`（LCS：回合前 vs 当前；新建文件=全部新增），写入 assistant 消息 `metadata.turnFiles`（仅 path+行数，几十字节）→ 历史回放有数据；`finally finishTurn`
4. 前端完成时：`onComplete` 调 `GET /file-changes/turn` 取同一快照汇总，附着到本地新消息 → 汇总条立即出现
5. 撤销：`POST /file-changes/undo {paths?}` → 恢复快照/删除新建文件 → 同步修正 `session_file_change` 记录（恢复后与 before_snapshot 相同则删记录）→ 前端刷新变更面板 + 标记已撤销

## 后端改动（4 文件 + 1 单测）

**1. SessionFileWorkspaceService.java（+~130 行，核心）**
- 状态：`turnStates: ConcurrentHashMap<sessionId, TurnState{seq, beforeByPath: Map<path, Optional<String>>}>`、`activeTurns`、`undoLocks`（per-session 锁，本项目首个会话锁先例）
- `beginTurn/finishTurn(sessionId)`；writeFile 钩子（putIfAbsent，天然防重复快照）
- `turnChanges(sessionId)`：构建最小 ToolContext（sessionId+userId+projectId，复用 resolveBinding），逐文件 `diffLineCounts(before, current)`，新建文件特例（空→[行数,0]）；抽取纯函数 `static int[] turnDiffCounts(before, after)` 便于单测；0/0 未变文件跳过
- `undoTurn(sessionId, paths)`：锁内执行；activeTurns 中拒绝「AI 正在执行中」；路径仅接受快照白名单内（防任意路径删除）；存在快照→writeFile 恢复（putIfAbsent 语义保证不污染快照），若恢复内容==记录 before_snapshot 则删除 session_file_change 记录；新建文件→`sandboxClient.execCommand("rm " + quoteShell(sanitizeRelative(path)))`（复用 listDir 的 exec+quote 模式）+删 CREATE 记录；返回逐路径结果 {path, success, reason}
- 快照失效场景（重启/新回合）返回明确 reason「快照已失效」

## 边界与降级
- 快照失效（重启/新回合开始）→ 逐路径 reason → toast「快照已失效」，汇总条保留
- AI 执行中撤销被拒；并发撤销 per-session 锁互斥
- 撤销后已打开的面板 tab 内容可能过期（面板无失效机制，v1 保持现状，可手动重开）
- ProjectDetailPage 聊天面板不显示汇总条（该页无 metadata 解析与文件面板，维持现状，后续可选补齐）
- metadata 只增 path+行数，无内容膨胀；快照仅内存，重启丢失只影响撤销可用性
