## 根因分析结论

**你的问题"还存在上限次数或 tokens 控制吗？"——有，但你那次任务一个都没触发：**

| 控制维度 | 当前状态 | 你的任务（23:17:54–23:22:46） |
|---|---|---|
| 轮次上限 | L2=50 轮，到顶强制总结 | 只跑了 **19 轮**，未触发 |
| token 熔断 | 未绑套餐用户注入 Long.MAX_VALUE/2 哨兵 | 利用率 ≈10⁻¹³（日志实锤），永不触发 |
| 时间熔断 | 已改为滚动续期，不熔断 | 续期过 1 次，正常继续 |
| 成本熔断 | cost-budget=0，关闭 | 未启用 |
| 死循环保护 | 同工具同参数连续 10 次 | 未触发 |

**任务最终总结是模型自己收的尾，不是被掐断**：日志显示共 20 次 LLM 调用 = 1 次我的验证消息 + 19 轮任务，没有强制总结的第 21 次调用；第 19 轮正常流式完成（HTTP 200、[DONE]）且无工具调用 → 自然 DONE；agent_stat 记账为**成功**（13→14），经验正常沉淀（被预算截断时记失败、不沉淀）。模型完成了 plan_task 的 4 项步骤后自主输出总结，"三、尚未完成的部分"是它如实汇报沙箱离线无法联网编译。

**真正的缺陷在告警系统本身：**
1. **刷屏**：每轮头部只要处于 ALERT(≥70%)/DEGRADE(≥90%) 就重发告警，无去重；且时间续期后利用率重置到 ≈66.7%，几十秒内又越过 70% → 永久处于告警态，必然每轮一条（你的任务第 15–18 轮连发 4 条 + 1 条续期通知）。
2. **文案误导**：`使用率已达 87%（token 0% / 时间滚动续期中）`——87% 是时间利用率却不说清，token 0% 是"无限哨兵+分母大"的真实读数，整体像故障。
3. **完成态不透明**（信任问题的根源）：自然收尾时前端无任何说明，只有被限制收尾才显示横幅——用户无法区分"干完了"和"被掐断"。

## 修复方案（已按你的两项决策定稿）

### A. 告警去重（gewu-agent-engine）
- `BudgetContext` 增加 `lastAlertLevel`、`roundsRenewed`、`timeRenewals` 字段。
- `ReactAgentExecutor` 流式头部：告警仅在**状态跃迁**时发送（NORMAL→ALERT、ALERT→DEGRADE），同级静默；每次时间续期后重置，新周期允许再告警一次。

### B. 文案修正 + token 无限标记
- `AgentExecutionEngine.applyUserQuota` 注入哨兵时给 `AgentTask`/`BudgetContext` 加 `tokenUnlimited` 标记。
- 告警文案改为：token 不限时 → `任务执行时间较长：已用时 X 分钟（时间预算滚动续期中，任务正常推进）`；token 有限 → `任务预算使用率已达 N%（token P% · 时间 T%）`。

### C. 阈值可配
- `AgentEngineProperties.Budget` 增加 `alertThreshold`(0.70)/`degradeThreshold`(0.90)，`BudgetController.check()` 改用配置值。

### D. 轮次滚动续期（你已确认）
- 新配置 `rounds-renew-enabled`(true)、`rounds-renew-max`(2)。
- 轮次到顶且**仍在推进**（未触发死循环告警阈值）时：`maxRounds += max(maxRounds/2, 10)` 并发扩容告警，最多续 2 次（50→75→100，与 L3 绝对上限一致）；无推进或超次数才走既有强制总结。同步路径维持现状。

### E. 完成透明度（后端透传 + 前端展示，你已确认）
- 自然完成 DONE 事件携带 metadata `{rounds, elapsedMs, tokenEstimated, timeRenewals}`；修复 `AgentExecutionEngine.toChunk`、`AiChatController.toStreamEvent` 目前丢弃 metadata 的问题。
- 前端 `chat.ts`/`ChatPage.tsx`：自然收尾且 rounds≥3 时在消息尾部渲染状态行 `✅ 任务由 AI 自主完成收尾 · 共 N 轮 · 用时 X 分钟`；被限制收尾的既有横幅文案微调为明确"非正常完成"。
