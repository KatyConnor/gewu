## 三级工作空间架构实施计划

### 目标
将当前"用户 1:1 平铺工作空间"重构为"用户 -> 项目 -> 需求"三级层次结构，修复 Project ↔ Git 仓库、Requirement ↔ 文件/代码的三条断裂线。

### 架构变更全景

```
重构前:                              重构后:
User ─1:1─ Workspace                User ─1:1─ Workspace
         ├─ WorkspaceFile (MinIO)             ├─ personal/ (MinIO, 个人文件)
         ├─ WorkspaceProject (git repo)       └─ projects/
         └─ GitCredential                           └─ {projectId}/
                                                        ├─ repo/ (git, 项目主仓库)
Project (无仓库关联)                                    │   └─ branch: feature/REQ-001
Requirement (doc URL 字符串)                           ├─ requirements/
                                                        │   └─ {REQ-001}/
                                                        │       ├─ docs/ (MinIO)
                                                        │       ├─ tests/ (MinIO)
                                                        │       └─ reports/ (MinIO)
                                                        └─ docs/ (MinIO, 项目文档)
```

### Phase 1: 数据库迁移 + 领域实体（V21）

#### 1.1 V21__add_project_repo_requirement_files.sql

**project 表增加 Git 仓库字段**（替代未使用的 worktree/sandboxes）：
```sql
ALTER TABLE project ADD COLUMN repo_url VARCHAR(512) DEFAULT NULL COMMENT 'Git仓库地址';
ALTER TABLE project ADD COLUMN repo_branch VARCHAR(128) DEFAULT 'main' COMMENT '默认分支';
ALTER TABLE project ADD COLUMN clone_status VARCHAR(32) DEFAULT NULL COMMENT 'clone状态: pending/cloning/ready/failed';
ALTER TABLE project ADD COLUMN repo_local_path VARCHAR(256) DEFAULT NULL COMMENT '容器内路径(如 projects/{projectId}/repo)';
ALTER TABLE project ADD COLUMN head_commit VARCHAR(64) DEFAULT NULL COMMENT '当前HEAD commit SHA';
```

**requirement 表增加 Git 分支字段**：
```sql
ALTER TABLE requirement ADD COLUMN git_branch VARCHAR(128) DEFAULT NULL COMMENT '需求开发分支(如 feature/REQ-001)';
```

**新建 requirement_file 表**（需求文件空间，MinIO 元数据）：
```sql
CREATE TABLE IF NOT EXISTS requirement_file (
    id VARCHAR(26) NOT NULL,
    requirement_id VARCHAR(26) NOT NULL,
    category VARCHAR(32) NOT NULL COMMENT 'docs/tests/reports',
    file_name VARCHAR(255) NOT NULL,
    object_key VARCHAR(512) NOT NULL COMMENT 'MinIO对象Key',
    mime_type VARCHAR(128) DEFAULT NULL,
    file_size BIGINT DEFAULT 0,
    version INT NOT NULL DEFAULT 1,
    deleted TINYINT DEFAULT 0,
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL,
    created_by VARCHAR(26) DEFAULT NULL,
    updated_by VARCHAR(26) DEFAULT NULL,
    PRIMARY KEY (id),
    KEY idx_reqfile_requirement (requirement_id),
    KEY idx_reqfile_category (requirement_id, category)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='需求文件空间';
```

### Phase 2: 项目仓库服务（ProjectRepoService）

#### 2.1 ProjectRepoService

**文件**: `gewu-application/.../project/ProjectRepoService.java`

通过 SandboxClient HTTP 调用沙箱执行 git 操作。项目仓库路径统一为 `projects/{projectId}/repo/`。

| 方法 | 逻辑 |
|------|------|
| `cloneProjectRepo(projectId, repoUrl, branch)` | 创建项目仓库目录 -> git clone -> 更新 project.cloneStatus/headCommit |
| `gitPull(projectId)` | git pull origin main -> 更新 headCommit |
| `getRepoStatus(projectId)` | 返回 cloneStatus/headCommit/repoUrl |
| `createRequirementBranch(projectId, requirementCode)` | git checkout -b feature/{requirementCode} -> 更新 requirement.gitBranch |
| `switchBranch(projectId, branch)` | git checkout {branch} |

注入: `ProjectMapper`, `RequirementMapper`(查需求编号), `SandboxClient`, `DevWorkspaceService`(获取沙箱ID)

#### 2.2 ProjectService 扩展

- `createProject()`: 初始化 `repoLocalPath = "projects/" + projectId + "/repo"`
- `deleteProject()`: 增加 `sandboxClient.execCommand` 清理 `/workspace/projects/{projectId}/` 目录
- `toDTO()`: 输出 repoUrl/cloneStatus/headCommit

#### 2.3 ProjectController 新增端点

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/projects/{id}/repo/clone` | 克隆项目仓库 |
| POST | `/api/v1/projects/{id}/repo/pull` | Git pull |
| GET | `/api/v1/projects/{id}/repo/status` | 仓库状态 |

#### 2.4 ProjectDTO 扩展

新增: `repoUrl`, `cloneStatus`, `headCommit`, `gitBranch`(当前分支)

**验证**: `mvn compile -q`

### Phase 3: 需求文件空间 + 分支关联

#### 3.1 RequirementFileService

**文件**: `gewu-application/.../requirement/RequirementFileService.java`

管理需求文件空间（docs/tests/reports 三类），使用 MinIO 存储。

MinIO 路径: `projects/{projectId}/requirements/{requirementId}/{category}/{fileName}`

| 方法 | 逻辑 |
|------|------|
| `uploadFile(requirementId, category, file)` | 上传到 MinIO -> 写 requirement_file 元数据 |
| `listFiles(requirementId, category)` | 按 category 查询文件列表 |
| `getFileContent(requirementId, fileId)` | 读取文件内容 |
| `deleteFile(requirementId, fileId)` | 删 MinIO + 删元数据 |
| `getDownloadUrl(requirementId, fileId)` | 预签名 URL |

注入: `RequirementFileMapper`, `RequirementMapper`(校验需求归属+获取projectId), `MinioStorageService`

#### 3.2 RequirementService 扩展

- `createRequirement()`: 不再设置 designDoc/planDoc/testDoc URL 字符串（改为文件空间管理）
- `updateStatus()`: 当状态流转到 `IN_DEV` 时，自动调用 `ProjectRepoService.createRequirementBranch()` 创建开发分支
- `toDTO()`: 输出 gitBranch

#### 3.3 RequirementController 新增端点

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/requirements/{id}/files?category=docs` | 上传文件 |
| GET | `/api/v1/requirements/{id}/files?category=docs` | 文件列表 |
| GET | `/api/v1/requirements/{id}/files/{fileId}/content` | 读取内容 |
| DELETE | `/api/v1/requirements/{id}/files/{fileId}` | 删除文件 |
| GET | `/api/v1/requirements/{id}/files/{fileId}/download` | 下载 |
| POST | `/api/v1/requirements/{id}/branch` | 创建开发分支 |

#### 3.4 RequirementDTO 扩展

新增: `gitBranch`

**验证**: `mvn compile -q`

### Phase 4: DevWorkspaceService 适配

#### 4.1 cloneRepo 方法重构

原 `DevWorkspaceService.cloneRepo()` 在用户工作空间下创建 git 仓库。改为：
- 项目仓库克隆走 `ProjectRepoService.cloneProjectRepo()`（路径: `projects/{projectId}/repo/`）
- 需求分支走 `ProjectRepoService.createRequirementBranch()`
- 废弃原 `workspace_project` 表的使用（保留表结构，不再新写入）

#### 4.2 DevWorkspaceService 方法调整

| 方法 | 变更 |
|------|------|
| `cloneRepo()` | 标记 @Deprecated，重定向到 ProjectRepoService |
| `listProjects()` | 改为从 project 表查（按 ownerId），而非 workspace_project 表 |
| `gitPull(projectId)` | 重定向到 ProjectRepoService.gitPull() |
| `gitCommitPush(projectId, msg)` | 保持，但路径改为 `projects/{projectId}/repo/` |
| `build(projectId, cmd)` | 保持，路径改为 `projects/{projectId}/repo/` |
| `run(projectId, cmd)` | 同上 |

**验证**: `mvn compile -q`
